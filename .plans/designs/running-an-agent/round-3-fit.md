## Findings

### fit3-1 · BLOCKER · The lead cannot be stopped after a successful reply

The “Stop agent” row keeps the control where it is shown today. After the first reply, the real lead is idle. The actual project shell renders the bare composer. Its square only stops the whole agent while the lead is working, with no pending reply and no ready message. Mapping an active turn to “Stop this reply,” as the draft requires, removes even that working-state path. The separate Chat tab has an agent menu, but the draft excludes that tab. The owner can cancel a reply and still have no way to stop the resulting idle lead or release its checkout. The smallest change is to specify one reachable “Stop agent” action in the real lead column for starting, working and idle leads, including an offline machine. Keep “Stop this reply” separate, show “Stopping” while the request is outstanding and include the visible change in the approval list. Make A16 stop an idle lead through that control after reload. ### fit3-2 · BLOCKER · A new client run can release the folder of a start it still intends to deliver

The new-run state row fails a `starting` lead with no run. The paragraph below it keeps an undelivered start eligible, and the reservation section lists a change of run as proof that release is safe. Create a project just before the client restarts, before the start is dispatched. After the replay gate opens, one reading lets the old command start a lead whose folder was released and may already be reserved by a second project. The other reading discards a start that the draft says the new process will run. A8 covers an interrupted launch and A9 covers an expired command. Neither covers this unexpired, never-dispatched start. Keep the reservation and state of a start that the new run can still execute. Define how the server distinguishes that case from a dispatched start with uncertain effects. The current sender writes the frame before it commits the dispatched flag, so a false flag alone cannot establish that the client never saw the command. A start the server abandons needs a durable fence that prevents future execution before releasing the folder. Also assign replayed events to their producing run. The existing inbox identifies the transport by the current stream, so associating a replayed `AgentStarted` with that stream's new run would hide the old lead from reconciliation. The guard also needs to make its exit proof available before the replacement admits work. A8 waits for process exit before it starts the replacement, so it cannot detect a replacement that opens too soon. Check an immediate restart with buffered old-run output and a still-eligible start. ### fit3-3 · MAJOR · An expired stop can stay pending on a healthy stream

The stop table retains the intent after every outcome except proof of exit. It stores a replacement only on stream admission. Consider a stop waiting behind other commands on a connected machine. The built link shares its sending permits across machines and offers commands after expiry so the client can decline them. If the stop reaches the client after two minutes, the client returns `expired` without stopping the lead. The same stream can then remain open indefinitely, and the disabled control prevents a second request. Renew an expired stop while the stop intent remains and the stream can send commands. Allow only one outstanding stop per lead and renew it under the machine lock. Specify that the stop and cancel decisions can preempt a start or prompt awaiting its submission point. Running each handler to completion in arrival order cannot withhold an earlier unwritten prompt. Test expiry on an admitted stream and use a controlled pre-submission pause in A4 and A6. ### fit3-5 · MAJOR · The saved repository can differ from the checkout that runs the goal

“ProjectService in sprint 4” accepts an explicit attachment when either the remotes or the first commits match. Two forks can have different configured remotes and share the same first commit. Choosing one in “Add to a machine” can therefore attach it to the other and run the goal there. ### fit3-9 · MAJOR · A valid harness description can be dropped and leave every project blocked
