## Findings

### fit 1 | BLOCKER | An uncertain process can lose its checkout to a second project

The one-project rule makes a checkout available when the first lead is `failed`. The start sweep can declare a lead failed before seeing its start event. For example, the client writes the goal, loses the link, and continues working. The server marks the lead failed, and a second project can reserve the same checkout while the first start report and any compensating stop are still pending. Stop timeout can cause the same release. The foundation says that a lost connection does not prove the harness stopped. Keep checkout ownership until there is proof of non-delivery or process exit, including proof from old-run reconciliation. Keep the browser failure separate from that ownership. Exercise a timed-out start followed by a second create while the original process is still alive. [Checkout rule](../../../docs/specs/2026-11-27-running-an-agent-design.md#L286) · [Start sweep and late start](../../../docs/specs/2026-11-27-running-an-agent-design.md#L324) · [Stop timeout](../../../docs/specs/2026-11-27-running-an-agent-design.md#L365) · [Foundation, machine presence](../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L294)

### fit 2 | BLOCKER | The first real run leaves an admitted credential outside rule 9

The draft requires an existing Claude Code sign-in, admits that its credential is outside the output filter, and postpones checking the sandbox. A first-run harness that can read its sign-in can send it back through ordinary answer or tool text. The filter has no matching value, so the same text can reach the saved thread and website. The credential exists even though the server has yet to hand out a shared sign-in. The foundation calls for checking the applicable sandbox and file access before the affected part is built. Apply that gate to the first real launch with planted credentials and prove protection for the selected permission modes. Define redaction before buffering and logging for all runner and folder fields, including labels and paths, and keep credential-bearing remotes out of the projection. Keep the shared sign-in feature in sprint 9. ### fit 13 | MINOR | Valid metadata can be larger than the aggregate event budget

The 48-kibibyte pre-numbering gate avoids sending an oversized event. An inspected path at the 4-kibibyte input limit can resolve to a longer real path, and a remote address has no field budget. A valid folder result that exceeds the aggregate cap has no defined report to settle the operation. The same gap exists for labels and modes alongside the bounded model and effort lists. Specify truncation for display text, preserve identifiers and paths exactly or decline them with a bounded reason, and use that reason as a correlated result. Cover one successful boundary value and one large result that settles without pinning replay. State how the 2-mebibyte newest-thread window identifies truncation.
