### Both orders of the six machine events

In this table, an event is the eligible next numbered report. A result means one for a successfully dispatched current attempt. A reconnect may use the same run or install a new one. A restart may interrupt a transaction before commit or break reply delivery after commit. The machine lock serializes writes. The exact-stream fence governs old frames. The comparison includes observable replies as well as final state.

| Pair | First order | Reverse order | Same outcome |
|---|---|---|---|
| Reconnect and event | A committed replacement fences the displaced frame. The new stream can replay its retained event. | The prior stream commits the mark. Welcome on the replacement carries that mark, and a repeat has no second effect. | The durable report converges after valid replay. Acknowledgement source differs. An inconsistent new boundary can be refused after the mark moves. |
| Reconnect and result | The old result loses the exact-stream fence. Normal reoffer and a retained receipt can supply it on the new attempt if the command remains eligible. | The current result settles or stages once. No resend follows a committed stage. A contradictory unseen run can fail the staged-watermark check. | No. Attempt assignment and whether a durable stage exists depend on the order. Preserve that difference. |
| Reconnect and sweep | Admission itself leaves sweep eligibility unchanged. A later re-dispatch does not change the absolute cutoff. | A due command times out before reconnect and is never offered on that stream. | Yes for the same due command once a sweep obtains the lock. A busy sweep may defer it. |
| Reconnect and removal | An admitted stream may see Welcome before removal wins and closes it. | The same identity is absent and cannot be admitted. | The machine ends removed in both orders. Welcome and admission callbacks can differ. |
| Reconnect and restart | A confirmed admission leaves its exact run pair and boundary for re-admission. The live handle disappears on restart. | The previous pair survives startup. The candidate is validated against that pair and the durable mark. | Same durable pair after the same successful reconnect. Welcome delivery can differ. |
| Event and result | The report and mark commit. A covering result settles in its own write. | An early result stages. That event's write applies the report, advances the mark and settles. | Yes for a result whose watermark covers the report. A result already covered by an earlier mark can instead close an operation before an unrelated late report. |
| Event and sweep | A covering event settles staged work before the sweep. An applied folder report can also close a Projects operation while its unanswered command remains sweepable. | The sweep skips staged work. With no stage, a due timeout can close an open operation and the later report is consumed. | Yes for a staged command. No for an unanswered due command with a report in flight. |
| Event and removal | A committed report may save a folder or a terminal operation reply before removal cleans up. | Removal fails open operations and later old frames have no effect. | The machine and its folders end removed. A previously saved reply can differ. |
