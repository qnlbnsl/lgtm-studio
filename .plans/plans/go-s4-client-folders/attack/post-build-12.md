## Findings

### post-12 1 — MAJOR — One overlapping sample can postpone every unsent event

By reading, event preparation releases the registration lock, and final handoff declines the prepared report if any local-text sample is still active. This can occur even when the event's own screen completed well within budget. For a current-run event, the owner sets `haveEvents` false, disregards append notifications for dispatch, and clears the deferral only on the heartbeat ticker. Sending the initial heartbeat does not clear it. [Replay preparation and final handoff](../../../../src/client/internal/link/replay.go#L149) · [Screen eligibility](../../../../src/client/internal/link/filter.go#L216) · [Deferral](../../../../src/client/internal/link/session.go#L706) · [Wakeup](../../../../src/client/internal/link/session.go#L779)

Confirmed live, a signed-stream probe kept two numbered reports on disk, released the held sample at 1.2 seconds, and received report 1 at 10 seconds followed by report 2. In instrumented repeats of the command-line reconnect test, three of eight runs deferred event 3 after final-handoff rejection within 10 milliseconds, then failed at the eight-second listener deadline. The paired active-scan case failed once in four instrumented runs, with event 3 deferred after about 0.3 milliseconds and the inventory database check timing out. Both cases also failed on the uninstrumented head. On a reconnect within the same process, the run boundary remains fixed, so a previously buffered report can still take this current-run branch. [Run boundary](../plan.md#L74) · [Command-line reconnect assertion](../../../../src/client/cmd/lgtm-client/link_test.go#L847) · [Paired reconnect assertion](../../../../src/linktest/commands_test.go#L38) · [Paired inventory deadline](../../../../src/linktest/command_fixture_test.go#L116)

A single heartbeat interval is compatible with the foundation's delivery order and heartbeat cadence. The plan specifies no event-screen retry interval, and the ten-second pause fails its executable and paired acceptance when the sample has already recovered. It can explain the reported nine-second `TestOutgoingFilterExecutable` failure under load. The signed peer waits for three events and a scan result, and its subprocess limit is eight seconds. The initial heartbeat allowance alone is one second, and event dispatch remains eligible during that allowance. All 16 instrumented repeats of this particular test passed here, so the host failure's cause remains unverified. [Foundation C7 and C11](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L384) · [Foundation heartbeat cadence](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L294) · [Plan acceptance](../plan.md#L228) · [Executable peer](../../../../src/client/internal/app/outgoing_test.go#L103) · [Subprocess deadline](../../../../src/client/internal/app/client_test.go#L170)

Retry the same event when the sample registers, with a bounded retry timer for contention and the existing final classification under lock. Keep heartbeat and result dispatch independent of that retry.

### post-12 2 — MAJOR — Earlier result screening can use the entire Restart send budget

By reading, Restart saves its result and puts it behind earlier results. The owner begins the two-second Restart send timer while the head of the queue can spend one second screening a state-conflict diagnostic and another second attempting the result refresh. When the timer expires, the client exits for Restart even if it has yet to hand the Restart result to the sender. The diagnostic uses the same sign-in reader as the result refresh in the application. [Durable Restart result](../../../../src/client/internal/link/commands.go#L334) · [Queue](../../../../src/client/internal/link/session.go#L319) · [Send timer](../../../../src/client/internal/link/session.go#L742) · [Screening order](../../../../src/client/internal/link/session.go#L839) · [Application logger](../../../../src/client/internal/app/outgoing.go#L109)

Confirmed live in three signed-stream scratch runs, I held sign-in sampling, queued three well-formed state commands with conflicting content at the current revision, then sent Restart. The sender was available before the send budget elapsed. Link returned `RunRestart` and the closed store held a finished `DONE` receipt. The Restart result never reached the sender. The saved receipt lets the next client answer on a later attempt. Item 6 asks for the normal durable Restart result and exit while a read is held, and item 2 preserves the restart drain budget. [Plan item 6](../plan.md#L168) · [Plan item 2](../plan.md#L88) · [Foundation D16](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L41)

Run conflict diagnostics independently of result readiness. Bound optional earlier refresh work so it leaves time to hand off the accepted Restart result through the registered-value gate.

### post-12 3 — MINOR — The frozen stall tests miss a current-run event that never resumes

The persistent case expects zero events after the stall starts, and the reconnect case releases its stall on another stream before current-run delivery. The same mutation failed the two-event scratch probe, which observed a heartbeat at 10 seconds and no event. This is a coverage gap in the frozen tests.
