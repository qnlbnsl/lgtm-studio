REVISE

The planned status reader can report a clean checkout when a tracked file has changed.

The planner, the test writers, the builders and this reviewer are workers of OpenAI. I reviewed the plan against the approved designs and the repository at `17320f6b`. A byte comparison confirmed that the current plan matches the frozen round 1 input.

## Findings

### logic-r1 01 · MAJOR · plan

**A copied index can hide an uncommitted change.** Item 5 copies the index and accepts a successful porcelain command with empty output as proof of a clean tree. I confirmed live that Git reports empty status output for a tracked file marked assume-unchanged after its contents differ from the committed contents, even with untracked files and submodule changes explicitly enabled. An isolated configuration alone leaves the per-entry flag in the copied index. The website can then show a clean working tree where the approved design requires a dirty one. Evidence is in `.plans/plans/go-s4-client-folders/plan.md:152`, `.plans/plans/go-s4-client-folders/plan.md:154`, `docs/specs/2026-11-27-running-an-agent-design.md:249` and `docs/specs/2026-11-27-running-an-agent-design.md:290`.

Require the snapshot reader to verify tracked entries whose index flags can suppress comparisons, or return `FOLDER_REFUSAL_NOT_READABLE` when it cannot verify them safely. Specify how it distinguishes an intentionally absent sparse entry from a present modified entry. Freeze a fixture with a changed assume-unchanged file and a fixture for sparse checkout before building. Both must preserve the original index bytes.

Category is logic. The responsible builder is Client Folders. Evidence is confirmed live for Git and by reading for the plan. Risk is 6 × 3 × 4 = 72. The status is incorrect for one owner, a fresh inspection can repair it after the flags are addressed, and the flags occur in a specific class of checkouts.

### logic-r1 02 · MAJOR · R7

**An invalid durable counter can put the installed client in a retry loop.** Item 1 sends the value of `Store.Next()` and keeps retrying `invalid_argument`. The store accepts any nonzero unsigned next value when the event bucket is empty. An enrolled client with an empty bucket and `next = 2^63 + 1` therefore attempts an announcement that the reviewed server rejects before Welcome. Item 3 validates the cursor after Welcome, so that check never runs. The client keeps the bad pair and the owner gets no terminal local recovery instruction. Evidence is in `.plans/plans/go-s4-client-folders/plan.md:78`, `.plans/plans/go-s4-client-folders/plan.md:80`, `.plans/plans/go-s4-client-folders/plan.md:99`, `src/client/internal/link/store.go:325`, `.plans/plans/go-s4-contract/plan.md:143` and `.plans/plans/go-s4-server-link/plan.md:175`.

Validate `next` in the inclusive range from 1 to `2^63` at store startup, before receipt sealing or dialing. Leave the invalid store untouched and return the terminal history outcome. Freeze a valid empty store at the upper edge and an invalid empty store one above it. Check the invalid case also with intact enrollment at the executable boundary. Keep remote `invalid_argument` retryable for locally valid stores. Preserve the existing exhaustion behavior after the final legal event number and verify that a required last event can drain before a new append reports exhaustion.

Category is logic. The responsible builder is Client Link. Evidence is confirmed by reading. Risk is 6 × 5 × 4 = 120. One corrupted counter blocks the machine until recovery, and this requires one local history fault.

### logic-r1 03 · MAJOR · R7

**A recovery stop has no write fence against work from the previous stream.** Item 3 preserves the outbox on a failed replay check and keeps the terminal status during cleanup. The sprint 3 process can still have a scan in flight from the previous stream. The scan can append a report with the process context, and `Run` settles its completion during cleanup. On a reconnect with an incompatible verified Welcome, that work can commit after the replay fault has been detected or create a finished receipt on the way out. The new tests inject startup faults with no live command producer. Evidence is in `.plans/plans/go-s4-client-folders/plan.md:99`, `.plans/plans/go-s4-client-folders/plan.md:101`, `src/client/internal/link/session.go:99`, `src/client/internal/link/session.go:159`, `src/client/internal/link/session.go:388`, `src/client/internal/link/commands.go:230` and `src/client/internal/link/commands.go:260`.

Give the terminal transition an explicit store write fence before stream teardown. An already durable write stays durable. Later report writes and receipt completions are refused, and workers are canceled and joined without settling their starts. Keep requested restart on the existing orderly drain path. Freeze a same-process reconnect test that releases a held scan completion after the fault and checks the exact event rows, next number and started receipt after exit.

Category is logic. The responsible builder is Client Link. Evidence is confirmed by reading. Risk is 6 × 5 × 2 = 60. One machine may need manual recovery, and the race requires both a history fault and work in flight.

### logic-r1 04 · MAJOR · R9

**A pending snapshot can reach disk after the filter learns the value it contains.** The reporter holds encoded snapshots when the outbox is full and appends them later from `flush`. For example, a pending inventory version may contain the token that the peer supplies in its next verified Welcome. Item 7 specifies registration and checks current reports and retained events, but gives the pending snapshot no recheck at durable append. The first acknowledgement can free capacity and commit the stale bytes. The later handoff check can then stop the client, with the now-known value already in numbered history. Evidence is in `.plans/plans/go-s4-client-folders/plan.md:200`, `.plans/plans/go-s4-client-folders/plan.md:205`, `src/client/internal/link/report.go:174`, `src/client/internal/link/report.go:192`, `src/client/internal/link/report.go:212` and `src/client/internal/link/session.go:672`.

Make durable admission of new reports check the final field values against current filter knowledge, including the coalesced flush path. Serialize registration with that check and admission so an older scan cannot commit a payload already rejected by the current filter. A pending snapshot can be masked or have a field omitted while it has no number. Keep numbered rows immutable. Freeze a full-outbox test that learns a synthetic token on reconnect, frees one slot and inspects the resulting durable bytes and wire event.

Category is security and logic. The responsible builder is Client Link. Evidence is confirmed by reading. Risk is 6 × 5 × 2 = 60. A known value can become part of local durable history and require manual recovery. This needs a pending snapshot, a new credential match and a later flush.

## Answers to the attack questions

1. The durable `next` counter orders events, while the run identifier distinguishes processes at an equal first number. A reconnect repeats the pair and gets a fresh nonce. The server orders admissions and attempts, and the client advances credit using cumulative acknowledgements bounded by their receipt-time ceiling. Expiry is strict at the sampled server-clock bound. Event timestamps describe capture and do not order the stream. Required gaps stop locally, while a remote `event_gap` retries. The startup range is incomplete at the upper edge, and the last append at the ceiling needs a replay witness. See `logic-r1 02` and `logic-r1 06`.
2. A definite refusal to append leaves `next` unchanged. An uncertain write poisons the store and a restart reads the committed side before continuing. A duplicate uses the receipt before the expiry check, and a new expired command gets a durable decline before filesystem work. The plan retains ordinary retry for transport failure and a verified remote history refusal, and stops for a verified incompatible Welcome or a required local history fault. The client uses the existing sampled server clock for execution, while server database staging and sweep belong to Server Link. The lost-history cleanup cell lacks a write fence. See `logic-r1 02` and `logic-r1 03`.
3. A valid legacy finish replays its outcome at zero, and a legacy start returns interrupted at zero. A revision 2 finish replays its saved mark, a live start keeps one worker, and a dead start seals once. Malformed required metadata stops. An approved and current command with no receipt runs only inside the clock window, a busy different live command retries without a receipt, and a valid standing notice applies by revision even while waiting or expired. Waiting replay sends the retained prefix and bare heartbeats. For origins, present and withheld together is invalid, absent and withheld is unknown, and absent without withholding is known absent. Empty cells remain for fault plus live producer, new credential plus pending snapshot, and empty Git output plus a comparison-suppressing flag. See `logic-r1 01`, `logic-r1 03` and `logic-r1 04`.
4. Zero is valid as a server mark or a saved watermark with no prior event, and is the legacy receipt mark. Zero is invalid for an event number, first event, command attempt, state revision or refusal arm. Facts use false for dirty and for known absence when the origin is missing. A detached branch and an unavailable commit are absent, while a present optional string must be nonempty. A revision 2 finished or interrupted receipt with an omitted or null watermark stops. The generated unspecified folder refusal is zero and the receiving server consumes it without a report effect. See `.plans/plans/go-s4-contract/plan.md:132` and `.plans/plans/go-s4-contract/plan.md:155`.
5. Inventory and requested scans can append through the reporter as the stream owner appends folder reports and writes receipts. The stream owner and sender share the dispatch ceiling, and the outage worker currently owns scan completions while disconnected. A recovery stop and an old worker can still contend for admission.
