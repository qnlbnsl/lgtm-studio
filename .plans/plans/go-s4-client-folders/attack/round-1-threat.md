REVISE

The proposed receipt retention can let a fast machine clock erase the first result while the server can still offer the command, causing a second inspection and a different watermark.

OpenAI supplies the planner, the test writers, the builders and this reviewer. Finding labels refer to the foundation design's rules. The approved running-an-agent design records security findings for the owner and keeps the build decision separate.

## Findings

### threat-r1 01 — MAJOR — R6 — A live command can lose its receipt

The plan preserves the 23-hour offer and 24-hour receipt margin but gives no trusted clock for pruning. The current store computes the cutoff from the machine wall clock. The frozen clock-offset test deliberately expects an earlier command to become runnable again after that clock jumps forward. By reading, the authenticated server estimate used to admit commands and the wall clock used for pruning are separate. (`.plans/plans/go-s4-client-folders/plan.md:90`, `src/client/internal/link/receipts.go:171`, `src/client/internal/link/commands.go:157`, `src/client/internal/link/commands_test.go:1234`, `docs/specs/2026-11-27-running-an-agent-design.md:89`, `docs/specs/2026-11-27-running-an-agent-design.md:111`.)

If the result is lost and a later command triggers pruning after the machine clock jumps forward by 30 hours, the server may still be within the original command's execution window. A retry can inspect a second time and allocate a second report. When the machine clock leads by enough to prune during the offer grace, the retry can instead replace a finished outcome and watermark with a new decline. Specify a conservative lower bound from a verified server time sample for pruning, with pruning deferred when that bound is unavailable. Add the clock-offset test to the list of assertions intentionally superseded by the revision 2 retention rule. In both offset cases, require the original result and watermark on a fresh attempt, including across a reopen.

### threat-r1 02 — MAJOR — R9 — A running client misses a changed sign-in file

The shared design says the filter reads the file when it changes. Item 8 reads it at startup and defers refresh because sprint 4 starts no agent. By reading, the installed service keeps running and its probe and folder commands remain available while the owner signs in to Claude Code separately. (`docs/specs/2026-11-27-running-an-agent-design.md:146`, `.plans/plans/go-s4-client-folders/plan.md:212`, `.plans/plans/go-s4-client-folders/decisions.md:6`, `src/client/internal/link/session.go:74`.)

An owner can refresh a readable sign-in file while the client runs. A subsequent folder report with the new value in a path or branch can then send the value to the server, where `AddRepository` can store it. Specify how the filter refreshes when the readable file changes while sprint 4 is running. Keep previously observed values available for queued material during that process. Make the tests replace a synthetic credential file after an approved Welcome, then check the next inspection, logs and replay while the client remains up. Keep the recorded macOS keychain exception and leave the agent-start refresh hook to sprint 5.

### threat-r1 03 — MAJOR — R9 — Parent Git status needs an explicit submodule boundary

Item 5 promises to inspect populated submodules in separate private views. It leaves the parent status invocation free to do its own recursive check first. Confirmed live, ordinary Git 2.47.3 status in a disposable checkout with a populated submodule launched a second Git status in the submodule, even with optional locks disabled. That probe used benign configuration. (`.plans/plans/go-s4-client-folders/plan.md:152`, `.plans/plans/go-s4-client-folders/plan.md:153`, `.plans/plans/go-s4-contract/plan.md:157`.)

The parent private view can therefore use original child metadata before Folders gets to construct the child's private view. A child supplied by another writer can affect status or activate a configured probe in the client's service context. Require parent status to suppress implicit submodule work-tree inspection. Compare recorded targets and inspect populated submodules explicitly, with each probe receiving its own isolated metadata and configuration. Apply the non-execution and no-network controls to discovery and metadata reads too, and specify the supported host Git capabilities and the refusal when they are unavailable. Test a populated child with an inert sentinel and assert that nested dirty state and a changed target still affect the reported result.

### threat-r1 04 — MAJOR — R9 — Report transformations can introduce a match after screening

Item 7 calls for screening before truncation and again at replay and handoff. It gives no final check after normalization before a candidate is encoded, and no check when a coalesced candidate is retried for append. By reading, existing report normalization removes zero bytes and drops invalid text bytes. The reporter can retain a serialized candidate on a full buffer and flush those same bytes later. (`.plans/plans/go-s4-client-folders/plan.md:201`, `.plans/plans/go-s4-client-folders/plan.md:202`, `src/client/internal/link/report.go:174`, `src/client/internal/link/report.go:192`, `src/client/internal/link/report.go:236`, `docs/specs/2026-11-27-running-an-agent-design.md:152`.)

A raw display value can contain pieces of a known synthetic credential separated by a zero byte. The current normalization joins the pieces. If the first check runs before normalization, the normalized secret becomes durable and the next handoff can stop the client on history that its own producer wrote. A pending snapshot can similarly outlive the set of values used to screen it. Specify the order for normalization, masking and truncation. Check the final field values at the actual buffer append, including a pending flush with updated filter knowledge, and preserve exact-field omission or refusal. Add both cases to the tests and assert that the unsafe bytes never become durable.

### threat-r1 05 — MAJOR — R9 — Shared command results can echo an unsafe identifier

The plan's exact-identifier guard is written for `FolderSeen`. By reading, the existing dispatcher has a fast `SetState` path before the approval check, and other commands share a reply builder that copies the inbound identifier verbatim. Item 2 explicitly retains the current identifier on every reply. (`.plans/plans/go-s4-client-folders/plan.md:90`, `.plans/plans/go-s4-client-folders/plan.md:201`, `src/client/internal/link/commands.go:132`, `src/client/internal/link/commands.go:306`, `docs/specs/2026-11-27-running-an-agent-design.md:157`.)

A syntactically valid command identifier can equal a known, universally unique identifier-shaped credential in the readable sign-in file. A standing notice, unsupported command or returned stored outcome can echo it without passing the folder-specific guard. The common dispatcher needs the exact-value check before it records or applies any command. Keep a final check at the shared reply boundary, including on a result queued before the filter learns a value. Treat the frame as invalid with the fixed diagnostic and no echo. Exercise `SetState` and replay as well as `LookAtFolder` with the signed fixture peer.

### threat-r1 06 — MAJOR — R10 — The transaction interruption uses two incompatible signatures

The client handoff asks for `BeforeEventCommit func(context.Context, *linkv1.Event) error` on the fixture options. Server Link plans `BeforeEventCommit func(context.Context, string, uint64) error` through `servertest.Options.LinkSeams`. By reading, the existing fixture already routes a separate after-commit `BeforeEventAck` observation through those nested options. (`.foundry/go-rewrite/results/plan-go-s4-client-folders.md:26`, `.plans/plans/go-s4-server-link/plan.md:241`, `.plans/plans/go-s4-server-link/plan.md:274`, `src/server/servertest/server.go:31`, `src/linktest/outbox_test.go:53`, `.plans/plans/go-s4-contract/plan.md:281`.)

A combined test written against the client handoff fails to compile against the Server Link fixture. Using the older acknowledgement seam would let the write commit and would leave the required rollback proof untested. Adopt the nested Server Link signature in the result. Key the failure on the authenticated machine and the known event number from the client fixture. Freeze the test against the agreed signature and check that the error leaves the Projects row, terminal result, mark and acknowledgement absent before the retry.

### threat-r1 07 — MAJOR — R6 — A folder probe has no execution budget

Item 6 checks command expiry before reading and gives the client one folder slot. Items 5 and 6 call for context cancellation and joining the worker, without an execution budget or a maximum join time. By reading, the analogous command scan has a separate per-probe budget, while the shared dispatcher gives active work process context so it can survive a stream change. (`.plans/plans/go-s4-client-folders/plan.md:152`, `.plans/plans/go-s4-client-folders/plan.md:161`, `src/client/internal/link/commands.go:131`, `src/client/internal/harness/scan.go:43`, `src/client/internal/harness/scan.go:72`.)

A filesystem read or a local Git process that stalls after a timely start can occupy the slot after the operation times out. A different command repeatedly hits busy. A requested restart can wait on that worker and miss its regular exit and result path. Define a bounded inspection budget, the fixed outcome on timeout after an accepted start, and the cancellation and join behavior for subprocesses and filesystem work. Identify any filesystem calls that cannot honor cancellation and give them isolation that prevents them from keeping the slot or restart open. Test a probe that stalls through the operation wait and receives a normal restart while blocked.

### threat-r1 08 — MAJOR — plan — The Git isolation item is too large to build and freeze as one unit

Item 5 combines isolated configuration, metadata and index capture, shared indexes, local object availability, ignore rules, recursive submodule semantics, concurrent mutation detection and native Linux and macOS acceptance. `checkoutPaths` has a name without a defined field or snapshot contract between items 4 and 5. The epic requires small work items and tests that freeze before implementation. (`.plans/plans/go-s4-client-folders/plan.md:138`, `.plans/plans/go-s4-client-folders/plan.md:150`, `.plans/plans/go-s4-client-folders/plan.md:300`, `.plans/epics/go-rewrite/epic.md:71`, `.plans/epics/go-rewrite/epic.md:159`.)

An ordinary single-checkout fixture can go green while split indexes and submodules remain unimplemented. If the test writer freezes a fixture without a named metadata boundary, the two builders can also disagree about which object or index data is captured before status. Specify the private input contract and split item 5 into ordinary checkout isolation and extended metadata with explicit submodule traversal. State outcomes and frozen fixture inputs for a split index, missing local objects, cancellation and a change between discovery and capture. Use the ninth work item for that split.

- **P1. Folders and Stack.** Run the shipped client as its ordinary service user on Linux and macOS. Use a linked worktree, split index and populated submodule with benign side-effect sentinels. Require correct dirty state, no sentinel or network request, unchanged original metadata and removal of the private view on success, refusal and cancellation. Keep the marker results and before-and-after digests.
- **P2. Client and Projects.** Plant synthetic current and rotated sign-in values, a private-key representation and a connection token in approved test inputs. Exercise startup, pending-buffer flush, nested structured diagnostics and folder inspection. Capture the complete process output, underlying queue, decoded frames, server records and website replies. Require each unsafe exact value to be refused or omitted and safe surrounding display text to survive masking. Use a signed synthetic peer and include the standing-reply check.
- **P3. Client, Server Link and Projects.** Interrupt the client after its durable folder append, interrupt the server after the report callback, and lose an acknowledgement after a confirmed commit in separate runs. Restart the client twice, with an unrelated append between starts. Require the original watermark and one inspection, one committed Projects effect, and one terminal settlement. Preserve the client queue digest and server event mark at each interruption. Repeat the clock-offset scenario while the server may still offer the original command.
- **P4. Stack.** Upgrade a state produced by the revision 1 executable. Require the same enrollment and original safe event, zero for the identified old receipt, and no rerun. Try damaged required history and a verified incompatible Welcome on the shipped supervisors. Require one local diagnostic and a stopped process after the restart interval, then verify a requested restart still relaunches. Retain the supervisor transition, permissions and certificate-pin evidence.
- **P5. Server Link, Projects and Website.** Send an eligible-looking folder report from a waiting, replaced or wrong-machine fixture stream, and try the website operation from an unlisted origin or without a valid session. Require no operation or repository effects from these inputs. For an approved stream, require the fixed safe refusal for an unreadable checkout and successful application for the matched machine, operation and command.
