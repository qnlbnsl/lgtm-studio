| 9 | How does a part register a migration and how does startup serialize it? | Assume an explicit manifest uses an embedded file system, reserved store-first order, sorted part names and contiguous four-digit versions. | 10 | How are version 7 universally unique identifiers (UUIDs) made? | Assume the public generator returns a canonical string and an error. | 11 | How are feed positions and wake-ups represented? | Assume a signed 64-bit identity with cache size 1, a fixed transaction advisory lock and one static PostgreSQL notification on each transaction with buffered changes. Allow gaps from rollback. Use a separate lock for migrations. | Allocation and visibility share the same lock lifetime. A notification needs neither a cursor nor record data. | unanswered | 2026-11-26 |
| 12 | What value can the feed store for its write time? | Assume `written_at` uses the PostgreSQL clock at final insertion. This is the clock immediately before the commit attempt, and it can precede the actual commit. | The design approved on 2026-11-25 calls this the commit time. PostgreSQL exposes exact transaction timestamps only after commit with an optional setting. The approximation keeps the row and state atomic under the current stack contract. The difference matters to retention, not feed order. | unanswered | 2026-11-26 |
| 13 | What identifies a retry and what can be saved? | Assume one global case-sensitive key up to 256 bytes. Digest the authorized caller, operation and stable body bytes. Use a single per-key advisory lock and save successful, receipt-safe reply bytes only. Return a conflict on a mismatched digest. | A request body alone does not authorize sharing a reply. The service owns authentication and the policy for replies containing credentials. An empty key leaves the normal write path available. | unanswered | 2026-11-26 |
| 14 | How does retention handle expired rows and cursor gaps? | Assume one hourly sweep after a startup sweep, a strict 24-hour cutoff and batches of 512. Advance a durable watermark when deleting an expired contiguous feed prefix. The sweep can delete expired receipts. The sweep excludes part-owned state, separate history, and feed rows blocked by a still-retained predecessor. | A clock adjustment can make timestamps disagree with positions. Pruning a prefix lets a follower detect a gap in order. The design approved on 2026-11-25 identifies only feed rows and receipts as retention data. | unanswered | 2026-11-26 |
| 15 | How are process-level reading and lag bounded? | Assume one reader with a dedicated notification connection and one shared ring of 2,048 rows. Fetch pages of 512 and count actual global feed rows, including an in-flight row, after the subscriber's acknowledged cursor. Check from the database when notifications are unavailable. Use one stable endpoint per follower lifetime. | The design specifies a notification, a two-second poll and the cutoff number. One reader can retain bounded history even when a subscribed sender stops reading. A sequence gap should not count as a change. | unanswered | 2026-11-26 |
| 16 | How is the Watch helper shared across record types and ended at the cutoff? | Assume a generic Go envelope mapped by each service to the shared contract. Require a context-aware sender and map lag to `resource_exhausted` when a later transport can emit a status. A saved row whose record is missing yields a removal. A removed row yields its key. | The 2026-11-25 design specifies a snapshot followed by current records or removed identifiers. A transport adapter must stop a blocked response before the client can reopen it. | unanswered | 2026-11-26 |
| 17 | How are the work items split and sized? | Assume nine items. Split the follower into ordered database reads and bounded subscriber dispatch. Keep the store's first schema with the migration runner. | The brief allows different file cuts. The split makes the two follower behaviors independently testable and gives each pair of files one writer. The approved build-loop reading for issue 1635 uses low, medium and high. | unanswered | 2026-11-26 |
| 18 | Which work can run beside this foundation and how is review load budgeted? | Assume the initial review and the nine build pairs fit the sizing estimate in the plan. The bounded assignment provides no live allowance readings and gives the orchestrator control of launches and review. | unanswered | 2026-11-26 |
