REVISE

An event file can be placed before a directory sync fails, leaving the next append free to overwrite that event at the same number.

## Findings

This review compares the plan with the approved design and the sprint 3 brief at commit `fb992dc9`. The submitted plan matches the frozen version byte for byte. The commit has no Go client, so the findings concern the written rules and proposed tests. The three local probes exercised the file replacement, receipt age calculation and shell fixture in isolation.

### logic-r1 1 — BLOCKER — C11

**Evidence by reading.** `.plans/plans/go-s1-client-local/plan.md:246`, `.plans/plans/go-s1-client-local/plan.md:584`, `.plans/plans/go-s1-client-local/plan.md:588`, `.plans/plans/go-s1-client-local/plan.md:608`.

**Failure.** The event at position 6 is renamed into place, and the directory sync returns an input/output error. The helper returns an error after placement, and the open outbox still has 6 as its next number. A retry with a different payload replaces the first file. A fresh reopen before that retry would instead find event 6 and move on to 7. A failed sync after placing the acknowledgement mark can also leave the open handle and its on-disk mark in disagreement. A temporary-folder probe confirmed that the replacement leaves only the second payload.

**Fix.** Specify distinct outcomes for failure before placement, confirmed durability and uncertain durability after placement. Create numbered event files without replacing existing names. On an uncertain commit, suspend queue operations and delivery until the file or mark is reconciled and its durability is confirmed. Give the producer an explicit way to resolve whether its original append committed before it retries. Apply the same placement contract to key and receipt creation. Inject a directory sync failure after both event placement and mark placement, then test immediate retry and reopen.

### logic-r1 2 — BLOCKER — R6

**Evidence by reading.** `.plans/plans/go-s1-client-local/plan.md:640`, `.plans/plans/go-s1-client-local/plan.md:644`, `.plans/plans/go-s1-client-local/plan.md:648`, `.plans/plans/go-s1-client-local/plan.md:662`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:284`.

**Failure.** A command runs, and its receipt later contains only `{`. Recovery can follow the written rule by rebuilding an interrupted receipt with only the identifier. Its three missing timestamps then take the zero value, which qualifies for deletion in the same opening pass. A retry of the still-valid command runs again. The age calculation was confirmed in a local probe. The rules also leave valid JavaScript Object Notation (JSON) with a missing state, unsupported version or identifier different from its filename outside the stated recovery policy.

**Fix.** Validate receipt version, filename and identifier agreement, state and each state's required fields. Keep a durable refusal for a damaged receipt with an unknown expiry until an explicit repair establishes a safe deletion bound. Treat filesystem read errors as storage failures and block command execution until recovery succeeds. Test damaged, unreadable and valid-but-inconsistent receipts across repeated opens and prunes, followed by a still-valid delivery of the same identifier.

### logic-r1 3 — BLOCKER — C11

**Evidence by reading.** `.plans/plans/go-s1-client-local/plan.md:147`, `.plans/plans/go-s1-client-local/plan.md:243`, `.plans/plans/go-s1-client-local/plan.md:257`, `.plans/plans/go-s1-client-local/plan.md:575`, `.plans/plans/go-s1-client-local/plan.md:605`, `.plans/plans/go-s1-client-local/plan.md:633`.

**Failure.** One process can acquire the folder lock and open two queues by passing the same path twice. Each owns its own counter and mutex. Both can assign 1 to different payloads, and the second file placement replaces the first. Opening a second queue or receipt store can also remove the first store's live temporary file or mark a command interrupted while it is running. The proposed two-process test opens the folder twice, and the concurrency tests use one queue or receipt handle each.

**Fix.** Make the locked folder the owner of one outbox and one receipt store. Derive their paths from that owner and either share the existing handles or refuse a second open. Require both `join` and `run` to hold the same lock over all state access and cleanup, and close the stores before releasing it. Keep the lock file on a stable inode. Test a second store opener in one process, a second process using an alias of the same folder and concurrent cleanup during a write.

### logic-r1 4 — BLOCKER — C11

**Evidence by reading.** `.plans/plans/go-s1-client-local/plan.md:241`, `.plans/plans/go-s1-client-local/plan.md:246`, `.plans/plans/go-s1-client-local/plan.md:253`, `.plans/plans/go-s1-client-local/plan.md:297`, `.plans/plans/go-s1-client-local/decisions.md:20`.

**Failure.** On first start, the state folder and `outbox/` can both be new. Syncing the event file and `outbox/` leaves the directory entry for `outbox/` in its parent outside the required syncs. A power loss can remove the directory entry after `Append` has reported success. The same gap in the state folder's parent affects a newly created machine identity and command receipts. A stopped child leaves the filesystem mounted and cannot establish this durability.

**Fix.** Require initialization to sync the parent of each newly created directory, including missing ancestors, before allowing a key, event or receipt write to report success. Propagate a failed initialization sync. Add a first-start sync-order test that fails when any parent sync is removed. Keep the power-loss check distinct from the process-exit tests.

### logic-r1 5 — BLOCKER — C11

**Evidence by reading.** `.plans/plans/go-s1-client-local/plan.md:539`, `.plans/plans/go-s1-client-local/plan.md:540`, `.plans/plans/go-s1-client-local/plan.md:588`, `.plans/plans/go-s1-client-local/plan.md:599`, `.plans/plans/go-s1-client-local/decisions.md:24`, `.plans/plans/go-s3-client-link/plan.md:45`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:290`.

**Failure.** With events 6 and 7 pending and only 6 sent, passing 41 to the same acknowledgement method used for recovery deletes both files, including the unsent event. The proposed test explicitly requires that method to accept 41 on an empty outbox, and the interface gives the method no send bound or proof that the number belongs to a recovery handshake. There is also a dead end in the stated recovery rule. If the mark is missing after events 1 through 5 were deleted, and only 6 and 7 remain, open refuses the gap before the client can reconcile against the server's applied cursor of 5. A cursor at the maximum unsigned 64-bit value wraps the next position to 0 under the stated arithmetic.

**Fix.** Bound normal acknowledgement by the last position sent on the authenticated connection. Give recovery its own operation, tied to the durable applied cursor for the same server and machine identity. Define recovery for a missing mark with retained files, and stop with a specific error when a gap cannot be accounted for. Reject sequence exhaustion before arithmetic wraps. Test an acknowledgement ahead of the sent range, a missing mark with pending events, a changed identity, and the maximum cursor.

### logic-r1 6 — MAJOR — R6

**Evidence by reading.** `.plans/plans/go-s1-client-local/plan.md:632`, `.plans/plans/go-s1-client-local/plan.md:645`, `.plans/plans/go-s1-client-local/plan.md:649`, `.plans/plans/go-s1-client-local/decisions.md:27`, `.plans/plans/go-s1-client-local/decisions.md:28`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:283`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:286`.

**Failure.** A server deadline of noon arrives when the server already reads 12:01 and the client clock reads 11:59. The default clock authorizes execution. A clock rollback after a prune can also make a previously expired command appear valid again. If a retry can extend the expiry under the same identifier, a pruned receipt permits a second run even with accurate clocks.

**Fix.** Agree with the link plan on a time source with a known uncertainty bound, a rule for equality at expiry and a refusal when time validity cannot be established. Require an immutable expiry for each command identifier across attempts, or retain deduplication through the server's explicit last possible retry. Use a time basis for pruning that cannot be undone by a later clock rollback. Test skew in both directions, equality, rollback after pruning and an increased attempt with a changed deadline.

### logic-r1 8 — MAJOR — R6

**Evidence by reading.** `.plans/plans/go-s1-client-local/plan.md:643`, `.plans/plans/go-s1-client-local/plan.md:647`, `.plans/plans/go-s1-client-local/plan.md:664`, `.plans/plans/go-s3-client-link/plan.md:46`.

**Fix.** Require the handler and receipt store to persist a bounded terminal outcome when a result cannot be stored or the handler fails. Define the restart handoff in sprint 3, including the durable outcome it records before transferring control, the point at which success can be reported and the reply on redelivery. ### logic-r1 10 — MINOR — D7

**Evidence by reading.** `.plans/plans/go-s1-client-local/plan.md:335`, `.plans/plans/go-s1-client-local/plan.md:336`, `.plans/plans/go-s1-client-local/plan.md:349`, `.plans/plans/go-s1-client-local/plan.md:350`.

**Failure.** If the key path contains a named pipe with no writer, an ordinary read-only open can block before the regular-file check. ## Answers to the attack questions

1. **Ordering.** The acknowledged mark starts at 0 and the event stream at 1. A single queue orders appends, reads use ascending positions, repeated or lower acknowledgements are ignored, pending gaps block open, and restart takes one plus the maximum of the mark and pending positions. Cross-handle ties, acknowledgement bounds and wrap remain open. The receipt key is the command identifier, regardless of attempt order. Attempt 0 is refused and a higher attempt replays the first outcome under the incoming attempt number. Missing-attempt policy beyond 0, lower-attempt replies and server attempt wrap need agreement. Receipt age uses the latest stored time and a strict retention threshold. Harness ties go to the first valid candidate in configured order and results use registry order. `.plans/plans/go-s1-client-local/plan.md:448`, `.plans/plans/go-s1-client-local/plan.md:539`, `.plans/plans/go-s1-client-local/plan.md:584`, `.plans/plans/go-s1-client-local/plan.md:642`.
2. **Failure and repair.** An unplaced event can reuse its number, and an unplaced start receipt permits execution. A surviving start receipt becomes interrupted, and a surviving finish replays its result. Handling of a failed sync after placement, read failures, receipt damage and clock disagreement is incomplete. A full queue refuses the new event and leaves producer recovery open. A database outage and expired join or connection tokens belong to sprint 3, where reconnect and resend are required. The harness timeout should decline the candidate and continue the scan, but its fixture exits early. `.plans/plans/go-s1-client-local/plan.md:585`, `.plans/plans/go-s1-client-local/plan.md:645`, `.plans/plans/go-s1-client-local/plan.md:669`, `.plans/plans/go-s1-client-local/plan.md:712`, `.plans/plans/go-s3-client-link/plan.md:43`.
3. **Interacting rules.** For a valid delivery, absent plus future or equal expiry starts, absent plus past expiry records expired, started in this process plus any deadline waits, and finished, interrupted or expired plus any deadline replays. A start from a prior process becomes interrupted. The damaged-receipt plus prune cell can erase the refusal. The valid JSON plus missing or unknown state cell and the write-placed plus failed-sync cell have no safe policy. For events, a number at or below the mark is removed, a contiguous number above it is pending, and a gap is refused. A mark missing with pending events above 1 cannot reach the advertised reconciliation path. For enrollment, an existing key with missing server metadata can mean either a local-only start or a completed server registration. `.plans/plans/go-s1-client-local/plan.md:149`, `.plans/plans/go-s1-client-local/plan.md:382`, `.plans/plans/go-s1-client-local/plan.md:539`, `.plans/plans/go-s1-client-local/plan.md:642`.
4. **Zero values.** An empty state override selects the next candidate, a missing settings file uses defaults, and zero agent limit is invalid when supplied. The settings tests leave omitted fields within an existing file, explicit empty paths and JSON null unclear. Zero outbox options use defaults, position 0 is the initial mark, read position 0 starts at the first unacknowledged event, a nonpositive read limit returns nothing, and an empty payload is valid. Empty receipt options use defaults, empty identifier and zero attempt or expiry are refused, zero finish time and empty result are omitted, and zero decision and empty receipt state have no valid meaning. Empty harness problem denotes success, empty harness name has no registry entry, empty search path finds nothing, and zero timeout uses the default. The load tests expect zero at zero cores or zero total memory and reject a zero Darwin scale. Negative options and zero sequence on disk lack a stated validation policy. `.plans/plans/go-s1-client-local/plan.md:195`, `.plans/plans/go-s1-client-local/plan.md:423`, `.plans/plans/go-s1-client-local/plan.md:443`, `.plans/plans/go-s1-client-local/plan.md:545`, `.plans/plans/go-s1-client-local/plan.md:573`, `.plans/plans/go-s1-client-local/plan.md:628`.
5. **Concurrent actors.** Two clients choosing the same folder contend on its `lock` file. Goroutines sharing one queue or one receipt store must serialize competing writes. Separate store handles can bypass that serialization, cleanup can race a writer, and the plan leaves ownership of the lock across join and run implicit. The installer or owner can write settings during a read, and the plan gives that writer no atomic update protocol. `.plans/plans/go-s1-client-local/plan.md:144`, `.plans/plans/go-s1-client-local/plan.md:243`, `.plans/plans/go-s1-client-local/plan.md:575`, `.plans/plans/go-s1-client-local/plan.md:633`.
6. **Risky mutations.** Item 2 has direct assertions for the file sync, permissions, lock and no-replace changes. The in-place edit needs a stop after a partial write or truncation, which the five named hooks leave to the mutation author. Missing directory sync on exclusive create can pass. Item 3 directly checks modes, existing keys and the link refusal, but an independent link precheck could let the no-follow mutation pass. The formatting test does not require each verb to show only the fingerprint and can miss a raw decimal byte dump. Skipping the owner check can pass. Item 6 has direct fixtures for all four named mutations. Skipping checksum verification only in recovery can pass. Item 7 has direct checks for the mark order, limit and counter mutations, but the random kill cannot guarantee observation of a number returned early. Reusing a number after a failed directory sync can pass. Item 8 directly checks interrupted recovery, expiry and identifier rules, but the kill test records authorization and simulated finish, with no separate command effect. In the planned API the handler runs after `Begin` returns, so a deterministic pause before durable start plus an independent effect counter is needed for the first mutation. Treating valid JSON with no receipt state as valid can pass. `.plans/plans/go-s1-client-local/plan.md:224`, `.plans/plans/go-s1-client-local/plan.md:318`, `.plans/plans/go-s1-client-local/plan.md:529`, `.plans/plans/go-s1-client-local/plan.md:567`, `.plans/plans/go-s1-client-local/plan.md:622`.
7. **Cheapest wrong implementations.** Item 1 requires both optional settings fields whenever a file exists. Item 2 omits the directory sync only on the exclusive-create path. Item 3 omits the owner check. Item 4 always returns an empty architecture. Item 5 omits `LANG=C` while still setting the tested environment variables. Item 6 fails to validate the checksum when reopening a pending file. Item 7 implements the normal path and reuses an already placed event number after a directory sync error. Item 8 validates JSON syntax but skips persisted-state validation. `.plans/plans/go-s1-client-local/plan.md:211`, `.plans/plans/go-s1-client-local/plan.md:262`, `.plans/plans/go-s1-client-local/plan.md:354`, `.plans/plans/go-s1-client-local/plan.md:427`, `.plans/plans/go-s1-client-local/plan.md:466`, `.plans/plans/go-s1-client-local/plan.md:547`, `.plans/plans/go-s1-client-local/plan.md:606`, `.plans/plans/go-s1-client-local/plan.md:662`.
8. **State shape.** A locked owner with one store per folder removes competing writers. A no-replace event file and an explicit uncertain-commit outcome remove the overwrite path. Separate bounded acknowledgement and authenticated recovery operations prevent a normal acknowledgement from deleting unsent events. A validated receipt state with a durable refusal for unknown expiry prevents malformed files from permitting another run. The close promise also needs an expressible API, because the scalar accessors and change channel have no error return. Specify read-only values after close or return errors from those signatures. `.plans/plans/go-s1-client-local/plan.md:575`, `.plans/plans/go-s1-client-local/plan.md:579`, `.plans/plans/go-s1-client-local/plan.md:589`, `.plans/plans/go-s1-client-local/plan.md:640`.

a. **Machine key.** Creation generates an Ed25519 key, encodes it in one Privacy-Enhanced Mail (PEM) block using Public-Key Cryptography Standards number 8, writes and syncs a mode `0600` temporary file, links it to the final name without replacement, syncs the directory and removes the temporary name. An existing entry returns `ErrKeyExists` and remains intact. A missing entry returns `ErrKeyMissing`, malformed content returns `ErrKeyInvalid`, and exposed, foreign-owned or nonregular files are refused. There is no specific unreadable-file recovery or post-link sync-failure rule. The plan needs the refusal paths in findings 1, 7 and 10 before sprint 3 uses it. `.plans/plans/go-s1-client-local/plan.md:246`, `.plans/plans/go-s1-client-local/plan.md:334`.

b. **Crash recovery and numbering.** After five queued events, an interrupted sixth write leaves 6 as the next number if placement did not survive, or 7 if the complete file survives. Recovery preserves ascending order and refuses gaps. Unacknowledged sends can repeat on reconnect and the server must apply each number once. An event before placement can be absent, and an event that survives placement can be repeated at a new number if the producer blindly retries the same payload. Findings 1, 3, 4 and 5 show paths to losing buffered events. `TestOutboxCrashAtEachWriteStep` and `TestOutboxKillKeepsEveryNumberedEvent` cover local process exit. `TestAckIsDurableBeforeDelete` checks the visible mark ordering. The receipt equivalents are `TestReceiptsCrashAtEachWriteStep` and `TestReceiptsKillNeverRunsTwice`. Sprint 3 must prove ordered server application against real peers. `.plans/plans/go-s1-client-local/plan.md:601`, `.plans/plans/go-s1-client-local/plan.md:607`, `.plans/plans/go-s1-client-local/plan.md:668`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:388`.

c. **Sprint 3 state handoff.** The layout has the key, server trust and machine metadata slot, settings, outbox and receipts needed by the brief. Sprint 3 still owns the exact server trust fields and needs a pending enrollment state. Ordinary independent processes sharing a folder are refused by the folder lock if both use it. Distinct absolute state overrides give independent state folders. They retain a shared default repositories path, which does not store wave 1 state. Multiple handles or copied identity state can still collide even when a folder lock exists. `.plans/plans/go-s1-client-local/plan.md:144`, `.plans/plans/go-s1-client-local/plan.md:158`, `.plans/plans/go-s1-client-local/plan.md:196`, `.plans/plans/go-s3-client-link/plan.md:43`, `.plans/epics/go-rewrite/epic.md:173`.
