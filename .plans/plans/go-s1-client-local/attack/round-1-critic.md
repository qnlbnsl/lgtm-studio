REVISE

An append that reaches its final filename and then fails to sync the directory can leave the event on disk while the queue still offers its number to a different event.

## Findings

### critic-r1 1 — BLOCKER — C11

`WriteAtomic` can report an error after it has installed the file. `Append` advances `next` only after a successful write and uses an operation that can replace the final name. Event 6 can therefore become visible, return an error after the directory sync fails, and then disappear when a different payload is written as event 6. A temporary filesystem probe reproduced the replacement after a simulated sync failure. The client does not exist yet. (`.plans/plans/go-s1-client-local/plan.md:246`, `.plans/plans/go-s1-client-local/plan.md:586`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:290`.)

Publish numbered event files with the exclusive create operation. Define a failed sync after placement as an indeterminate commit. Stop allocation and sending until recovery has reconciled the final name and confirmed durability. Give the caller a distinct outcome so retrying cannot append a second copy of an already placed event. Add `TestAppendAfterDirectorySyncErrorPreservesEvent` with two distinct payloads and an injected error after placement. Assert that neither the second append nor reopening silently replaces the first payload.

### critic-r1 2 — BLOCKER — C11

`Open` creates the state hierarchy, but the write protocol only syncs the directory that directly holds the event or receipt. On the first run, a power loss after `Append` returns 1 can lose the newly created `outbox/` entry in its parent. The same failure can erase the first `started` receipt after its command has run. The file-level ordering tests do not exercise the creation of the hierarchy. (`.plans/plans/go-s1-client-local/plan.md:241`, `.plans/plans/go-s1-client-local/plan.md:246`, `.plans/plans/go-s1-client-local/plan.md:262`, `.plans/plans/go-s1-client-local/plan.md:646`.)

Require `Open` to sync the parent of every directory it creates, including newly made ancestors and the state directory itself, before returning usable paths. Specify how an interrupted first open establishes the same guarantee on retry. Add `TestOpenSyncsNewDirectoryEntries` to assert the path of each sync and that a failed required sync prevents use of the stores.

### critic-r1 3 — BLOCKER — C11

The same `Ack` method clears pending files and accepts a server position beyond the local counter. Decision 17 uses that behavior after loss of the outbox. Suppose the server has applied through 41, the local outbox is rebuilt empty, and a producer queues a new event as 1 before the first successful reconnection. Applying the server's 41 as specified deletes the new event, which the server has never received. `TestAckBeyondNextMovesCounter` starts with an empty outbox and misses this case. (`.plans/plans/go-s1-client-local/decisions.md:24`, `.plans/plans/go-s1-client-local/plan.md:584`, `.plans/plans/go-s1-client-local/plan.md:588`, `.plans/plans/go-s1-client-local/plan.md:599`, `.plans/plans/go-s3-client-link/plan.md:45`.)

Give normal acknowledgements a bound at the last committed event. Define a separate initial reconciliation with the authenticated server position, before producers can number events on a missing or reset queue. Preserve local files and report a conflict if reconciliation finds pending events that could have been numbered since the reset. Give sprint 3 the ordering precondition and a test that queues an event before or during reconciliation and checks that it is delivered once.

### critic-r1 4 — BLOCKER — R6

When an existing receipt is damaged, the only recoverable field specified for its replacement is the identifier in its filename. `OpenReceipts` then prunes using the latest of three times. If the builder leaves those unavailable times at zero, the new interrupted receipt is removed in the same open. A replay with a future expiry then returns `DecisionRun`, even if that command already acted. The malformed-receipt test leaves its clock and retention inputs implicit. (`.plans/plans/go-s1-client-local/plan.md:644`, `.plans/plans/go-s1-client-local/plan.md:648`, `.plans/plans/go-s1-client-local/plan.md:649`, `.plans/plans/go-s1-client-local/plan.md:662`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:284`.)

Define a durable interrupted marker for a valid identifier whose receipt cannot be read or validated. Keep it until the link contract provides a safe replay cutoff for that identifier. Validate the receipt identifier against the filename as well as the version and state. Freeze a test that opens a damaged receipt, runs pruning, reopens, and replays the same identifier with a future expiry. Require `DecisionReplay` after each reopen.

### critic-r1 5 — MAJOR — C11

The folder lock covers clients that call `state.Open`. Each store constructor takes a plain path and has its own in-memory state. A single lock holder can open two queue handles during reconnection. If both start at 1, the second handle can publish a different event at 1. Opening a second receipt handle while a command runs can also turn its live `started` record into `interrupted`. The existing tests exercise a second folder lock or multiple goroutines on one handle. (`.plans/plans/go-s1-client-local/plan.md:243`, `.plans/plans/go-s1-client-local/plan.md:257`, `.plans/plans/go-s1-client-local/plan.md:575`, `.plans/plans/go-s1-client-local/plan.md:605`, `.plans/plans/go-s1-client-local/plan.md:633`, `.plans/plans/go-s1-client-local/plan.md:648`.)

Specify that `join`, `run`, and the test entry point acquire `state.Open` before reading or changing durable state. Bind one outbox handle and one receipt handle to that ownership interval and reuse them across reconnections. Make a second open share the existing handle or return a named error. Test simultaneous opens and lock release after the first holder dies.

### critic-r1 6 — MAJOR — C11

### critic-r1 7 — MAJOR — D7

Use a nonblocking, no-follow open and validate the opened descriptor before reading. Define a distinct read error that identifies the file, preserves the operating-system cause, and contains no key bytes. Read one extra byte to detect an oversized file. Reject leading junk or extra blocks and reject trailing content other than the permitted final newline. Specify that `join` and `run` stop on unreadable or invalid keys without creating a replacement. Add named tests for a pipe, a read failure, an oversized file and extra content.
