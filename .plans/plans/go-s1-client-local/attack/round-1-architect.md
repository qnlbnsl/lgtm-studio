REVISE

The client can report an event or command receipt as durable before the directories that contain it are durable.

## Findings

### architect-r1 1 · BLOCKER · C11 · Persist the state directory tree before using it

Evidence by reading. `.plans/plans/go-s1-client-local/plan.md:241` creates missing ancestors, the state directory and both record directories. Line 246 syncs only the directory immediately containing the file. Line 586 then hands out an event number, and line 646 authorizes a command after the corresponding file write.

Failure. On a first start with a newly created state tree, a power loss after a successful append can lose an unsynced ancestor entry and make the whole outbox unreachable. The same window can lose an acknowledged machine key creation or the `started` receipt for a command that already ran. The proposed child-process tests leave the operating system and its directory cache running. [Linux file and directory sync semantics](https://man7.org/linux/man-pages/man2/fsync.2.html#DESCRIPTION)

Fix. Make `state.Open` a durability barrier. Under the folder lock, sync the containing directory for each new directory entry, including missing ancestors, before handing the folder to any caller. Define how a later open completes a partially initialized tree. Return any failure before accepting a durable write. Add an ordering test that removes an ancestor sync and goes red. Apply the same ordering to `machine.key`, `server.json`, `outbox/` and `receipts/` on a fresh install.

Risk. Integrity. Confirmed plan omission. Client state builder. 8 × 7 × 3 = 168, fix before release. A first-start power loss can permanently lose records and the identity cannot be reconstructed locally.

### architect-r1 2 · BLOCKER · C11 · Define what a write error means after placement

Evidence by reading. `.plans/plans/go-s1-client-local/plan.md:246` places the file before the directory sync, then cleans up the temporary name on error. Line 586 replaces an event at the current number and advances the in-memory counter after a successful write. Lines 588 and 646 use the same helper for acknowledgement and command start. Lines 601 and 607–608 exercise successful calls and process exits.

Failure. Append places event 6 and the directory sync reports an input/output error. The process stays up with `next` still 6. Another append replaces the first payload at 6, although a reopen between those calls would have recovered it. An acknowledgement with the same failure can also leave the on-disk mark ahead of memory. Key creation can return an error while the final name already exists.

Fix. Give the storage helper a distinct outcome for a failure after placement. Use exclusive placement for numbered event files. On uncertain commit, stop affected reads, writes and dispatch, retain the lock, and require recovery that re-establishes durability and reconciles the final names before retrying. Make the synced acknowledgement mark authoritative before any best-effort deletion. Specify that cleanup failures cannot change a committed result. Inject a failed directory sync after placement for append, acknowledgement, key creation and receipt writes. Assert that a live retry cannot overwrite a number, delete an unacknowledged payload, regenerate a key or dispatch against uncertain receipt state.

Risk. Integrity. Confirmed by the stated write order. Client state and local link builders. 8 × 7 × 4 = 224, fix before release. A single storage fault can permanently replace a pending event or leave its result ambiguous.

### architect-r1 3 · BLOCKER · C11 · Separate live acknowledgements from recovery of the counter

Evidence by reading. `.plans/plans/go-s1-client-local/plan.md:588` and `:599` deliberately allow an acknowledgement above all local numbers. `.plans/plans/go-s0-contract/draft/events.proto:16` treats gaps as dropped reports and `:30` allows acknowledgement of dropped reports. `.plans/plans/go-s0-contract/draft/link.proto:140` separately exposes the highest applied number during the authenticated handshake. The design requires buffered events to arrive once and in order. `docs/specs/2026-11-25-go-rewrite-foundation-design.md:288`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:388`.

Failure. The client has sent event 5 and is holding event 6 locally. A server sender defect emits a live cumulative acknowledgement for 6. The local API durably advances the mark and deletes event 6. If an event reaches the draft server beyond a gap, that draft also lets the server advance past a report it has never applied.

Fix. Require the live sender to bound acknowledgements by the highest number sent in the authenticated stream and reject a jump before touching disk. Require the server to advance its mark across a contiguous applied prefix for wave 1. Use a separate reconciliation operation for the authenticated `Welcome.last_event_number`, scoped to the same machine identity. Specify the error when the server reports a number below the local acknowledged mark. Prevent a counter advance from wrapping to zero. Agree on these rules with the Contract and Server teams before freezing the wire shape. Test unsent, stale, out-of-order and lost-acknowledgement cases with the real link.

Risk. Integrity and design. Confirmed mismatch with the current contract draft. Client link, Server link and Contract builders. 8 × 7 × 4 = 224, fix before release. A single incorrect acknowledgement can permanently discard a queued report.

### architect-r1 4 · MAJOR · R6 · Keep proof of execution through receipt repair and expiry

Evidence by reading. `.plans/plans/go-s1-client-local/plan.md:640` defines the receipt fields. Line 648 rebuilds a damaged file from its name and then prunes. Line 649 prunes by the latest of three times. Line 662 checks the unreadable case without defining the recovered time or how long that proof must survive. `.plans/plans/go-s0-contract/draft/commands.proto:16` keeps the same identifier across attempts and omits a lifetime rule for that identifier.

Failure. A command ran but its receipt now contains `{`. Recovery knows only the identifier. If it fills the three times with zero, opening the store can immediately prune the newly written `interrupted` receipt. A retry with an unexpired deadline can then run again. A valid receipt can also be pruned too early if a retry extends the original expiry or the expiry clock moves backward after pruning.

Fix. Define a fail-closed corruption path for a receipt whose expiry cannot be recovered. Keep a durable, non-prunable refusal marker for that identifier or stop opening the store until it can be repaired. Validate version, filename-to-identifier agreement, state and required fields, including for valid JSON with invalid contents. Agree with the server on the maximum replay deadline, whether every attempt uses the original expiry, and how pruning remains safe across clock corrections. Test corruption, immediate prune, another restart, and a higher attempt for the same identifier. Test the agreed expiry rule before trusting normal receipt pruning.

Risk. Integrity. Confirmed policy gap. Client and Server command builders. 6 × 5 × 3 = 90, schedule. Repeating a command such as restart breaks the promised command flow after a storage or clock fault.

### architect-r1 5 · MAJOR · C11 · Make the state lock a prerequisite of every store open

Evidence by reading. `.plans/plans/go-s1-client-local/plan.md:231` exposes a `Folder` and independent path strings. Line 243 holds an advisory lock. Lines 575 and 633 let an outbox or receipt store open independently from a path. Line 589 promises method-level concurrency safety. `decisions.md:15` permits a second state directory, and `decisions.md:19` promises a single holder of each directory. Both references are under `.plans/plans/go-s1-client-local/`.

Failure. Two `OpenOutbox` calls on the same path can each recover `next = 6` and write event 6 under independent mutexes, even if one process holds the folder lock. A second `OpenReceipts` can also turn a live `started` receipt into `interrupted`. Two copied state trees with the same key and machine identifier each acquire a different lock and independently issue the same sequence numbers.

Fix. Make the opened state folder own one outbox and one receipt store, or require a held lease and enforce one opener per store. Hold that lease across `join`, `run`, recovery, temp cleanup and shutdown. Validate the lock file and keep its inode stable for the lifetime of the directory. Give the installer and service the same state selection. Define a separate state directory as a separate enrollment and forbid copying a live identity into another writer's directory. Test two opens inside a process, two processes using one directory, and two separately enrolled directories.

Risk. Integrity and design. Confirmed unenforced ownership boundary. Client state and client link builders. 8 × 7 × 2 = 112, schedule. Two writers can overwrite records, but duplicate opens or copied enrollments require a specific failure in wiring or operation.

### architect-r1 6 · MAJOR · C11 · Assign serialization, ordering and backpressure to the link producer

Evidence by reading. `.plans/plans/go-s1-client-local/plan.md:45`, `:520` and `:573` describe refusal on full storage and opaque bytes numbered by `Append`. `.plans/plans/go-s3-client-link/plan.md:45` calls for ordered resend and `:47` assigns reporting. The current draft puts the number in `Event.number = 1`, the producer time in `happened_at = 2`, and typed reports in `facts = 10` and `harnesses_found = 11`. `.plans/plans/go-s0-contract/draft/events.proto:14`.

Failure. A reporting worker serializes a complete wire event before `Append` has assigned its number. It has to invent a number or serialize an event with zero. A scan command can also run and return success while its harness report was refused by a full outbox. A live sender that races the resend worker can transmit a new number before older pending numbers.

Fix. State that the outbox accepts a versioned report body and producer time, and the link sender fills the wire number exclusively from `Event.Seq`. Keep the storage package independent of generated types. Assign one ordered sender per machine and specify one wake-and-drain rule for old and new events. Require the reporting and command layers to retain and retry blocked reports or surface an explicit failure. Complete a scan command successfully only when its report is durable. Define how producers handle a crash between commit and notification without treating a replayed report as a new logical event. Add an end-to-end test with a full outbox, a scan command, a server restart and a lost acknowledgement.

Risk. Design. Confirmed handoff gap. Client link builder with the Contract and Server link builders. 6 × 5 × 6 = 180, fix before release. An ordinary network outage or startup race can break the Machines page and the ordered resend promise.

### architect-r1 7 · MAJOR · D7 · Define the join recovery contract for the two credential files

Evidence by reading. `.plans/plans/go-s1-client-local/plan.md:149` allocates `machine.key`, line 150 leaves the enrollment record for sprint 3, and line 382 defers what a second join does. `.plans/plans/go-s3-client-link/plan.md:43` says join makes a key pair. ### architect-r1 8 · MAJOR · D7 · Refuse an unreadable or malformed key without blocking or regenerating it

Evidence by reading. `.plans/plans/go-s1-client-local/plan.md:332` declares key errors. Lines 335–336 open read-only and check the descriptor afterward, then cap the read at four kibibytes. Line 350 tests a missing path and some invalid content. Go's `encoding/pem/pem.go:89` searches for a block and can skip leading bytes.

Failure. A named pipe at `machine.key` with no writer blocks a read-only open before `Stat` can refuse it as nonregular. An ordinary permission or read error has no explicit link-level handling. A valid block followed by enough data can pass a decoder that sees only a truncated prefix.

Fix. Open with no-follow and nonblocking flags before checking that the descriptor names a private, caller-owned regular file. Read one byte beyond the supported limit to detect oversized input and require one complete block under an explicit whitespace rule. Reserve `ErrKeyMissing` for absence. Surface other open or read failures without key bytes and preserve the existing file. Add bounded-time checks for a named pipe, access denied as a regular user, a valid key with excess data, and a failed read. Require join to stop on any load error other than absence.

Risk. Availability and design. Confirmed from the prescribed open and decode sequence. Client enrollment builder. 6 × 3 × 4 = 72, schedule. A single malformed local file can hang enrollment or stop it until repaired.
