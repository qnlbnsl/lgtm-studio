REVISE

An acknowledgement above the last locally issued event can make the client permanently discard queued events that the server never applied.

## Findings

### threat-r1 01 — BLOCKER — C11

The acknowledgement API combines acknowledgement of sent events with recovery of a lost outbox. If events 6 and 7 are pending and the acknowledgement belongs to a different enrollment or reports an incorrect position of 41, `Ack(41)` deletes both events and advances the next number to 42. The planned test asserts this jump for an empty queue and never checks it with unsent events. Separate normal acknowledgement from lost-outbox recovery. On the authenticated, approved stream, accept a cumulative acknowledgement only through the highest contiguous event sent for that enrollment. Reconcile the same enrollment's server position explicitly on reconnect. Allow recovery to advance a known empty, lost queue after authentication and surface the loss. Preserve pending files and stop on an unexplained disagreement, including a server position below the durable local acknowledgement. Add tests for both directions of disagreement and for a valid reconnect after delivery but before acknowledgement. `.plans/plans/go-s1-client-local/plan.md:585-601`, `.plans/plans/go-s1-client-local/decisions.md:24`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:288-292`.

Category is integrity. Evidence is confirmed by reading. Client and link builders own the fix. Risk is 224 (8 for lost events × 7 for irreversible deletion × 4 for a peer or recovery fault).

### threat-r1 02 — BLOCKER — C11

The acknowledgement mark accepts a damaged value that still parses as a decimal number. If a mark of 1 is damaged to 9 while events 2 through 4 remain pending, recovery deletes them before it can discover that the mark is wrong. Give the mark a versioned, integrity-checked format and distinguish a new outbox from a missing mark in an established one. Refuse damage before any deletion. Test a digit change that still parses, a missing mark after all events were acknowledged, and preservation of every pending file on recovery failure. `.plans/plans/go-s1-client-local/plan.md:534-554`.

Category is integrity. Evidence is confirmed by reading. The client outbox builder owns the fix. Risk is 224 (8 for lost events × 7 for irreversible deletion × 4 for one storage fault).

### threat-r1 03 — BLOCKER — C11

First-time directory creation has no durability rule for the parent entries that name the new directories. If the first append succeeds and the machine loses power before those entries reach disk, syncing the event file and `outbox/` cannot by itself guarantee that `outbox/` is reachable after reboot. The same gap applies to the initial key and receipts. Require successful parent synchronization for all newly created entries in the directory chain before `Open` returns. Use a filesystem that supports the required durability operations and fail if it cannot provide them. Add an ordering test that covers fresh initialization and injected parent sync errors. The existing process-exit tests exercise file replacement while the operating system remains running. `.plans/plans/go-s1-client-local/plan.md:240-247`, `.plans/plans/go-s1-client-local/plan.md:262-265`, `.plans/plans/go-s1-client-local/plan.md:296-298`.

Category is integrity. Evidence is confirmed by reading. The client state builder owns the fix. Risk is 224 (8 for lost durable state × 7 for unrecoverable state × 4 for a power or filesystem fault).

### threat-r1 04 — BLOCKER — D19

The plan checks the final directories but leaves the path to them and the existing `lock` file outside the ownership checks. If another local user can replace a parent directory entry, the first client can keep the lock on the original file while a second opener resolves the same configured path to another file. The first client can also resolve a later path-based write through the replacement. Require that the state path cannot be redirected by another user. Validate and hold the directory you actually opened, check the existing lock as an owned private regular file, operate relative to the validated directories, and acquire the stable lock before recovery or cleanup. Require `join` and `run` to hold it for the full lifetime of all state operations. Test a mutable parent and an invalid pre-existing lock, in addition to the normal two-process case. `.plans/plans/go-s1-client-local/plan.md:144-162`, `.plans/plans/go-s1-client-local/plan.md:230-258`.

Category is isolation and integrity. Evidence is confirmed by reading. The client state builder owns the fix with the client link builder. Risk is 112 (8 for overwritten or misdirected state × 7 for lost state × 2 for a shared path setup with a second writer).

### threat-r1 05 — BLOCKER — R6

Recovery can remove the only evidence that a command may already have run. If a receipt for a still-live command becomes unreadable, `OpenReceipts` reconstructs the identifier but has no trustworthy expiry or execution timestamps. When the reconstructed record has zero timestamps, the immediate `Prune` removes it, and the next delivery can run the command again. Preserve a durable record that refuses execution for that identifier until the server establishes that the command can no longer arrive, or fail closed and preserve the damaged file. Validate the filename against the record identifier and check the version, state and required timestamps before replay or pruning. Test damage to a live receipt across recovery, pruning and redelivery. The corrupted-receipt test must exercise that sequence and assert that the command never runs again. `.plans/plans/go-s1-client-local/plan.md:640-649`, `.plans/plans/go-s1-client-local/plan.md:661-665`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:281-286`.

Category is integrity. Evidence is confirmed by reading. The client receipts builder owns the fix. Risk is 224 (8 for an irreversible repeated action × 7 for an outcome a receipt cannot undo × 4 for one damaged record).

### threat-r1 06 — BLOCKER — R9

An absolute search directory can still be writable by somebody else. If the service search path includes such a directory, a different local user can supply a candidate that the client will run under its own user. The subprocess can read files accessible to that user, including the machine key, even with three environment variables. Define a trusted executable policy for the probe and the lookup paths a wrapper inherits. An owner-configured or recognized installation must resolve through trusted, non-writable-by-others paths under a trusted owner. Skip ambiguous candidates before starting them. Test that discovery skips a candidate in a shared writable directory and that ordinary trusted installations still work. The old engine verifies managed executable identities and constrains discovered Cursor and Gemini candidates. `.plans/plans/go-s1-client-local/plan.md:445-454`, `packages/engine/src/harnesses/programs.ts:124-140`, `packages/engine/src/harnesses/programs.ts:205-234`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:505-511`.

Category is isolation. Evidence is confirmed by reading. The client harness builder owns the fix. Risk is 224 (8 for compromise of machine identity × 7 for irreversible disclosure of the key × 4 for a shared executable path).

### threat-r1 07 — MAJOR — C11

A write can place its new file and then return a directory synchronization error. If `Append` returns an error without advancing its in-memory counter, a retry can replace the same event file, while a restart could recover and send the first payload despite the reported failure. A failed acknowledgement write can likewise leave the on-disk mark ahead of the in-memory mark. Define a distinct outcome for a failure after placement. Stop issuing numbers, deleting events or authorizing commands until the record has been reconciled durably. Specify how the producer learns whether to retry, and how the original payload survives an uncertain outcome. Inject sync failures after placement for append, acknowledgement, and receipt transitions, then exercise retry and reopen. The interruption tests only cover process exit. `.plans/plans/go-s1-client-local/plan.md:234-247`, `.plans/plans/go-s1-client-local/plan.md:584-590`, `.plans/plans/go-s1-client-local/plan.md:607-608`, `.plans/plans/go-s1-client-local/plan.md:645-648`.

Category is integrity. Evidence is confirmed by reading. The client state, outbox and receipts builders own the fix. Risk is 120 (6 for an ambiguous core operation × 5 for manual reconciliation × 4 for one synchronization error).

### threat-r1 08 — MAJOR — R6

The same adjustable client clock controls command execution and receipt deletion. If it jumps forward far enough to prune a live receipt and then moves back, the next delivery can run that command again. A slow clock can also run a command after the server's expiry. Set a time authority and a fail-closed rule for remotely issued commands before freezing the receipts interface. Retain identifiers until the client has trusted evidence that redelivery is impossible, including after a clock correction or reconnect. Treat the expiry instant as the end of eligibility. Test a clock behind the server, the exact expiry instant and a forward-then-backward adjustment across pruning. `.plans/plans/go-s1-client-local/plan.md:632-649`, `.plans/plans/go-s1-client-local/plan.md:659-665`, `.plans/plans/go-s1-client-local/decisions.md:27-28`.

Category is integrity. Evidence is confirmed by reading. The client receipts and link builders own the fix. Risk is 120 (6 for a command eligibility failure × 5 for manual recovery × 4 for a clock fault).

### threat-r1 09 — MAJOR — D7

The directory layout reserves `server.json` but does not bind the queues or receipts to an enrollment. If an existing state directory is reused for a fresh enrollment, old queued events can be sent under the new identity or be discarded as acknowledged against a different sequence. Bind each state directory to the machine key, pinned server identity and assigned machine identifier. Define retry after partial enrollment, the same-enrollment restart, and a deliberate move to fresh state when enrollment changes. Require the later reader to verify the server record and credential before opening enrolled state. Distinct directories avoid the same lock, but clients using defaults still share the repository directory. Require a distinct repository directory for simultaneous profiles, or explicitly restrict that use before the clients can write repositories. `.plans/plans/go-s1-client-local/plan.md:144-162`, `.plans/plans/go-s1-client-local/plan.md:189-197`, `.plans/plans/go-s1-client-local/plan.md:379-382`, `.plans/plans/go-s3-client-link/plan.md:43-48`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:247-256`.

Category is design and integrity. Evidence is confirmed by reading. The client local and link planners own the handoff. Risk is 180 (6 for broken enrollment or misattribution × 5 for manual recovery × 6 for ordinary retry or re-enrollment).

### threat-r1 10 — MAJOR — R9

Selecting a version-shaped substring does not establish that it is a version. If a genuine harness emits a diagnostic first and the only dotted number is a credential fragment, the scan keeps that text and makes it eligible for a website report. The current test plants its secret after a valid version and outside the pattern. Specify whole-line, harness-specific output from a recognized installation, require a successful exit, and report the version as unknown for any ambiguous output. Use trusted installation metadata where it supplies the version. Test a diagnostic containing version-shaped data and a failing command that prints a version-looking line. Keep raw output and local executable paths out of the report. `.plans/plans/go-s1-client-local/plan.md:449-454`, `.plans/plans/go-s1-client-local/plan.md:464-472`, `src/contracts/proto/lgtm/v1/clients.proto:76-81`.

Category is confidentiality. Evidence is confirmed by reading. The client harness and reporting builders own the fix. Risk is 168 (6 for private text disclosed × 7 for an irreversible disclosure × 4 for a diagnostic fault).

### threat-r1 11 — MAJOR — D7

The key loader specifies a blocking open before it checks for a regular file. A named pipe at `machine.key` with no writer can block startup indefinitely, while an unreadable regular file has no prescribed diagnostic or recovery path. Open without following links or blocking on special files, check the opened descriptor, read with an enforced size limit, and reject content outside the single expected key block. Return a safe, actionable error for unreadable and invalid keys. Preserve the existing key path and require deliberate recovery or re-enrollment. Add tests for a nonregular file, denied access, oversized content and a valid block surrounded by unexpected content. `.plans/plans/go-s1-client-local/plan.md:325-350`.

Category is access and integrity. Evidence is confirmed by reading. The client enrollment builder owns the fix. Risk is 120 (6 for startup failing until corrected × 5 for manual recovery × 4 for one unusable key file).

### threat-r1 12 — MAJOR — C11

The queue has an explicit full response, but the handoff does not require a durable producer response to it. If the server is down and a producer receives `ErrOutboxFull` for a report whose source it then forgets, the report never reaches the outbox and the next report can still get the next number. Define which reports can be regenerated and which must be retained until accepted, and supply a backpressure or retry contract for the latter. Keep the refusal test and add a producer-level test that saturates the queue, restores connectivity, then verifies delivery in order. `.plans/plans/go-s1-client-local/plan.md:45-48`, `.plans/plans/go-s1-client-local/plan.md:585-586`, `.plans/plans/go-s1-client-local/plan.md:602`, `.plans/plans/go-s1-client-local/plan.md:712`, `.plans/plans/go-s3-client-link/plan.md:45-47`.

Category is integrity. Evidence is confirmed for the missing requirement, by reading. The client link planner owns the handoff. Risk is 120 (6 for a missing report × 5 for manual recovery × 4 for an outage that fills the queue).

## Answers to the attack questions

1. The local code accepts environment and settings, state files, operating system facts, and harness output. It checks the state path's form, the settings schema, the final directories' ownership and modes, the opened key's type and ownership, event length and checksum, and command identifier and fields. The harness scan checks executable type and output shape. The gaps are path trust, mark integrity, receipt recovery and harness provenance. Network messages and approval enter in sprint 3. This slice has no website, database or network entry point. `.plans/plans/go-s1-client-local/plan.md:129-162`, `.plans/plans/go-s1-client-local/plan.md:190-197`, `.plans/plans/go-s1-client-local/plan.md:334-337`, `.plans/plans/go-s1-client-local/plan.md:410-415`, `.plans/plans/go-s1-client-local/plan.md:447-455`, `.plans/plans/go-s1-client-local/plan.md:534-540`, `.plans/plans/go-s1-client-local/plan.md:642-649`.
2. The machine's Ed25519 private key is generated locally, serialized in `machine.key` and a temporary file, and used through a signer. The public key, fingerprint and signatures may leave the machine in sprint 3. `server.json` stores public trust data, not a credential secret. The plan specifies fingerprint-only credential formatting and errors without key bytes. Temporary files are removed on recovery. Outbox payloads and receipt results are opaque and have no filtering gate here. There are no web cookies, password verifiers or stored join or connection tokens in this slice. The later `join` brief passes the token as an argument, which can expose it through process inspection or shell history. Carry that exposure and the installer invocation into the sprint 3 review. `HOME` gives a harness access to files the child user can read. `.plans/plans/go-s1-client-local/plan.md:144-156`, `.plans/plans/go-s1-client-local/plan.md:324-337`, `.plans/plans/go-s1-client-local/plan.md:449-452`, `.plans/plans/go-s1-client-local/plan.md:519-520`, `.plans/plans/go-s1-client-local/plan.md:640`, `.plans/plans/go-s3-client-link/plan.md:24`, `.plans/plans/go-s3-stack-client/plan.md:42`.
3. The machine key has no local expiry, removal or rotation flow. Removing the machine revokes its registered key on the server and sprint 3 stops the client, while the local key file remains unless a separate recovery or decommissioning action removes it. Preserve identity on restart and settle deletion and re-enrollment in the handoff. The later join token is single-use with a 15-minute expiry. The short-lived connection token, web sign-out and cookies belong to other plans. `docs/specs/2026-11-25-go-rewrite-foundation-design.md:247-256`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:278-279`, `.plans/plans/go-s1-client-local/plan.md:334`, `.plans/plans/go-s3-client-link/plan.md:48`.
4. The local plan sends nothing. The design allows plain Hypertext Transfer Protocol on loopback and requires its encrypted form elsewhere, with a pinned server certificate and machine identity. Issue 1633 leaves the proxy termination and pin source to sprint 2 and sprint 3. The layout can reserve a public trust record pending that decision. At rest, mode `0600` inside `0700` directories protects against other ordinary local users. The private key and opaque records are plaintext and readable in a copied state directory or an unencrypted offline volume. Record the local storage assumption and settle disk and backup protection if copied state is in scope. Redact sensitive material before passing payloads or results into these stores. `docs/specs/2026-11-25-go-rewrite-foundation-design.md:316-335`, `docs/issues.md:7520-7529`, `.plans/plans/go-s1-client-local/plan.md:144-155`, `.plans/plans/go-s1-client-local/plan.md:519-520`, `.plans/plans/go-s1-client-local/plan.md:640`.
5. Nothing found among added Go modules or images. The plan uses only the Go standard library and waits on the Contract team's root module for the toolchain. A live check at commit `fb992dc9` found Go 1.23.3 installed and no tracked `go.mod` or Go client tree. The design requires Go 1.26 or newer. The four installed harnesses and any wrapper interpreters are external runtime executables selected from the machine. The plan does not pin or verify their provenance. `.plans/plans/go-s1-client-local/plan.md:114-116`, `.plans/plans/go-s1-client-local/plan.md:129-136`, `.plans/plans/go-s1-client-local/plan.md:447-456`, `.plans/plans/go-s1-client-local/scouting.md:89-98`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:71-74`.
6. Website and preapproval peers have no entry point in this slice. Sprint 3 must keep pending machines from processing work or changing durable counters. A different local user can affect the client when it relies on replaceable directory entries or executes a program discovered in a path that user can write. The design explicitly accepts shared access for processes of the client's own operating system user in this wave. The payload checksum detects accidental damage and supplies no proof of authorship. `.plans/plans/go-s1-client-local/plan.md:240-247`, `.plans/plans/go-s1-client-local/plan.md:448-454`, `.plans/plans/go-s1-client-local/plan.md:534-540`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:247-252`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:505-511`.
7. The post-build checks below cover real filesystem durability, process and file ownership boundaries, credential disclosure, command side effects and delivery against the real server.
a. `Create` writes and syncs a mode `0600` temporary file in the same directory, then links it to `machine.key` without replacement. The shared routine syncs the directory and removes the temporary name. An existing name returns `ErrKeyExists` without modification. `Load` distinguishes missing, exposed, wrong-owner, nonregular and malformed keys. An operating system read denial has no specified safe diagnostic, and no automatic repair is specified. `TestCreateExclusiveCrashAtEachStep`, `TestCreateRefusesExistingKey` and `TestLoadRefusesMissingAndInvalid` cover the published cases. `.plans/plans/go-s1-client-local/plan.md:234-247`, `.plans/plans/go-s1-client-local/plan.md:263-265`, `.plans/plans/go-s1-client-local/plan.md:332-351`.
b. Recovery chooses one above the larger of the acknowledgement mark and the highest complete pending event. In the crash-step test, the next event is 6 if event 6 never reached its name and 7 if it survived whole. `TestOutboxCrashAtEachWriteStep` and `TestOutboxKillKeepsEveryNumberedEvent` cover local process interruption and stable numbers. `TestAckIsDurableBeforeDelete` checks that the new mark is visible before deletion. `TestReceiptsCrashAtEachWriteStep` and `TestReceiptsKillNeverRunsTwice` cover the start and result transitions. An unacknowledged event can be retransmitted, and the server must apply it only once, in order. Delivery under false marks, power loss or producer backpressure and command replay after pruning need additional checks. `.plans/plans/go-s1-client-local/plan.md:539-540`, `.plans/plans/go-s1-client-local/plan.md:595-608`, `.plans/plans/go-s1-client-local/plan.md:656-669`, `docs/specs/2026-11-25-go-rewrite-foundation-design.md:288-292`.
c. The layout supplies the private machine key, a versioned slot for the server address, pin and assigned machine identity, settings, outbox and receipts. The later brief needs all of them. It still needs agreement on enrollment binding and record validation. Two regular opens of the same stable directory contend on one lock. Separate state directories get separate locks and local records, but can still collide through copied enrollment state or the shared default repository directory. `.plans/plans/go-s1-client-local/plan.md:144-162`, `.plans/plans/go-s1-client-local/plan.md:196`, `.plans/plans/go-s1-client-local/plan.md:241-257`, `.plans/plans/go-s3-client-link/plan.md:43-48`.

## Post-build checks

- **PB1. Client state and enrollment.** On Linux and macOS, use a second ordinary operating system user to verify the actual permissions, ownership and lock behavior. Refuse an unsafe state path and unreadable or nonregular key without blocking. A second process using the same valid state directory must refuse before touching records. Capture formatted credentials, startup errors and service logs with a test key. Only public material may appear.
- **PB2. Client state and outbox.** Record file and directory synchronization at fresh initialization and on append, acknowledgement and receipt writes. Use an abrupt machine or filesystem restart in an isolated test environment when supported. After reboot, every record reported durable must be reachable and complete. A numbered event must be pending under its original sequence or covered by a durable acknowledgement.
- **PB3. Client enrollment and installer.** Follow a successful join, an interrupted join and removal through the installed service. Verify that the same enrollment keeps its key, removal stops work, and re-enrollment uses the selected state and identity. Inspect invocation and logging with a synthetic token and confirm the token exposure rules settled by the sprint 3 plans.
- **PB4. Client harness and reporting.** Scan the four real trusted installations on Linux and macOS, then use inert fixtures for an untrusted location, an ambiguous diagnostic, a cancellation and a child with descendants. Verify rejection before any untrusted executable runs, bounded probe completion and cleanup, and a report containing only recognized names and validated version values.
- **PB5. Client and server link.** Connect through the deployed proxy with a trusted pin, a wrong pin and a pending machine. The trusted approved stream works. The other cases never authorize commands, reports or acknowledgement updates. Check the encrypted connection at each hop covered by the decision on issue 1633.
- **PB6. Client receipts and server link.** Drop the connection after the server commits an event but before the client records the acknowledgement. Verify replay in order and one application in the server's durable record. Interrupt an actual harmless command after its durable start and after it records a result. Redeliver its identifier and check the side-effect count and the result or interrupted status the server receives.
