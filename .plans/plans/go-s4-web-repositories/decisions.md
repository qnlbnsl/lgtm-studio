# Decisions for the sprint 4 website repository plan

The decision sources are the foundation design approved on 2026-11-25, the epic's team scope confirmed on 2026-11-26, and the running-an-agent design approved on 2026-11-27. The recovery note and added row of that design record the later decision on the same date.

| id | question | decision | rationale | status | date |
|---|---|---|---|---|---|
| 1 | What is the plan's size? | Use Tier M and eight low or medium items. | The assignment fixes Tier M. Each item has a separate first test and observable acceptance. | closed | 2026-11-27 |
| 2 | What belongs to this team and sprint? | Website changes are under `src/frontend/`. Include discovery, real repositories, machine facts, the two existing dialogs, cleanup, views and approved recovery display. The server, client, database and deployment work belong to their own teams. Projects, agents, threads, harness choices and creation by name belong to sprint 5 or later. | The epic records the team boundary confirmed on 2026-11-26. The newer design and brief record the sprint split approved on 2026-11-27. | closed | 2026-11-27 |
| 3 | Which workspace records can appear with the real service? | Include current watched machines, joining machines and saved repositories with folders. Exclude sample repositories, projects, agents, threads, tasks, teams and requests, plus the sample slices that depend on them. On sign-out, expiry or server change clear remote records, derived records and record-scoped dialog state, drafts, selections and notices. Keep browser appearance and navigation preferences. Keep both sample transports and capability-absent real servers in compatibility mode. | The owner approved the repository-only boundary and both sample modes in The website in sprint 4 on 2026-11-27. The included and excluded slices implement that design. | closed | 2026-11-27 |
| 4 | How is the real mode selected? | Wait to seed until discovery completes. Enable repository mode on a real server advertising the exact ProjectService name with contract revision 1. Keep the legacy engine mount independent. Stop compatibility timers when their workspace departs. | The approved website section and the reviewed contract keep revision 1 and gate on the advertised service. Early sample seeding would expose records on real startup. | closed | 2026-11-27 |
| 5 | What guards asynchronous work? | Use one selected server and session scope. Abort its network work at invalidation and verify identity before applying asynchronous results. Each dialog also checks its active intent. Bounded authentication calls serialize on a shared cookie hostname. | The design requires cleanup and dated folder replies. The scope check covers already queued data. The authentication order prevents a late cookie deletion on the same host. | closed | 2026-11-27 |
| 6 | How do watchers reconcile? | Replace each collection on its first frame and after reconnect. Gate initial rendering on both collections, including empty snapshots. During a transport retry retain the last visible snapshot in that scope and derive connection freshness from both streams. | Full snapshot replacement implements rule 5 and the closing line in round-three logic. Keeping the visible snapshot avoids a flash of missing records during a temporary disconnect. | unanswered | 2026-11-27 |
| 7 | How do save and watch meet without making duplicate state? | Match both returned identifiers against the watched repository and folder. One scoped refresh after a two-second wait establishes absence if the identifier still has not arrived. Retain folder identities in the projection alongside the existing machine-to-path lookup. If more than one folder is present on a machine, the convenience lookup uses the first by identifier and the view uses the full list. | The add reply has identities and no feed position. A newly opened snapshot after the reply can establish that a record was removed, and the watched list remains authoritative. | unanswered | 2026-11-27 |
| 8 | What is the browser's folder retry boundary? | A dialog activation, procedure, machine, exact path and target define an intent. Any input edit creates a new intent. Keep the key through a same-intent retry, including a manual save retry while offline, and use one automatic retry for an inconclusive inspect transport failure. Keep the current 700 millisecond debounce. | The approved design and reviewed contract require replay identity. This gives a lost inspection response a bounded recovery using the dialog that already exists. | unanswered | 2026-11-27 |
| 9 | Which machine starts a dialog? | Prefer its registered opener and otherwise the first online machine. When none qualifies the choice is empty. Keep a selected machine if it goes offline. If it disappears, choose from the current list and drop its old facts. | Both defaults and the empty-machine behavior were approved on 2026-11-27. Selection behavior after a watch update is an implementation assumption. | unanswered | 2026-11-27 |
| 10 | How does the new copy fit existing controls? | Use the copy table in the plan. Choose a dirty checkout sentence and put the approved projects-unavailable response in the existing action-refusal toast. Use the existing dash for a withheld remote and the existing label for an absent remote. Keep the New project controls in their existing places, with inert name entry and no project or repository creation. | The owner approved the original four changes on 2026-11-27. The exact dirty sentence, unavailable feedback treatment and absent-data rendering are planner choices. | unanswered | 2026-11-27 |
| 11 | What can an empty or saved repository show? | Use the existing missing-record, empty or unavailable bodies listed in the route table. Reuse the real checkout and project widgets. Route terminal entry to the existing unavailable treatment and show no simulated terminal. Keep appearance preferences available. Treat the sample controls and the simulated connection action as unavailable. | The bounded assignment requires an individual route decision. Current Usage, About, workflow and repository activity bodies fabricate results or actions without their services. | unanswered | 2026-11-27 |
| 12 | What appears for a machine needing recovery? | Use the approved status and reason in the copy table. Preserve Remove machine and show no recovery instruction. Build item 8 in sequence. | The later recovery note and the added design decision on 2026-11-27 settle the previously waiting item. | closed | 2026-11-27 |
| 13 | How does the status reach a waiting machine? | Show a flagged waiting machine in the existing Machines table only while it needs the diagnostic. Keep its pairing record in the waiting collection and exclude it from usable selections and registered counts. The existing remove action is available for a flagged waiting or host machine. | The contract asks the browser to verify waiting and offline. The owner chose the status column and opened row. The existing removal handler accepts both waiting machines and hosts. The temporary row for flagged waiting machines is a planner assumption. | unanswered | 2026-11-27 |
| 14 | How will browser cases prove timing and narrow layouts? | Use the existing Playwright dependency and one Website-owned configuration. Use generated messages in controlled browser fixtures. Run the built website with explicit barriers, both samples, desktop and a 390 by 844 pixel viewport. Merge the proof with the Go stack checks. | The assignment requires existing tools, worst-case inputs and phone coverage. Controlled response timing distinguishes browser ordering from server behavior. | unanswered | 2026-11-27 |
| 15 | How are staffing, linkage and the work area handled? | Use one vendor, the model sheet's `mobile-ui` work area, and the assigned `website/frontend` scope. The orchestrator registers the epic link, materializes the scope and reviews the plan. | The bounded assignment supplies the vendor rule and owns only its three plan documents and result. The existing work-area list covers screens, components and navigation under `mobile-ui`. | closed | 2026-11-27 |
