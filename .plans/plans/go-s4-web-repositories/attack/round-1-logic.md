## Answers to the attack questions

1. Discovery, session, dialog and stream attempts order work by the current identity. A replacement snapshot repairs a feed gap. A full upsert or removal by identifier tolerates repeat changes, and the browser needs no feed cursor or wrap logic. Reload starts a fresh scope. Duplicate submits share one active intent. First-folder selection has an identifier tie-break under the server's unique records. The join timeout and request-key expiry need the transitions in findings 03 and 04.
2. A sign-out or current expiry fences the proposals for both watches and protected actions. Normal stream loss retains records and reopens. A server crash can leave a durable operation open, and the original key can retrieve it. A database or transport error cannot justify a local success. The browser still needs a policy for a stalled refresh, receipt retirement and a server wait response. Cookie-writing order must cover dispatch of discovery. The browser should measure its own wait durations with elapsed time, while the server owns command expiry and receipt retirement.
3. Discovery cells are sample address or sample flag → compatibility, real with empty or unknown-only services → compatibility, and real with the exact entry → repository mode. Exact plus unknown is ambiguous in item 1. Readiness is hidden for neither or only one initial snapshot and open for both. Save cells are healthy match → complete, healthy miss → wait, a fresh post-reply snapshot without a match → refusal, and obsolete intent → ignore. The stale match and no-snapshot refresh cells are wrong or empty. An online selection allows a fresh call, a selected offline machine allows the specified add replay only, and a blank selection permits neither. Recovery takes status precedence when true and uses normal status when false. Its flagged offline detail has the conflict in finding 07.
4. Omitted discovery services mean compatibility, and omitted recovery means false. Empty snapshot lists open the gate when both streams have provided their snapshot frames. Omitted target stays absent, and the browser has no legitimate empty-string target. Blank machine disables writes. A missing remote and a withheld remote are different states. No browser-generated enumeration or feed position is introduced. In the browser fixture, any malformed success without facts or saved identifiers must fail safely without completing the form.
5. Watch and unary results can contend for machine and repository records. Watches own the records, while replies own progress and feedback only. Old and replacement streams can be active at a barrier, so the attempt identity fences their commits. A departing sample callback can still write to the shared store. Cookie writers and discovery can read overlapping session state. Machine removal and folder completion need the order in finding 02.
6. Items 1, 2, 3, 5, 6, 7 and 8 name risky mutations. Use a controlled queued-frame mutation for item 3 and a retained-snapshot mutation for item 6. Route all sample callbacks through one scope-aware scheduling boundary and all same-host discovery and cookie writes through one ordering boundary.
