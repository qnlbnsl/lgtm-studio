The token command cannot compile against the Server plan because it requires two certificate fields that the Server plan omits.

### critic-r1 01 | BLOCKER | D7 | The token command calls interfaces the Server team does not provide

**Evidence.** `.plans/plans/go-s3-stack-client/plan.md:96`, `:98`, and `:154`–`:158` require `Config.TLSCertFile`, `Issuer.CertificateFile`, and closure of the vault client. **Fix.** Remove the two certificate fields from the dependency table and command procedure. ### critic-r1 03 | MAJOR | C6 | An interrupted rejoin can leave the service enabled with unfinished state

**Evidence.** `.plans/plans/go-s3-stack-client/plan.md:236`–`:243` replaces the program, stops the service and moves the old folder before joining. It specifies neither rollback nor a recovery marker. A stop leaves the old enabled unit on disk. `.plans/plans/go-s3-client-link/plan.md:103`–`:109` and `:262` describe pending joins that rely on the same token and key and a fresh folder after an unusable token. `.plans/plans/go-s3-server-machines/plan.md:263`–`:269` ties replay to the token row.

**Failure.** An approved client starts `--rejoin`. The server accepts the new enrollment, then the local store write fails before `identity.json` is committed. The old folder has already moved. On reboot, Linux can start the enabled unit against the incomplete folder and repeatedly fail. A plain rerun mints a different token even though the first attempt may have left a waiting server record. Separately, a regular reinstall can replace the working program before a unit reload or restart fails.

**Fix.** Specify the durable checkpoints for program replacement, enrollment and service activation. Keep the previous installation recoverable until the new state and service are verified. Define the next action for an interrupted join after server commit, including how the owner finds and removes a stranded waiting record when the original token cannot be reused. Propagate service-manager failures with the resulting state and the recovery command. Test failure after the old service stops, after server acceptance, and after the unit is written.

### critic-r1 04 | MAJOR | D19 | Rejoin can move a directory that belongs to something else

Document that a different nonroot account is a separate installation under the current procedure, or define and enforce a refusal if there may only be one host installation.

### critic-r1 05 | MAJOR | R9 | Installer token output tests miss process arguments and shell tracing

Category Security (isolation). Responsible builders Stack infrastructure and Client backend. Evidence confirmed by reading and a synthetic process probe.
