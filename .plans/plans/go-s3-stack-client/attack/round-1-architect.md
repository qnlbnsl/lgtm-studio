### architect-r1 01 — BLOCKER, D17 — The token command names fields the server does not provide

**Evidence.** By reading, the installer plan gives the command `TLSCertFile`, `Issuer.CertificateFile` and a vault client close operation. The sign-in plan defines `config.Config` and `vault.Client` without those members or a `Close` method. The Machines plan defines `Issuer{PublicURL, ServerKey}`, wires the app that way, and rejects HTTPS (Hypertext Transfer Protocol Secure) issuance in wave 1. `.plans/plans/go-s3-stack-client/plan.md:96`, `.plans/plans/go-s3-stack-client/plan.md:154`, `.plans/plans/go-s2-server-signin/plan.md:380`, `.plans/plans/go-s2-server-signin/plan.md:428`, `.plans/plans/go-s3-server-machines/plan.md:138`, `.plans/plans/go-s3-server-machines/plan.md:251`, `.plans/plans/go-s3-server-machines/plan.md:583`.

**Failure.** A builder who uses `cfg.TLSCertFile` and `CertificateFile` as specified gets undefined-field errors before the first command test can run. A direct call to close the vault client also has no declared interface.

**Fix.** Match the Machines application's two-field issuer and keep the loopback token's certificate fingerprint empty. ### architect-r1 02 — MAJOR, R9 — The installer exposes a live credential at the command boundary

**Evidence.** By reading, the token command prints the bearer value to standard output, the installer captures it in a shell variable and passes it as a positional argument, and the test shim hashes it before logging. The success test only checks the captured output and files. The plan already acknowledges visibility to another local user. `.plans/plans/go-s3-stack-client/plan.md:134`, `.plans/plans/go-s3-stack-client/plan.md:156`, `.plans/plans/go-s3-stack-client/plan.md:239`, `.plans/plans/go-s3-stack-client/plan.md:250`, `.plans/plans/go-s3-stack-client/plan.md:258`, `.plans/plans/go-s3-stack-client/plan.md:334`.

**Failure.** On a host where other users can see process arguments, the active join exposes a redeemable token bearing the server-host mark. Shell tracing can also emit the expanded token into diagnostic output. A direct invocation prints it into any recorded terminal session or build log, and a human who pastes a literal join command may save it in shell history. Waiting for approval still limits what the resulting enrollment can do.

**Fix.** Name the credentialed server operator as the issuer and document that container execution access plus the server's database and OpenBao credentials is the practical authorization boundary. The mark records how the token was issued. Agree with Client Link on a standard-input form for automation while preserving the positional form from the design. Disable tracing before handling the value and use fixed usage errors that omit argument values. For stack acceptance, assert token shape without writing the value to the report. Use a synthetic marker to test traces, process arguments and captured logs. [Docker Compose exec reference](https://docs.docker.com/reference/cli/docker/compose/exec).

### architect-r1 03 — MAJOR, C6 — A retry can create another waiting machine after the first join committed

**Evidence.** By reading, the installer mints a new token whenever `identity.json` is absent. The client saves that file after the server confirms the join and the local store opens and closes successfully. The Machines plan makes replay idempotent for the same token and key. `.plans/plans/go-s3-stack-client/plan.md:238`, `.plans/plans/go-s3-stack-client/plan.md:239`, `.plans/plans/go-s3-client-link/plan.md:105`, `.plans/plans/go-s3-client-link/plan.md:108`, `.plans/plans/go-s3-server-machines/plan.md:263`.

**Failure.** The server creates a waiting row, then the installer is interrupted before the client publishes `identity.json`. A plain rerun reuses the pending `machine.key` and supplies a fresh token. The server treats that token as a new redemption and creates another waiting row.

**Fix.** Specify a pending-enrollment recovery path before minting another token. If the installer cannot resume the same token securely, stop on a saved key without an identity, tell the operator how to remove the pending server record if present, and require deliberate enrollment from a fresh folder. Add a test for an interruption after server commit and before local identity publication.

### architect-r1 04 — MAJOR, D16 — A failed rejoin stops the existing installation and leaves its replacement unfinished

**Evidence.** By reading, the installer replaces the executable, stops the service, and moves the selected state directory before it requests a token. A failure exits before the service-file step, with no instruction to restore the prior state or service. The selected directory need only pass syntax and absolute-path checks. `.plans/plans/go-s3-stack-client/plan.md:232`, `.plans/plans/go-s3-stack-client/plan.md:236`, `.plans/plans/go-s3-stack-client/plan.md:237`, `.plans/plans/go-s3-stack-client/plan.md:239`, `.plans/plans/go-s3-stack-client/plan.md:266`, `.plans/plans/go-s3-stack-client/plan.md:288`.

**Failure.** With an approved, healthy client, `--rejoin` stops it and moves its state. The token command then fails because the vault is unavailable. The old unit is still present and points at the original path. A retry or reboot can find an empty or partial enrollment there. An unsafe absolute override can also make the move affect an unrelated directory before the client opens and validates it.

**Fix.** Validate that the selected directory belongs to the current installation and user before any mutation. Prepare a fresh enrollment in a private sibling directory under an installer lock, then switch the binary, service and state after join succeeds. Specify rollback for a failed switch or service start, and preserve the former state under a collision-safe name only when the replacement commits. Cover failure before token creation, during join and during service restart with an existing installation.

### architect-r1 05 — MAJOR, D16 — A successful second install can keep dialing the old stack port

**Evidence.** By reading, a rerun probes the current published port, skips enrollment on file existence and declares success when the service is active. The client saves its origin in `identity.json` and dials that saved origin while retrying failures. `.plans/plans/go-s3-stack-client/plan.md:234`, `.plans/plans/go-s3-stack-client/plan.md:238`, `.plans/plans/go-s3-stack-client/plan.md:242`, `.plans/plans/go-s3-client-link/plan.md:108`, `.plans/plans/go-s3-client-link/plan.md:194`.

**Failure.** The owner changes the published port and runs the installer again. The probe reaches the new port. The service process retries the old port, stays active, and the installer exits successfully while the machine is offline.

**Fix.** Define how the installer validates the saved identity and normalized origin against the selected stack before it mutates the installation. On mismatch, give the operator the documented recovery action and preserve the existing installation. If preserving enrollment across an origin move is intended, put the authenticated update in the client and specify its caller. In the live rerun test, check the same machine's identifier and connection against the selected stack.
