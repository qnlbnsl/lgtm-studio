REVISE

The token command cannot compile as planned because it reads a configuration field and sets an issuer field that the Server plans do not define.

## Findings

In the citations below, `plan.md` and `decisions.md` refer to the files in this plan's folder. The findings concern the written behavior. The installer and the Sprint 3 commands were unavailable for end-to-end execution in this checkout.

### logic-r1 01 · BLOCKER · R3

The token command requires `Config.TLSCertFile` and `machines.Issuer.CertificateFile`. Neither field exists in the interfaces the Server builders are told to implement. When the command is merged with those interfaces, its package fails to compile, so the installer cannot obtain a token. Pass only `PublicURL` and the signing public key to `Issuer`, use `TokenOptions{HostsServer: flag}` to select the mark, and remove the obsolete certificate-file setting from the handoff. Keep the loopback test's assertion that the certificate fingerprint is empty. Evidence is by reading. The Server command builder owns this design finding. The build gate is unscored. (`plan.md:96`, `plan.md:98`, `plan.md:155`, `.plans/plans/go-s2-server-signin/plan.md:379`, `.plans/plans/go-s3-server-machines/plan.md:139`, `.plans/plans/go-s3-server-machines/plan.md:251`.)

### logic-r1 02 · MAJOR · D19

The rejoin path can rename a directory that does not belong to the installation. For example, an owner sets `LGTM_CLIENT_STATE_DIR=$HOME` while debugging and runs `--rejoin`. The absolute-path check passes, and the script attempts to move the entire home directory before the client has examined any state. On a machine where the user can rename that directory, this moves unrelated files and the command path. Require an absolute, canonical home and verify that the rejoin source is a dedicated client state directory before stopping the service or renaming it. Reject symlinks, the home itself, and directories that encompass the installer, binary, or service configuration. Reuse the client's ownership and state validation rules, and define how the installer recognizes a partial enrollment. Test a rejected override with a sentinel file and with a service already installed. Evidence is by reading. Stack owns this design finding. Risk is 72, from 6 for an unusable installation and displaced files, 3 for operator recovery by restoring the directory, and 4 for one configuration mistake. (`plan.md:231`, `plan.md:232`, `plan.md:236`, `plan.md:237`, `src/client/internal/config/config.go:27`, `src/client/internal/state/folder.go:63`.)

### logic-r1 03 · MAJOR · D16

A failed replacement can strand a working service. Start with an enabled unit and an approved machine. During `--rejoin`, the script replaces the binary, stops the service, and moves its state out of the way. If issuing or redeeming the token then fails, the unit remains enabled at the old path, which has no completed enrollment. At the next boot, the unit can repeatedly start a client that exits 1. The Linux test for join failure starts with no unit, so it misses this state. Specify a staged replacement with a durable transition record. Preserve the previous binary, unit or agent, and state until the replacement is joined and validated. If a failure interrupts the switch, restore the prior usable service or leave a deliberately disabled service with an explicit recovery command when the old identity was revoked. Require the next invocation to reconcile an interrupted switch. Test both a rejected token and an interruption after moving state. Apply the same policy to launchd. Evidence is by reading. Stack owns this failure-policy finding. Risk is 72, from 6 for the service staying broken, 3 for operator recovery, and 4 for a single failure during rejoin. (`plan.md:233`, `plan.md:236` through `plan.md:247`, `plan.md:259`, `plan.md:268`, `plan.md:288`, `.plans/plans/go-s3-client-link/plan.md:263`.)

### logic-r1 04 · MAJOR · D7

An interrupted first join can create two records for the same key. If PostgreSQL commits redemption and the installer is killed before the client publishes `identity.json`, the state folder can still hold `machine.key`. A plain rerun sees no identity file, mints a different token, and the client reuses the pending key. The Server plan gives a replay only for the original token and key. Its machine schema allows the same public key in two rows. The rerun can leave a second waiting record and no way for the owner to tell which record belongs to the finished installation from the host name alone. Add an explicit pending case before token issuance. Refuse automatic issuance for a pending key, give the owner the original token identifier and the steps to locate and remove its record if one exists, then require a fresh state directory for a new join. A deliberate resume using the original token and key can also be specified if the plans agree on a protected way to retain that token. Prove that interrupting after the Server commit and rerunning creates no second record. Evidence is by reading. Stack owns the installer decision with the Client and Server builders. Risk is 48, from 4 for a duplicate record and interrupted enrollment, 3 for recovery from the Machines page, and 4 for one interruption at the commit boundary. (`plan.md:238`, `plan.md:239`, `.plans/plans/go-s3-client-link/plan.md:104`, `.plans/plans/go-s3-client-link/plan.md:262`, `.plans/plans/go-s3-server-machines/plan.md:221`, `.plans/plans/go-s3-server-machines/plan.md:263`.)

### logic-r1 05 · MAJOR · D19

The service, binary, and state changes have no shared owner across invocations. For example, `--remove` can remove the unit and binary after an update has replaced the binary but before it renders or restarts the service. The update can then leave an enabled unit for a missing program. The client locks a file inside the state folder, so that lock does not serialize the installer or stop a foreground client from writing to a directory the installer just moved. The proposed archive name also repeats on a same-second retry or a clock step. A temporary-directory probe confirmed that plain `mv` into an existing archive directory nests the new source in the archive. Serialize install, rejoin, and removal on one stable lock per user and service outside the movable state. Agree with Client on an exclusive state move or refuse a foreground holder. Reserve each archive path exclusively with a unique suffix and require the rename to fail if a destination exists. Test a competing removal and two archive allocations at the same timestamp. Evidence is by reading, with the archive collision confirmed live. Stack owns this ordering finding. Risk is 48, from 4 for a broken local installation, 3 for an owner rerun or restore, and 4 for overlapping operations. (`plan.md:84`, `plan.md:85`, `plan.md:90`, `plan.md:233`, `plan.md:236` through `plan.md:240`, `src/client/internal/state/folder.go:94`.)

### logic-r1 06 · MAJOR · R9

Capturing the server's standard output still puts the live token in the client's process arguments. A second account that can read process arguments can redeem it first under another key. Turn tracing off before capturing any token. Make the minting command report fixed usage for invalid arguments and document that Docker execution access is privileged and that direct mint output goes to the invoker's terminal or capture. Extend the tests to observe process arguments, tracing output, and both output streams with a marked fixture token. Evidence is by reading. Stack owns the handoff with the Client and Server command builders. Risk is 42, from 6 for failed enrollment, 7 for a disclosed credential in a persistent trace, and 1 for a local observer with the required access. ### logic-r1 07 · MAJOR · D16

## Answers to the attack questions

1. The command inherits version 7 universally unique identifiers and PostgreSQL time. Redemption serializes on the token row and checks expiry inclusively before same-key replay. A different key gets `token_used`, and a new token starts a separate redemption. The installer has no counters or feed cursors. The installer adds an archive suffix in Coordinated Universal Time (UTC) with a same-second and clock-step collision. The boot and restart checks need a recorded boot or ended invocation. (`plan.md:90`, `plan.md:164`, `plan.md:313` through `plan.md:321`, `.plans/plans/go-s3-server-machines/plan.md:252`, `.plans/plans/go-s3-server-machines/plan.md:263`.)
2. A settings, database, vault, token, or join error denies installation. The Server's locked transaction denies expiry and serializes duplicate redemption. Client retries a transient error with the same token and key while that invocation survives. Installer recovery is missing after a committed join with an unpublished identity and after an interrupted replacement. Linger refusal deliberately leaves a running login-only service and returns 1. A startup timeout returns 1 with the enable step already done. (`plan.md:153` through `plan.md:158`, `plan.md:237` through `plan.md:243`, `.plans/plans/go-s3-client-link/plan.md:103` through `.plans/plans/go-s3-client-link/plan.md:106`.)
3. With state absent, a default run joins before enabling and a failed fresh join leaves no unit. With a valid matching identity, a default run reuses it. With a pending key, it wrongly takes the fresh-token path. With a stale, invalid, or removed identity, it wrongly takes the healthy-update path. With any existing identity, a successful rejoin archives it, while failed or interrupted rejoin has no recovery cell. Removal keeps all local state and server records. A live service exit of 75 restarts, other nonzero exit codes restart, and 0 stays stopped until an explicit restart, boot, or graphical login. Linux lingering on permits boot start, lingering denied leaves login-only service, and the macOS choice is graphical login. (`plan.md:112` through `plan.md:115`, `plan.md:233` through `plan.md:247`, `plan.md:283` through `plan.md:288`.)
4. The plan adds no enumeration or stream position. Omitted `--hosts-server` is false, and the issuer's empty address selects `PublicURL`. Missing `identity.json` means fresh join even if the key is present. For an exported empty `LGTM_CLIENT_STATE_DIR`, match the existing client fallback. An unset or relative `HOME` with an absolute override, and an empty search-path segment, need explicit handling before rendering and execution. `src/client/internal/config/config.go:27` already requires an absolute home when there is no override. (`plan.md:153`, `plan.md:155`, `plan.md:231`, `plan.md:232`, `plan.md:238`, `decisions.md:41`.)
5. The server command and web caller can mint separate token rows. Competing redemptions of the same token serialize, and the pinned identity is read without allowing initialization. Competing installer runs can write the same binary and service files. A foreground client can hold the key and outbox while the installer moves the directory. Another user runs a separate user service. The plan has no installer transaction lock, state-move interlock, or explicit choice of service account across users. (`plan.md:123`, `plan.md:154`, `plan.md:233` through `plan.md:240`, `src/client/internal/state/folder.go:94`, `.plans/plans/go-s3-server-machines/plan.md:263`.)

Its service-order mutation fails when enable precedes join, but pre-join template publication or a pre-join service restart with enable unchanged can still evade the stated ordering predicate. The argument, trace, and runtime recovery gaps also survive the stand-ins. (`plan.md:150`, `plan.md:156`, `plan.md:163`, `plan.md:166`, `plan.md:225`, `plan.md:257`, `plan.md:258`.)
