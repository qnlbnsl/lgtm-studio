## Findings

### threat-r1 01 · MAJOR · R7

The server can detect a lost event history that the client cannot diagnose. For example, a restored client store ends at event 40 and opens a new run at 41, while the server has a staged result waiting for event 45. The server rejects admission before `Welcome`. The client therefore never checks the server mark against its own store. Under the prescribed retry rule it keeps dialing while the operation stays open. The current client treats generic `invalid_argument` as retryable and only checks the outbox mark after `Welcome`. Evidence by reading `.plans/plans/go-s4-contract/plan.md:145–153`, `src/client/internal/link/conn.go:133–142`, `src/client/internal/link/conn.go:206–221`, `src/client/internal/link/retry.go:23–44`, and `src/client/internal/link/session.go:471–479`.

Specify a distinct recovery signal on the authenticated handshake for contradictory history. Pin its code, on-wire indication, and stop behavior in the contract and handoff. Keep generic malformed-message refusals retryable. Require both ends to prove that this case preserves the mark, waiting result and command gate, and emits one fixed recovery message before the client stops.

Category is integrity and recovery. The Link and Folders builders own the change. The contract gap is confirmed by reading. Risk is 120 (severity 6, fallout 5, probability 4) because one stale restore can block the owner's machine until manual intervention.

### threat-r1 02 · MAJOR · R7

The receipt handoff omits the crash-safe point at which one run's boundary becomes durable for the next run. The event store currently advances one shared counter, and the receipt has no run or watermark. If run A commits a folder report and dies with the receipt still started, run B can append its own event and die before that receipt is encountered again. Sampling the high-water number in run C now makes A's result wait on B's event. Losing B's event can strand a result whose original dependency is already satisfied. The existing decoder also treats a malformed receipt as interrupted, which makes the legacy zero path ambiguous during migration. Evidence by reading `.plans/plans/go-s4-contract/plan.md:143–149`, `.foundry/go-rewrite/results/plan-go-s4-contract.md:43`, `src/client/internal/link/outbox.go:35–53`, `src/client/internal/link/receipts.go:34–60`, and `src/client/internal/link/receipts.go:116–137`.

Require the client to persist the previous run's final boundary and bind its started receipts to that boundary before the next run can append. Require version-aware validation that grants watermark zero to a valid revision 1 receipt or a genuinely empty history. Route damaged revision 2 receipts through the local store fault. Test a crash on each side of the run transition and a damaged receipt.

Category is integrity. The Folders builder owns the change. The persistence requirements are incomplete by reading. Risk is 60 (severity 6, fallout 5, probability 2) because the demonstrated failure needs consecutive restarts and unavailable history.

### threat-r1 03 · MAJOR · R9

The folder contract leaves the local execution boundary implicit. An owner can legitimately inspect a checkout another user or process can modify. If the implementation uses a Git inspection path that honors repository-supplied external programs, asking whether that checkout is clean can execute code with the client service user's access. The approved design treats folder inspection as read-only and recognizes that this user can read the machine key and harness sign-in. Evidence by reading `.plans/plans/go-s4-contract/plan.md:155–168`, `docs/specs/2026-11-27-running-an-agent-design.md:145–159`, and `docs/specs/2026-11-27-running-an-agent-design.md:224–250`.

Put the read-only boundary in the `LookAtFolder` rules and the Folders handoff. Limit inspection to local facts and prohibit repository-controlled program execution and network access. Require a fixture with an inert side-effect sentinel and evidence that inspection leaves it untouched.

Category is access. The Folders builder owns the change. The plan omission is confirmed by reading, and implementation exposure depends on the chosen inspection code. Risk is 168 (severity 8, fallout 7, probability 3) because a writable checkout and an implementation that trusts its executable configuration could expose the service account's files.

### threat-r1 04 · MAJOR · R9

The remote sanitization and filtering rules lack an observable credential boundary. A remote can contain a credential in a query value even when it has no username or password field. Removing user information and applying a filter that knows only local client secrets can leave that unrelated credential in the buffered event, the database, and the repository watch. The plan describes screening facts before buffering and testing byte lengths and presence. The approved design also requires the shared filter on client log text and requires it to know the client key and connection token in every form held by the client. Evidence by reading `.plans/plans/go-s4-contract/plan.md:113–114`, `.plans/plans/go-s4-contract/plan.md:155–168`, `.foundry/go-rewrite/results/plan-go-s4-contract.md:43`, and `docs/specs/2026-11-27-running-an-agent-design.md:145–159`.

Define the permitted credential-free remote forms and the omission rule for ambiguous inputs before those values become repository identity keys. Require the shared filter on sprint 4 buffer and log paths. Test synthetic credentials in a remote, a path, and branch text. Assert omission or the fixed refusal as appropriate and absence of the values from both programs' logs, the event buffer, stored results, and browser replies.

Category is confidentiality. The Folders and Projects builders own the change. The contract gap is confirmed by reading, and exposure depends on the implementation. Risk is 168 (severity 6, fallout 7, probability 4) because credential-bearing remote configuration can reach durable copies during an otherwise ordinary add.

Category is access and compatibility. The Projects builder owns the change. The separate allowlist and handoff gap are confirmed by reading.
