### architect-r2 01 — MAJOR — C11

The warning is written for a refused admission and can be cleared by an earlier admission. At mark 10, ready run A has a staged result through event 12. Run B announces first event 11. The server refuses B, sets the warning, and leaves A current. A delivers events 11 and 12, so the plan now permits the event write to clear the warning because the admitted run is ready and the staged watermark is covered. B still retries with its immutable first number of 11 and is now behind the committed mark. A watch that reads the machine after the clear can miss the warning entirely because it reads the current record by feed key. The proposed recovery test restores the prefix and sees a clear without proving which admission earned it.

Give the server a durable condition for clearing the warning. Record the generation current when the contradiction was diagnosed and the required coverage. Clear when a later successful admission is ready and has proved that coverage, or delete the warning on removal. Preserve the incumbent on refusal. Test that the old stream can advance and settle without clearing the warning for the refused run, and that a recovered admission can clear it.

Design. Server Link and Machines. Confirmed by reading. Risk 120, with severity 6 for a recovery loop that needs intervention, fallout 5 for one enrollment, and probability 4 for an incomplete restore with an older stream still able to write. ### architect-r2 02 — MAJOR — R7

The local recovery stop does not extend to the installed client's supervisor. A machine with a valid enrollment and a corrupt or missing event database reaches `stopForStore`. That path logs a generic database failure and returns an error. The client executable converts the error to exit status 1. Both shipped service definitions restart on failure. Changing only the message therefore puts the installed machine into a loop that prints the recovery instruction each time. The in-process loss probe does not observe that restart boundary.

Define a terminal local history fault through the executable. Use an exit status that both shipped service definitions treat as a stop, and keep the fixed recovery message on that terminal path. Name Client Link, the client application and Stack in the handoff. Test an installed client with a valid enrollment and damaged history, and observe one instruction and no restart across the configured restart interval.

Design and recovery. Client Link, client application and Stack. Confirmed by reading. Risk 120, with severity 6 for an enrollment that cannot resume, fallout 5 for a machine that needs recovery, and probability 4 for a damaged local database. ### architect-r2 03 — MAJOR — R4

Serialization of the key does not by itself make the admitted replay safe from retirement. A matching retry takes the Store lock shortly before a terminal operation is eligible for cleanup. `WriteOnce` returns the operation identifier after releasing its transaction, and the request pauses before Projects reads the result. The retirement transaction takes the same key lock and deletes the receipt and the operation. The retry then has an accepted old identifier and no result to return. The receipt hold fixes the original pruning conflict but leaves the handoff between Store and Projects exposed.

Require the new Store boundary to let Projects capture the terminal result under the same key serialization that admits the replay, or hold an explicit read claim through the handoff. Keep the waiting interval outside the write. Put the race assertion between receipt return and the first operation read. The admitted call must return the saved result. A call admitted after retirement may follow the fresh-request rules.

Design. Server Projects and Store. Confirmed by reading. ### architect-r2 04 — MAJOR — D5

Stripping the Secure Shell (SSH) login from a relative remote can turn two different repositories into an identity match. For example, two accounts on the same host can each have a repository named `repo.git` relative to their login directory. The patch strips both account names and compares the identical sanitized host and relative path, so Projects can attach the second checkout even when its first commit differs. A local Git probe using an inert SSH transport confirmed that the two originals pass distinct login targets and the same relative `git-upload-pack` path. The probe made no network calls.

Treat an account-relative SSH path, including a home-relative path, as insufficient identity evidence once the login is removed. Specify the omission or comparison policy before the sanitized value becomes a join key. Retain normal-form equality for independently qualified absolute paths, and add a cross-machine fixture with distinct SSH accounts and distinct first commits.

Design and identity integrity. Client Folders and Server Projects. Confirmed by reading and a local Git probe. ### 5. How the patched rules interact

The following admission and warning table follows the written plan. A pending fence is absent before admission. A staged watermark is absent when no result is waiting. An unchanged retry of the same run retains its original fence even if the mark has already passed it. Evidence `.plans/plans/go-s4-contract/plan.md:143`, `.plans/plans/go-s4-contract/plan.md:159`.

| Input or transition | Admission and command gate | Warning as written |
|---|---|---|
| Bad proof or rejected link revision | No new admission | No diagnostic write. |
| Malformed pair or changed boundary for the same run | Refuse the attempt and preserve the incumbent | No diagnostic write. |
| Valid same-run retry with identical boundary | Reuse its boundary. Open the command gate when the run is ready. | Can clear if the ready condition and watermark coverage hold. |
| Different run at or below the mark or a staged watermark, or below the admitted pending boundary | Refuse it and preserve the incumbent and pending records | Set the diagnostic once while it is false. |
| Different run above the mark and staged watermark, at or above any pending boundary | Admit it. Keep the command gate closed until the mark reaches its boundary minus one. | Clear at readiness only when the current coverage criterion holds. |
| Previously admitted, ready stream commits an event after a conflicting refusal | Its old admission still holds | Can clear while the refused run remains incompatible. Finding 01. |
| Machine removed | End its commands and open operations | Delete the warning with the machine. |

The patched operation order and receipt hold yield the following results. Evidence `.plans/plans/go-s4-contract/plan.md:151`, `.plans/plans/go-s4-contract/plan.md:238`, `.plans/plans/go-s4-contract/plan.md:240`.

|---|---|
