# REVISE

The frozen link text tells the client to discard events through `Welcome.last_event_number` without requiring it to validate that mark before deleting its only local copy.

The cross-vendor rule is unmet because the test writer and the builder were both OpenAI workers, as is this reviewer. This review covers the four contract items at `89506b7c` on `sprint-0`.

## Findings

### post-a 1 — MAJOR — Plan and foundation check C11

The link needs to reject an incompatible Welcome before changing the local outbox. The replay rule tells the client to forget events through the mark, while the later loss rule defines incompatible marks and a replay stop without giving that check precedence over deletion. The test checks the incompatibility predicate and the replay stop as separate statements. [Event replay and loss rules](../../../../src/contracts/proto/lgtm/link/v1/events.proto#L11) · [Loss rule](../../../../src/contracts/proto/lgtm/link/v1/events.proto#L34) · [Rule assertions](../../../../src/contracts/rules_test.go#L397) · [Recovery check](../plan.md#post-build-checks)

If the local next number is 10 and the retained queue contains 7 through 9, a Welcome at 10 is incompatible. A client that follows the discard instruction first can erase all three events before detecting the fault. Require compatibility validation against the original durable local state before forgetting events or advancing the local acknowledgement. In the paired fixture, compare the retained event bytes and the stored acknowledgement before and after refusal at both incompatible boundaries. [Plan recovery case](../plan.md#post-build-checks)

### post-a 2 — MAJOR — Foundation check C11 and sprint check R9

The run gate needs an explicit ready-on-reconnect condition after the committed mark has passed the original boundary. The Protocol Buffers comment says the run becomes ready when the mark reaches `first_event_number - 1` and asks the server to check at admission. The design says a connection loss keeps the run and the check passes at once. The whole contract suite still passed when the scratch comment required exact equality at every admission, with regenerated output and a matching revision 2 hash. [Link run gate](../../../../src/contracts/proto/lgtm/link/v1/link.proto#L133) · [Readiness assertion](../../../../src/contracts/rules_test.go#L368) · [Design for reconnecting the same run](../../../../docs/specs/2026-11-27-running-an-agent-design.md#nothing-is-sent-to-a-client-process-before-its-past-is-known)

A ready run with first event 6 can commit through 8 and reconnect with its original pair. Exact equality with 5 leaves its new stream waiting for a mark that can only move forward. State that the latest admitted pair is ready at admission when the mark is at least the boundary minus one, and reserve the transactional ready callback for a run's first transition. Exercise the reconnect above the boundary, including after server restart, and expect command delivery with no repeat callback. [Plan pending-run case](../plan.md#post-build-checks)

### post-a 3 — MINOR — Plan and sprint check R9

The removal text leaves a `SetState` exception to the replay gate unspecified. The run gate puts replay acknowledgements before gated `SetState`. The removal section separately permits a best-effort `SetState` with `APPROVAL_REMOVED` before ending the stream, without a readiness condition. [Acknowledgement order](../../../../src/contracts/proto/lgtm/link/v1/link.proto#L157) · [Removal rule](../../../../src/contracts/proto/lgtm/link/v1/link.proto#L187)

If a machine is removed during replay with its last acknowledgement still pending, the removal clause permits a command on the draining stream. State that removal of a draining stream ends it with the existing refusal, and give any best-effort removal command an explicit ready-stream condition. Add that frame-order assertion to the paired removal case. [Design command gate](../../../../docs/specs/2026-11-27-running-an-agent-design.md#nothing-is-sent-to-a-client-process-before-its-past-is-known) · [Plan removal case](../plan.md#post-build-checks)

### post-a 4 — MINOR — Plan and foundation check C7

The recovery compatibility test does not pin the browser's JavaScript Object Notation (JSON) field name for a true value. The new-field watch cases exercise binary round trips, and the JSON input is an old record. Changing the field's `json_name` to `historyRecovered` and regenerating passed every contract test. The built declaration uses the expected name. [Recovery compatibility test](../../../../src/contracts/service_discovery_test.go#L181) · [Built declaration](../../../../src/contracts/gen/lgtm/v1/clients_pb.d.ts#L147) · [Browser transport](../../../../src/frontend/src/server/api.ts#L41)

A server generated from the renamed field could send `historyRecovered: true` to a website built with this contract. That website could decode the expected property as false and hide the warning. Assert the wire JSON name and round-trip true in both watch arms through the browser-facing representation. [Owner's Machines display decision](../../../../docs/specs/2026-11-27-running-an-agent-design.md#decisions-of-the-owner)
