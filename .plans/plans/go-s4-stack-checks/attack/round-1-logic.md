REVISE

OpenAI supplies the planner, test writers, builders and this reviewer.

The joint gate must prove that it owns its stack before it can run checks that restart services and revoke sessions.

## Findings

### logic-r1 01 — BLOCKER — C1

The plan validates the proposed Compose model and gates cleanup on ownership. Its start, selection and prepared-stack paths lack a common check of the ownership of resources that already exist. A project name and a resolved model describe what Compose will select. They do not establish who created the existing containers, networks, volumes or bind paths. If a prior run or a prepared manifest selects a foreign project with the expected shape, G1 can recreate its server and change its password. C4 then revokes that stack's sessions. An unrelated-label test only at cleanup cannot catch this path. Before the first mutation, claim a fresh run identity, reserve the names and reject existing objects or paths unless the current fixture recorded their ownership and identity. On later selection, including `--prepared`, verify the recorded Docker daemon, container, network and volume identifiers, actual published binding, and canonical bind and service paths before issuing any application request or lifecycle command. Use the same check on re-entry, retry and cleanup. Test a foreign stack at the expected nondefault port and an unrelated object under the expected project name. Assert that neither receives a request or lifecycle command. Evidence (by reading) is in `.plans/plans/go-s4-stack-checks/plan.md:74–79,136–138,164–183`, `deploy/test/checks.sh:38–47,389–409,450–465`, `deploy/test/web-testlib.sh:92–100`.

### logic-r1 02 — MAJOR — R4

The operator guide needs a precise point after which an image rollback cannot start the old server. A Sprint 4 migration can commit and then startup can fail in a later phase. The launcher can therefore exit before printing `phase server done` while the database already rejects the older image. The pinned Sprint 3 store rejects both a link schema version beyond its manifest and a new Projects entry. State the one-way boundary at the migration commit and give a read-only migration-ledger check for an ambiguous exit. Define when the owner may restart the old pair on the verified old ledger, when to preserve state and repair forward, and when to keep all clients quiescent. A later client start can also write revision 2 receipts, which the old reader does not replay. Explain that rerunning the same candidate installer is the ordinary retry and that the copied client state is for deliberate recovery. Keep database rewind outside the supported upgrade procedure. Add an interruption case on each side of migration commit and one after the installer replaces the binary but before service restart. Evidence (by reading) is in `.plans/plans/go-s4-stack-checks/plan.md:40–44,125–132,200`, `src/server/internal/store/migrate.go:36–60,101–119` (same at `f6cbea30`), `src/server/internal/app/start.go:178–211` (same ordering at `f6cbea30`), `deploy/install-client.sh:325–350`, `src/client/internal/link/receipts.go:34–48,116–134`, `.plans/plans/go-s4-server-link/plan.md:131–135`, `.plans/plans/go-s4-client-folders/plan.md:86–90`, `.foundry/go-rewrite/results/fold-go-s4-contract-r2.md:12`.

### logic-r1 05 — MAJOR — C11

The relay has one replaceable control file but the upgrade needs two simultaneous holds and a clean transition between old and new streams. The proposed selector identifies an event or command without identifying the stream to which its rule applies. After the old stream closes, a hold selected by machine and event number can catch the same event again when the candidate legitimately replays it. Releasing the hold first can forward the old copy from the relay and falsely pass the upgrade. Define an atomic control generation with multiple exact rules, a stream identity, an acknowledgement that each rule is armed, and a distinct terminal discard action. Fence the old stream and confirm both old copies were discarded before giving the candidate a new generation. Require the same event number and digest to arrive fresh from the candidate connection and correlate one committed application with that arrival. Test a second stream for the same machine, repeated control writes, cancellation with both holds armed, and a later numbered frame that would create a gap if allowed to pass the hold. Evidence (by reading) is in `.plans/plans/go-s4-stack-checks/plan.md:81–87,127–132`, `src/client/internal/link/commands.go:252–270`, `src/server/internal/link/stream.go:135–149`, `docs/specs/2026-11-27-running-an-agent-design.md:298–300`.

## Answers to the attack questions

1. The database orders commands under the machine lock. The paired checks govern run boundaries, consecutive events, cumulative acknowledgements and repeated attempts. The upgrade uses a committed event number and the 23-hour offer window. Specify the server-clock reference, exact cutoff, old and new attempt correlation, and the relay generation and restart rules from finding 05. Use Link's bounds tests for exhaustion and require a gap to leave the mark untouched.
2. Local corrupt history denies work and stops. A requested restart restarts. The design gives a replayed request its saved operation after a lost reply and denies an expired command without inspection. Half-finished startup and installer failures need the operator decision points in finding 02. Link owns the staged-result and clock-skew assertions through restart and sweep.
3. For storage and readiness, check four cells. Old ledger and old image can restart once readiness and settings are verified. Old ledger and candidate image retry migration. New ledger and candidate image recover forward. New ledger and old image are refused. For the relay, old stream plus armed controls holds, old stream plus cutover discards, new stream plus clean generation forwards, and a new stream plus stale controls currently has no defined result.
4. A recognized revision 1 receipt replays zero. A present revision 2 zero is valid, and missing revision 2 metadata stops locally. Absent discovery enters the compatibility workspace. No machine means a disabled dialog. The relay plan leaves absent control, empty selector and zero event or attempt ambiguous. Require explicit pass-through when disarmed and reject invalid armed rules instead of wildcard matching them.
5. Compose and fixture cleanup can address the same named object, and installer, supervisor and history observer can reach the same client files. Fence both with recorded ownership and serialize lifecycle actions. Stop and wait for the old process before opening or copying its Bolt database. A suspended process is still a lock owner. Give the relay a single owner of each stream and explicit controls across replacement.
6. Item 1's wrong tag, port and cleanup mutations need a preflight ownership case. Item 2's stripped metadata and mismatched key mutations should fail the listed assertions, while an old hold applied to the new stream could survive. Item 3's erased receipt or changed digest should fail a correlated assertion, while a failure after migration should still pass the happy path. Item 4's swapped statuses should fail the manager observations, while the wrong incompatible-Welcome instruction could survive. Item 5's extra port and wrong tag should fail the model test, while a replaced local Vite certificate survives it.

Limit releases to one manifest-bound lifecycle owner and correlate results by machine, command and attempt. This makes foreign reuse and stale relay release unrepresentable as an ordinary execution of the fixture.
