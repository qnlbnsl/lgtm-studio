## Answers to the attack questions

1. Startup has a fixed phase order and inherits the vault lock, whose coverage needs to include the added work. Readiness retries are local to a container start and their budget disagrees with the Server plan. The echo and count probes compare ordered messages within one connection, with no durable counter or wrap case. The tick probe measures arrival intervals. The plan gives the certificate 3,650 days, but gives expiry, clock skew and restarts with changed certificate bytes no handling. Findings 3 and 6–8 cover the gaps.
2. Failed vault setup stops startup. Failed server readiness stops it before web starts. Database migration, missing passwords during a live deployment, late port conflicts and interrupted certificate publication need the policies in findings 3, 5 and 7–9. Duplicate live link requests and expired enrollment tokens belong to sprint 3 and introduce no state here.
3. With a password and no public address, default loopback is intended to serve, other approved loopback binds can return 421, and a wider bind is refused. With a valid public address and a loopback or wider bind, encrypted traffic is intended to serve. The plan accepts an omitted public port even if the actual published port differs from the scheme default, and gives no rule for when a forwarding layer supplies that mapping. Define direct publication versus forwarded ingress and test the exact URL the launcher prints. Missing password plus an empty project is a refusal, missing password plus an active server leaves old access live, and missing password plus vault-only launch is incorrectly blocked by unconditional preflight. Findings 2, 4 and 5 cover those cells.
4. The empty operator public setting selects plaintext loopback Caddy but needs a separate nonempty server origin. Empty password refuses full launch. An absent port or bind renders the defaults, an explicit port of zero is rejected, and the early vault-only path must work without web settings. The unnamed probe shape selects echo and the absent tick count selects five. The plan adds no production enumeration or feed position. Findings 2, 4 and 10 cover the gaps.
5. Two launchers can contend for the state folder, a direct certificate job can contend with the launcher, and Caddy reads the certificate while the setup job replaces it. Hold one state lock through publication and web reconciliation. A separate process can still take the published port after preflight, so the actual publish result must decide. Findings 7–9 cover these cases.
6. By reading the assertions, item 1's context and user mutations meet the marker and user comparisons. Item 2's mutations meet the host and HTTP version comparisons. Item 3's mutations meet the marker and capability comparisons. Item 4's mutations meet the port, network and mount comparisons. Item 5's mutations meet the refusal and no-server assertions. Item 8a's mutations meet the key hash and mode comparisons, and item 8b's mutations meet the handshake and private-mount comparisons. These are predicted failures, with no executed mutation claims. Item 7's extra Caddy-version mutation must reach the timed upload failure rather than fail on setup. The missed wrong implementations are listed under question 7.
