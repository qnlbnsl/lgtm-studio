| 9 | Issue 1633: where does encryption end for the link? | In public HTTPS mode the web server holds the certificate and ends Transport Layer Security (TLS). It passes each call on to the server as cleartext HTTP/2 (h2c) over the internal network `app`, which only the web server and the server join. The web server asks no machine for a certificate. The server learns the key of the certificate by reading the public certificate file, which the stack mounts read-only into the server. In loopback mode nothing is encrypted, as the design allows. Assumption: the contract plan's reading that the machine presents no certificate holds after its review. | The orchestrator read issue 1633 the same way. The contract plan pins the hash of the certificate's key in the join token, so the server must be able to read that key. A machine proves itself by signing a challenge, so a certificate of the machine adds nothing once TLS ends at the web server. | unanswered | 2026-11-26 |
| 10 | Where does the certificate of the public address come from? | The stack makes it itself. A one-shot job makes one Elliptic Curve Digital Signature Algorithm (ECDSA) P-256 key the first time public mode is turned on, and it keeps that key for good. It signs one certificate with that key for the host name of the public address, valid for 3,650 days. A certificate supplied by the owner, and automatic certificates from a public authority, are left out of wave 1. Assumption: the owner accepts that warning in wave 1, and a certificate of the owner's own is a later feature. | The design decided on 2026-11-25 that no certificate needs a public authority. The join token pins the certificate's key, so a key that changes cuts off every machine (issue 1639). An automatic certificate service renews with a new key by default. A browser shows a warning once for this certificate, and the owner accepts it. | unanswered | 2026-11-26 |
| 11 | How is a public HTTPS address turned on? | Two settings. `LGTM_PUBLIC_URL` names the address, as `https://<host>` or `https://<host>:<port>`, with no path. `LGTM_WEB_BIND` names the host interface the port is published on, and its default is `127.0.0.1`. The launcher refuses a bind that is not a loopback address unless the public address is set and starts with `https://`. In loopback mode the web server also answers only the host names `127.0.0.1`, `localhost` and `[::1]`, and it refuses any other host name with status 421 before it serves a page or passes a call on. Assumption: no owner needs a public bind without HTTPS. | The design says that a public address is a setting the owner turns on and that it must be `https`. A second setting for the bind keeps publishing beyond loopback a deliberate act. It also lets the owner keep loopback and reach the stack through a port forward. The host rule stops a page from loading over plain HTTP from another computer, so no password is typed there. | unanswered | 2026-11-26 |
