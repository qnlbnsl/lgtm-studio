### architect-r1 02 — MAJOR — R6

The proposed result guard treats a committed claim as a transmission. A peer that previously received an attempt can reconnect and report the next attempt before receiving it. If the claimed retry is discarded at the send cutoff, the queued result still matches the current stream and its new attempt in storage. The server records a final outcome for a frame it never sent. Item 4b expressly expects completion to win in a pause before the first write. The frozen contract accepts a result for the attempt last sent. Evidence by reading `.plans/plans/go-s3-server-commands/plan.md:101`, `:153`, `:170` and `:172` and `src/contracts/proto/lgtm/link/v1/commands.proto:61`.

Specify an authorization for accepting results that distinguishes durable assignment from entry into the transport write. Keep the durable attempt increment before sending. Set the stream-local write entry marker at actual dispatch and keep the machine fence for result and send. Define how a write that may have delivered bytes ends the stream and leaves the command available for retry. Exercise pre-entry and cutoff-discarded results as ignored, and complete a delivered attempt in the positive case. Use removal and expiry to test finalization after a claim and before the first write. The Server link builder owns this design finding. The product risk is 36, with severity 6 for a false final disposition, fallout 3 because a new owner request can restore the action, and probability 2 because a peer must report a delivery it did not receive.

### architect-r1 03 — MAJOR — R10

The scheduled sweep cannot observe the in-progress send of the same row in the inverse test. An action must be younger than expiry plus 23 hours to enter the send. The send holds the machine lock for a two-second budget. The sweep selects only actions older than expiry plus 24 hours. A sweep during an ordinary held send therefore skips that row at candidate selection, before it can exercise `TryLock`. Aging the row after release leaves this part of the test unproved. Evidence by reading `.plans/plans/go-s3-server-commands/plan.md:110`, `:170`, `:171` and `:231` and `src/contracts/proto/lgtm/link/v1/commands.proto:3`.

For the send-wins case, seed a separate already-due command for that machine and a due control command for a second machine. Prove the sweep selected both, the lock refusal delayed only the first machine, and a later pass completes it. Use a matching result or removal for the same-row ordering check. This is a required Server integration gate and is unscored.
