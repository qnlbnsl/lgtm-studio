# The server accepts machine streams and saves their reports

## What the owner sees when a machine connects

The server will accept a connection from a machine that has already joined. It will prove both identities, replace any older connection from that machine, and save the reports that drive the Machines page. A machine can reconnect after either program restarts and continue from the last report the server saved.

A lost connection normally makes the page show the machine offline. If the database refuses the cleanup, the page can temporarily retain the last saved presence while the server retries. The server still stops treating that connection as live immediately.

The machines plan owns joining and approval. This plan supplies the stream. A later plan sends approval notices and carries out machine actions from the page. The stack leaves the optional machine address blank when it cannot verify where the connection originated. The review leaves one decision about how wave 1 protects stored machine records from copies of the database volume.

## Key decisions

The frozen revision 1 link determines what the server accepts and what it sends. The machine proves its identity with a signed challenge. A waiting machine can report its facts, which the owner can see before approving it. The stack's private network carries the hop from the web server to the application in wave 1.

An admission commit replaces the old stream and sets the event number for replay. A process fence prevents the old stream from starting a late Welcome.

A failed delete can temporarily leave stale presence while the server retries. Actions require an exact live stream, which is revoked immediately.

Full log → [decisions.md](decisions.md)

## Workstreams

### A machine proves its identity and replaces its old connection

The server proves its identity before it checks whether the machine is registered. It then checks the machine's proof and admits it in a database transaction. Tests pause competing streams at admission, during removal and before the first reply to verify which one can continue.

### A connected machine reports its facts and its load

The server saves each report and its number together. A check replays a report after a lost acknowledgement and counts its committed effect. The page shows joining until the current stream has reported both facts and harnesses while approved.

### The server clears disconnected streams and starts cleanly

The server ends silent streams and closes open streams when it shuts down. Tests hold a failed cleanup while another stream shuts down, then restart the server and check that it keeps the machine records and event numbers.
