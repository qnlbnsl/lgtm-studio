REVISE

The new event watermark lets the server acknowledge reports it never applied, which can permanently delete the only buffered copies.

## Findings

The evidence is by reading the round 2 plan at `fca037e0` and checking the referenced interfaces at the current checkout. The Go link is still a contract draft. The scenarios below describe consequences of the written rules.

### threat-r2 01 — BLOCKER — C11. Keep an event acknowledgement tied to committed effects.

The server raises its committed mark to a value supplied in `Hello.acked_event_number`. The proof signs the machine identifier and the two nonces. It leaves the watermark outside both signatures. On the draft's unprotected hop, the watermark can change while the proof still verifies. If the server has committed through 40 and the machine still holds 41 and 42, accepting 42 as the claimed mark makes the server announce 42 without applying either report. The machine can then discard its copies. A validly authenticated claimant also cannot establish that effects survived a restore by asserting a number. The routine `EventAck` rule still lacks the independent ceiling from round 1. Bind recovery inputs and both forms of acknowledgement to the authenticated peers and the current stream. Advance the applied mark only in the transaction that consumes the next event. Bound each ordinary acknowledgement by the reconciled starting mark and the highest event actually sent on that stream before calling the outbox. Handle a lost applied prefix through explicit recovery as in finding 05. [Plan 181–184, 342–351, 532–535](../plan.md#L532), [proof text](../draft/link.proto#L213), [outbox acknowledgement](../../go-s1-client-local/plan.md#L698).

### threat-r2 02 — BLOCKER — C10. Serialize revocation with stream admission and writes.

The fresh machine read occurs before the stream becomes current, while removal commits before stream cancellation. A new stream can verify and pass the fresh read, pause, then become current after removal commits and cancels the previous stream. An already current handler can also pass its fence before removal and finish a write afterward. The same gap applies when token revocation removes a waiting machine. Give the removal, admission and replacement operations a shared serialization point. Check the registered identity and current stream generation at the transaction that commits any machine effect. Revoke token authority at the removal commit, and fence token checks by the same identity and generation. Close the stream after the commit as cleanup. [Plan 523–531](../plan.md#L523), [revoking a used token](../plan.md#L446), [design removal rule](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L254).

### threat-r2 03 — BLOCKER — C10. Keep a database restore from undoing removal.

The new recovery case permits a restored database to resume admission under the existing signing identity. Restoring a snapshot from before a removal or cancellation brings back the machine's registered key or an unexpired token verifier. A machine removed by the owner can then pass the fresh read and obtain a current stream without a new approval. The restored database alone cannot tell that the later revocation happened. Define a restore gate that stops live link traffic and expires all restored enrollment tokens and registered machine authorizations before reopening admission, unless a trustworthy record outside the rolled-back state can reapply the revocations. Re-enroll and approve affected machines explicitly. Coordinate the restore gate with the session owner because a restored session verifier has the same rollback property. [Plan restore rule](../plan.md#L535), [restore acceptance check](../plan.md#L733), [design storage and removal rules](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L243), [design session verifiers](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L202).

### threat-r2 04 — MAJOR — C9. Authenticate the decision that makes a client stop.

A valid `Challenge` establishes who signed those challenge bytes. It does not authenticate the later status or distinguish a corrupt `Proof` from removal. A client can receive a genuine challenge, encounter an altered or misrouted proof on the unprotected hop, receive `unauthenticated` from its own server, and exit even though it remains registered. The `failed_precondition` row can stop it before any peer verification, and the package-wide revision rule also assigns `invalid_argument` to that input. Specify terminal refusal as an authenticated handshake outcome bound to this transcript and reserved for an authoritative absent identity or incompatible revision. Make bad proof, bare status and transport failures retry with the local state intact. Give unsupported revision one validation precedence. Specify whether lookup waits for `Proof` and how an early authenticated refusal is consumed. Retain the delayed retry for `aborted` and require exact current-stream replacement to be its server-side source. [Plan phase and code rules](../plan.md#L509), [revision value rule and refusal table](../draft/link.proto#L9), [proof text](../draft/link.proto#L213).

### threat-r2 05 — MAJOR — C11. Agree which event stream a watermark describes.

The plan says the client-local `Outbox.Ack` already advances `Next()` to a higher server mark. The current client-local plan explicitly rejects that operation and scopes reconciliation by a durable outbox epoch, which the wire format cannot send. A machine with an empty replacement outbox starts at 1. The server reports 40. The contract expects 41, while the client-local plan returns `ErrServerAhead` and keeps 1. A genuine server restore is different. Raising a mark from 40 to an already acknowledged 42 cannot restore the lost effects from 41 and 42. Agree one authenticated epoch and sequence contract across Client Local, Client Link and Server Link. Use a distinct authorized reset for a replacement outbox or explicit recovery after a server rollback. Republish current facts and harnesses as snapshots and keep the reset distinct from a claim that the old events were applied. Align the local sequence limit, the wire value rules and the restore acceptance check. [Plan restore rules and local assumption](../plan.md#L532), [wire `Hello`](../draft/link.proto#L190), [client epoch and sequence cap](../../go-s1-client-local/plan.md#L630), [client rejection rules](../../go-s1-client-local/plan.md#L698).

### threat-r2 06 — MAJOR — D7. Give the waiting state a complete authorization rule.

The owner options discuss what reports a waiting machine may submit. The draft also gives it the same token field as an approved machine, allows any other post-handshake request, and derives presence from `Welcome`. A newly enrolled process can send `CommandResult` despite the pending-state rule only describing outgoing commands. A later token reader can also treat a token from an authenticated waiting stream as permission to do work. Record the authority matrix before the contract freezes. A waiting stream receives no work-capable token, can send only the selected pending message types, and never finalizes a work command. Require every later token use to check current approval and stream generation, and specify whether approval mints a token on the existing stream or requires a fresh `Welcome`. Require `Welcome.state` as documented and clarify the fallback for an unknown approval in a present state. Distinguish connected transport, waiting for approval and approved presence. Keep the owner choice about display telemetry. [Plan options](../plan.md#L133), [post-handshake rules](../plan.md#L519), [token field](../draft/link.proto#L224), [design waiting rule](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L247).

### threat-r2 07 — MAJOR — R6. Give the command deadline a clock policy the two sides can honor.

The proposed elapsed time begins at `Proof`, but the server sample is taken later. If proof processing takes five seconds, the sample is already advanced by five seconds relative to the client's elapsed-time origin. A command sent with four seconds left can expire at a client with a correct clock and negligible return delay. Conversely, a forward correction of the server wall clock after sampling can make the client estimate trail the server. The client-local receipt store independently uses `Now` for `Begin` and pruning. Define the authoritative deadline clock and an explicit uncertainty rule for acting near expiry. Use one admission decision in Client Link and the receipt store, including replay of a final receipt. State how clock jumps affect admission and retention. Update the test to cover proof delay, clock movement and a command well inside the safe execution window. [Plan 323–332](../plan.md#L323), [draft clock calculation](../draft/commands.proto#L12), [local receipt clock](../../go-s1-client-local/plan.md#L752), [plan expiry test](../plan.md#L736).

### threat-r2 08 — MAJOR — C6. Hand the token's authoritative address to both enrollment entry points.

The new strict equality rule makes a mismatch fatal. With a public endpoint configured, the installer still passes its derived local address to the token maker and the enrollment client. The Machines page has only the token text and its own server label, which intentionally strips the scheme and can describe a different website access path. Either reader can therefore produce a command the client refuses even with a valid token. Settle one issuer policy for the public and local enrollment paths. Use the signed-in server's enrollment address when formatting or assembling the invocation, or use an invocation that takes it only from the token. Supply the full address and pin consistently to both token makers. Name the browser, mock, installer and client readers, and record the rollout owner. [Plan address rules](../plan.md#L452), [handoff](../plan.md#L716), [Machines page](../../../../src/frontend/src/screens/service.tsx#L410), [address label](../../../../src/frontend/src/server/address.ts#L44), [installer](../../go-s3-stack-client/plan.md#L219).

### threat-r2 09 — MAJOR — C5. Give the joining client a bounded retry deadline.

The client must retry a transient error until the token's original expiration, but the expiration is in the website response only. The installer passes only the encoded token and an address. A token pasted shortly before expiry, while the server cannot answer, leaves the client unable to determine when to stop. Give the client a bounded retry deadline by carrying the issuing deadline in the token, or define a separate locally measured retry budget and leave the authoritative expiry check to the server. Specify the clock and which failures exit. The frozen C5 check also reads distinct `token_used` and `token_expired` diagnostics. Agree with its owner on an assertion that checks refused enrollment without requiring reason-specific output from the generic refusal row. [Plan retry rule](../plan.md#L450), [token fields](../draft/link.proto#L107), [installer](../../go-s3-stack-client/plan.md#L225), [C5 refusal fixture](../../../../deploy/test/checks.sh#L335).

### threat-r2 10 — MAJOR — R9. Produce displayable command failure text at the server.

The restriction on `CommandResult.message` tells the reference client to use fixed sentences. The server still receives a string intended for the website. An authenticated machine with a matching command and attempt can put local tool output or a credential in a short message that meets the length and encoding checks. Make the server derive display and log text from an outcome and an allowed reason identifier. Ignore or reject free text at that boundary. Keep the limits and self-reported status for machine facts, and require the server and client to omit raw reports and credentials from diagnostics. [Plan result rules](../plan.md#L331), [result field](../draft/commands.proto#L47), [design secrecy rule](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L369).

### threat-r2 11 — MINOR — R9. Agree how token creation handles a request key.

The patched command makes a fresh token on every call and forbids reply replay. The sign-in plan assigns token creation the same credential-issuing exception as `SignIn`, which refuses a present request key. A future caller supplying a key can therefore get either a new token or a refusal depending on which handoff the builder follows. A lost unkeyed success also leaves the dialog without an identifier to revoke until the token expires. Specify that a present key is refused without a mutation, or agree a different explicit policy with the Store and Sign-in teams. State that unkeyed creation is a fresh issue and define the fate of a prior issue whose reply was lost. Keep the reply out of durable receipts. [Plan token creation rule](../plan.md#L279), [sign-in request policy](../../go-s2-server-signin/plan.md#L290), [dialog cleanup](../../../../src/frontend/src/screens/service.tsx#L367).

## Answers to the attack questions

### Threat lens

1. **Trust boundaries.** The signed-in site issues or revokes tokens through the owner route. The machine supplies a bearer secret and a public key at `Join`, then proves possession on `Open`. Reports and command results cross from the current machine stream, and recovery imports a disk watermark across that same boundary. Validation checks shape; committed identity, approval, stream generation and authenticated protocol outcomes must check authority. The proxy hop and database restore cross boundaries the patch still leaves open. [Plan agreements](../plan.md#L708), [value rules](../draft/link.proto#L9).
2. **Credential inventory.** The server makes and sends the join secret through the issuing screen or command and `Join`, retains its verifier, and excludes its reply from request receipts. The token may appear in shell history, the clipboard or the process list. Enrollment creates the machine's Ed25519 private key in user-only local state and sends its public key and proofs. The server signing key lives in OpenBao. Enrollment stores the public key and certificate pin for reconnects. The web server owns the certificate private key. `Welcome` sends an opaque bearer for later calls, and the draft gives it a stream lifetime. The web password, session bearer and verifier, vault access credential and unseal file remain with the sign-in and stack plans. Cover all secret-bearing paths in redaction checks. [Join draft](../draft/link.proto#L107), [stream bearer](../draft/link.proto#L224), [design vault and sessions](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L197).
3. **Credential endings.** Enrollment is single use with narrowly scoped replay until its original 15-minute expiry, or earlier revocation or removal. The machine key loses registry authority on removal, and the local key stays during retries. The stream token ends on replacement, close or removal. Re-enrollment is the stated recovery from a certificate key change. The browser session ends on sign-out, password revocation, expiry or eviction. Findings 02–04, 06 and 09 address missing enforcement and recovery. [Plan join rules](../plan.md#L446), [removal and connection token](../plan.md#L523), [pin rotation risk](../plan.md#L692), [design sessions](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L197).
4. **Encryption.** The design allows plaintext loopback, requires Hypertext Transfer Protocol Secure (HTTPS) elsewhere, and specifies a certificate from the machine. OpenBao protects its stored secrets, while the machine key relies on private local file permissions. The patch supplies a pin before secret transmission but leaves the inner hop, the signed refusal and the recovery watermark without end-to-end integrity under its working assumption. Point 2 must settle that boundary before freezing a wire shape that depends on it. [Plan transport options](../plan.md#L123), [design transport and storage](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L316), [issue 1633](../../../../docs/issues.md#L7520).
5. **Dependencies and images.** Nothing found in the patch that changes a dependency or image. The plan pins the Go Protocol Buffers and Connect generators and trusts their publishers and the Go toolchain. The workspace pins Buf and the TypeScript generator and runtime. The Go directive sets a minimum, and the patch adds no image. [Go tool pins](../plan.md#L220), [workspace versions](../../../../pnpm-workspace.yaml#L34).
6. **Integrity.** An authenticated waiting machine lacks a fail-closed dispatch and token rule. A removed machine can race admission or reappear after rollback. A peer on the unprotected path can affect the watermark and the client stop decision. The sign-in plan keeps the two exact machine routes separate from the owner guard and checks the origin on website calls. The at-rest verifier and key-file boundaries still need integration evidence. [Findings 01–06](#findings), [sign-in routes and origin guard](../../go-s2-server-signin/plan.md#L252).
7. **Checks that need code.** The post-build checks below cover transport, authority across transactions and restore, client outbox effects, credential lifetimes and the real issuing clients.

#### Event and restore truth table

| Condition | Draft result | Required boundary |
|---|---|---|
| Registered current stream sends the next valid known event | Its effect and mark commit together. | Apply once and acknowledge after commit. |
| Current stream sends a duplicate, a gap, or an unknown report at the next number | A duplicate receives the mark. A gap ends the stream. An unknown or empty report consumes the next number. | Make deliberate consumption of a forward-compatible report explicit. An ordinary acknowledgement cannot exceed the prefix sent on that stream plus its negotiated starting mark. |
| Claimed client watermark exceeds the committed mark | Server raises its mark before `Welcome`. | Treat the mismatch as a recovery condition. A client assertion alone never advances applied state. |
| Server mark exceeds the local counter for the same epoch | Contract skips ahead. Local `Reconcile` refuses. | Keep the outbox and return an explicit recovery error. |
| Server mark belongs to an old epoch and the client has a fresh outbox | Contract compares the two as one count. | Negotiate an authorized reset and use a separate count. |
| Restored registry predates a removal | Fresh read can admit the previously removed key. | Keep admission closed through credential restoration or invalidation. |

#### Handshake and revocation truth table

| Condition | Draft result | Required boundary |
|---|---|---|
| Unverified peer returns `unauthenticated` or `failed_precondition` | Retry the first. Stop on the second. | Retry both unless a terminal outcome itself is authenticated. |
| Verified `Challenge` followed by bad proof or missing identity | Both yield `unauthenticated`, and the client stops. | Retry a bad proof. Stop for an authoritative absent identity only when its outcome is authenticated. |
| Database read fails or current connection breaks | Retry and keep state. | Keep the same key and files. Issue no terminal refusal. |
| Another verified stream replaces the current stream | The old stream receives `aborted` and retries after the normal wait. | Fence old effects immediately. A replacement status leaves credentials intact. |
| Removal commits before a candidate installs or a handler commits | Fresh read and cancellation can occur on opposite sides of that commit. | Refuse the admission or effect and invalidate token authority at the revocation boundary. |
| Current stream is waiting, approved or removed | Waiting gets telemetry and a normal `Welcome`. Approved receives work. Removed is closed. | Waiting gets only permitted message types and no work authority. Approved requires the current identity. Removed produces no effect. |

#### Enrollment and command truth table

| Condition | Draft result | Required boundary |
|---|---|---|
| Fresh unexpired token and verified secret | `Join` creates one waiting record and binds the key. | Commit consumption and registration together. |
| Used unexpired token, same secret and key, valid enrollment | `Join` returns the original response. | Replay that response without mutating approval or creating a second enrollment. |
| Token expired or revoked, bound to another key, or its machine was removed | `Join` refuses. Revocation removes a pending enrollment and leaves an approved machine alone. | Apply the refusal and approval rules atomically. Use consistent safe diagnostics. |
| No command receipt and deadline reached | Client answers expired. | Use one admission clock policy through both link and receipt storage. |
| Running command receives a newer attempt, or a final receipt exists after expiry | Client answers under the latest received attempt. Server accepts only the current attempt on the current stream. | Preserve the final receipt through the reconciliation window and keep completion separate from accepting a restart. |
| No accepted final result at expiry plus 24 hours | Server records expired. | Specify which outcome wins if a final result and this transition reach the same transaction boundary. |
