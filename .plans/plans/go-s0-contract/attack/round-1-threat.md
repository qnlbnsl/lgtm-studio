REVISE

Removing a machine depends on sending it a command, so a failed send can leave its key valid after the owner removes it.

## Findings

### threat-r1 1 — BLOCKER — C10. Revoke access before notifying the machine.

By reading, `APPROVAL_REMOVED` says the server forgets the key **after** sending the state, and the replacement rule does not say that the new stream must finish authentication first. If a machine disconnects during removal, a server that follows that order can leave it eligible to reconnect. If removal races with a valid `Proof`, a stream authenticated against the old registry state can still become current. Make revocation authoritative at the registry commit. Reject new admissions and writes from the removed identity after that point. Invalidate any connection token and cancel the live stream even when a notice cannot be delivered. Make a replacement current only after proof and a fresh registry check. Fence writes, command results and presence callbacks by the current stream so the replaced stream cannot clear its successor’s online state. Define how a client stops retrying after an authenticated removal refusal when it missed the notice. [Command draft, commands.proto:74](../draft/commands.proto#L74), [stream draft, link.proto:30](../draft/link.proto#L30), [approved design, 2026-11-25-go-rewrite-foundation-design.md:248](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L248).

### threat-r1 2 — BLOCKER — D17. Authenticate and protect the traffic after the challenges.

By reading, the signatures cover only the machine identifier and the two nonces. The plan explicitly terminates encryption at the web server and accepts cleartext on loopback. An untrusted local listener or an intermediary with access to a cleartext hop can relay a valid handshake while the subsequent command and acknowledgement bytes have no independent integrity check. The enrollment request also carries its secret over these hops. Before the freeze, have the owner and the Stack, Server and Client teams agree on the transport boundary, including the approved design’s machine certificate and loopback rule. Specify peer authentication and integrity through the proxy, preferably with authenticated encryption on both hops. If cleartext loopback remains a requirement, agree on an authenticated local transport or a protocol that protects enrollment and binds the post-handshake stream to the authenticated peers. A private network or a completed challenge alone leaves the gap. [Plan, plan.md:41](../plan.md#L41), [proof and token draft, link.proto:122](../draft/link.proto#L122), [approved design, 2026-11-25-go-rewrite-foundation-design.md:316](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L316), [issue 1633, issues.md:7520](../../../../docs/issues.md#L7520).

### threat-r1 3 — BLOCKER — C11. Acknowledge only an ordered, committed prefix.

By reading, the stream allows messages in any order, and the server advances on any event number above its last one. The outbox writes the acknowledgement to disk before deleting covered files. If event 8 is handled before a retained event 7, acknowledging 8 deletes 7 at the client even if the server never applied it. Sprint 1 already refuses an append when full and takes no number for the refused append. Require one ordered sender and one ordered applier per current stream. Accept the next number or a duplicate, refuse a gap or an unknown report without advancing the cursor in revision 1, and commit the event effect and cursor together before sending an acknowledgement. Define ordinary acknowledgements as bounded by what that stream sent. Keep authenticated `Welcome` reconciliation separate and state how the client handles a server cursor behind its own durable acknowledgement, such as after a database restore. [Event draft, events.proto:14](../draft/events.proto#L14), [stream draft, link.proto:30](../draft/link.proto#L30), [client storage plan, plan.md:583](../../go-s1-client-local/plan.md#L583), [approved design, 2026-11-25-go-rewrite-foundation-design.md:288](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L288).

### threat-r1 4 — MAJOR — R9. Keep the join secret out of durable retry receipts.

By reading, the existing token creation response contains the whole copyable credential. The generic write-retry design stores the reply with the change, while the enrollment design permits only a verifier. If token creation uses generic reply storage, a database reader can recover an unexpired enrollment credential. Give this call an explicit retry policy that keeps cleartext out of the database, including request receipts and diagnostics. For example, exclude it from durable reply replay and make reissuance a new token operation with explicit invalidation of the abandoned token. Document the rule in both the existing method’s comments and the Server plan. [Website contract, clients.proto:100](../../../../src/contracts/proto/lgtm/v1/clients.proto#L100), [plan, plan.md:348](../plan.md#L348), [retry and enrollment design, 2026-11-25-go-rewrite-foundation-design.md:176](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L176), [verifier requirement, 2026-11-25-go-rewrite-foundation-design.md:254](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L254).

### threat-r1 5 — MAJOR — R9. Give the join secret an input channel outside command arguments.

By reading, the website renders the token inside a shell command, and the approved Go invocation also takes it as an argument. Pasting either command can retain a still-live credential in shell history or expose it through process arguments on systems where other users can read them. Agree with the owner on a protected prompt or standard-input flow, then coordinate its website, installer and client instructions. Keep the value out of diagnostics and use it only on the issuing screen and during enrollment. [Join screen, service.tsx:403](../../../../src/frontend/src/screens/service.tsx#L403), [approved invocation, 2026-11-25-go-rewrite-foundation-design.md:247](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L247), [token draft, link.proto:40](../draft/link.proto#L40).

### threat-r1 6 — MAJOR — C5. Define the exact exception for retrying a consumed token.

By reading, the same paragraph promises replay for the same machine key and refusal for a used token. If the server commits enrollment but the reply is lost, the two teams can reasonably build incompatible retry behavior. Specify that one transaction verifies the secret and binds the token to one machine identifier and key. Within the original expiry, let the same verified secret and key recover the original reply while that enrollment is valid. Refuse a different key, a revoked token and a removed enrollment. Specify how closing the website’s dialog affects an issued token, a waiting machine and an already approved machine. Have the client reuse its first persisted key on retry. Update the approval check to distinguish recovery of the original result from a second enrollment. [Join draft, link.proto:23](../draft/link.proto#L23), [website dialog cleanup, service.tsx:370](../../../../src/frontend/src/screens/service.tsx#L370), [approved acceptance check, 2026-11-25-go-rewrite-foundation-design.md:382](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L382).

### threat-r1 7 — MAJOR — D7. Define what approval gates.

By reading, the design permits a waiting machine to connect only, while the draft allows all events and sends the same token-bearing `Welcome` to every authenticated stream. A machine with a valid join secret but no owner approval can submit harness reports and receive a credential which later code may mistake for approval. Have the owner settle which bounded reports may populate the approval screen. Define a default-deny matrix for the pending and approved states on both sides, including `CommandResult` and the connection token. Keep the token empty or unusable for work while pending and require a fresh approval check for token-bearing operations. A website session stays required for owner actions. A machine credential authorizes the machine routes only. [Enrollment design, 2026-11-25-go-rewrite-foundation-design.md:247](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L247), [plan, plan.md:405](../plan.md#L405), [stream draft, link.proto:133](../draft/link.proto#L133), [website service contract, clients.proto:11](../../../../src/contracts/proto/lgtm/v1/clients.proto#L11).

### threat-r1 8 — MAJOR — R6. Define what a restart result proves across a crash.

By reading, `Restart` must send its result before exiting, while Sprint 1 recovers an unfinished command as interrupted and never runs it again. If the client records and sends success but then fails before the exit, the server can finalize a restart that never happened. If the client exits with a durable started receipt, the next process has no specified report outcome for it. Define an acceptance result and a recoverable restart intent. If the owner-facing operation promises completion, have a later authenticated connection correlate the prior intent with a new client process and report completion then. Freeze the wire mapping for an interrupted receipt, either as a new outcome or as a specified failure with a safe reason. Specify how a finished scan relates to a durably queued harness report. [Command draft, commands.proto:23](../draft/commands.proto#L23), [client receipt plan, plan.md:627](../../go-s1-client-local/plan.md#L627), [approved command design, 2026-11-25-go-rewrite-foundation-design.md:281](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L281).

### threat-r1 9 — MAJOR — R6. Use one rule for the command deadline and result acceptance.

By reading, expiry uses the client’s wall clock while the plan leaves the offset policy to the Client team. A slow client can execute after the Server team has expired the command. A fast one can write a terminal expired receipt for a command the server still considers valid. The dedicated outcome also defaults to zero if it is omitted. Specify a single expiry for every attempt of an identifier, the trusted clock and allowed uncertainty, and the interaction with receipt retention and retry. Define the expired result for an unseen command and preserve the stored outcome when a completed command is repeated after expiry. Accept results only for the current stream, the assigned machine, the exact outstanding attempt and a recognized terminal outcome. Define what happens to absent timestamps, attempt 0, state revision 0, and unspecified approval and outcome values. [Command draft, commands.proto:14](../draft/commands.proto#L14), [outcome and state enums, commands.proto:46](../draft/commands.proto#L46), [clock risk, plan.md:557](../plan.md#L557), [approved command design, 2026-11-25-go-rewrite-foundation-design.md:281](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L281).

### threat-r1 10 — MAJOR — D17. Identify the owner of the certificate pin and the recovery path when a key changes.

By reading, the token pins a hash of the certificate’s public key, but the web front end holds the certificate. A certificate issued before the server learns its key can yield a token the corresponding client can never use. A changed front-end key can leave every enrolled client unable to reconnect. Specify an authoritative configuration handoff for the public endpoint and its public-key fingerprint. Have the client verify the pin before transmitting the join secret and on every reconnect, with no untrusted redirect or address override. Agree on authenticated rotation or an explicit owner-assisted re-enrollment for either pinned key. Confirm that pinning the public key, which allows a same-key renewal, satisfies the approved certificate policy. [Certificate decision, decisions.md:21](../decisions.md#L21), [token draft, link.proto:45](../draft/link.proto#L45), [plan, plan.md:557](../plan.md#L557), [issue 1633, issues.md:7520](../../../../docs/issues.md#L7520).

### threat-r1 11 — MAJOR — R9. Treat machine-provided display fields as untrusted data.

By reading, `CommandResult.message` is arbitrary text for the website, and the link accepts strings from machine settings and local tools. If a failing scan includes a subprocess error or a credential in its version output, copying the text into a stored reply, an error or the Machines page breaks the design’s secrecy rule. Use enumerated or server-owned failure text, with bounded and validated report fields. Validate each challenge’s length and signature, reject malformed identifiers before processing them, and define load percentages and their allowed range. Treat machine facts as self-reported display data. Keep keys, tokens, raw command output and sensitive paths out of routine logs and diagnostics. Never derive identity, approval or trusted host role from machine strings or raw forwarding headers. ### threat-r1 12 — MAJOR — D16. Gate the website’s real enrollment and restart flows.

By reading, the Machines page offers reconnect only when a machine is offline and displays the old enrollment command. The mock also implements offline reconnect. Against the proposed Go server, an owner following the displayed command cannot enroll with the stated Go entry point and cannot request restart from an online row. Coordinate the website, mock and Go behavior in the Sprint 3 rollout, including which revision an old website can use. Keep revision 1 for the additive schema change. If the Go service ships the incompatible behavior without coordinated compatibility, apply the repository’s revision rule instead of treating the change as a comment edit. Test enrollment and online restart against the Go server. ## Answers to the attack questions

1. **Trust boundaries.** Owner calls cross the browser session and allowed-origin boundary. Join takes the secret and a self-reported key and hostname. Open takes an identifier and a signed challenge. Its writers also need approval, current-stream and assignment checks. Reports cross from files, client settings and harness output into the database and website. Check local file ownership and permissions, validate messages and consult committed database state for identity, revocation and cursors. See findings 1, 3, 7 and 11.
2. **Credentials and storage.** The server generates the join secret and retains its verifier. The secret travels in the issuance reply, the copy flow and `Join`. The machine creates its Ed25519 key, keeps the private key in a file readable by its user alone and sends the public key and signatures. The server signing key lives in OpenBao. Its public key and the public certificate fingerprint are kept in the client’s enrollment record. The proxy owns the Transport Layer Security (TLS) private key. The server mints the connection bearer for `Welcome` and later calls would carry it in a header. The owner password comes from a setting and travels in the sign-in body. The server generates a browser cookie token and stores a verifier, salt and password binding. The installer makes the vault unseal key file and first setup hands the server a scoped vault credential. The plan forbids logging the join token but leaves argument exposure, durable reply storage, other credential redaction and deletion rules to resolve. See findings 4, 5, 7, 10 and 11.
3. **Credential lifetime.** A join token lasts 15 minutes, is consumable once subject to the retry ambiguity, and can be revoked. Machine removal forgets the registered key but requires immediate stream invalidation and a client cleanup rule. The connection token ends with the stream under the draft. Scope it to the current approved identity and define its invalidation on replacement and removal. The website session ends at sign-out, password change, expiry or eviction. Rotation of the proxy and server signing keys, and rotation of the vault’s scoped credential and unseal key, have no handoff here. See findings 1, 6, 7 and 10.
4. **Encryption.** The design allows loopback cleartext, requires HTTPS elsewhere, permits private certificate trust and specifies a machine certificate. OpenBao encrypts its stored secrets and the client key is protected by file permissions. The draft does not close the proxy-to-server confidentiality and integrity gap in issue 1633, the post-proof protection gap on loopback or sensitive material in other stores. See findings 2, 4 and 10.
5. **Dependencies and images.** The workspace pins Buf 1.75.0 and its ECMAScript generator and runtime at 2.17.0. The plan pins the Go Protocol Buffers generator and runtime at 1.36.12 and Connect at 1.21.1, and adds the Go module checksum file. These toolchains and their publishers are trusted to generate executable source. The Go directive sets the minimum toolchain to 1.26.0, and a compatible newer local toolchain can still run generation. This plan adds no image. [Workspace pins, pnpm-workspace.yaml:34](../../../../pnpm-workspace.yaml#L34), [Go pins, plan.md:151](../plan.md#L151).
6. **Integrity.** An authenticated but unapproved machine can send reports under the draft. A revoked or replaced stream needs a write fence. An untrusted local listener could affect an unprotected link, and a foreign origin must have no owner authority even when a browser attaches a cross-site cookie. The client storage plan already states private permissions and rejects symbolic links and wrong owners. The wiring and credential input need runtime checks. See findings 1, 2, 5, 7 and 11.
7. **Checks that need code.** Run the transport, credential, approval, replacement, presence, replay, crash and website checks below against built components.

- **a. Server.** The draft carries the join identifier, secret, machine and server public keys, assigned machine identifier, both nonces and signatures, command identifier, attempt, expiry and result, numbered event, cumulative acknowledgement, heartbeat and heartbeat answer. The server can derive presence timestamps locally and must set offline on close or heartbeat timeout. The authority and ordering rules above need to be fixed before both teams can implement them independently. Define a terminal removal signal, the interrupted outcome mapping and any restart-completion correlation before freeze. Specify a trusted source or explicit absence for website `Client.address` and `hosts_server`, since neither machine field appears in `Join` or `Facts` and the server never dials the machine. [Link draft, link.proto:61](../draft/link.proto#L61), [event draft, events.proto:34](../draft/events.proto#L34), [website fields, clients.proto:33](../../../../src/contracts/proto/lgtm/v1/clients.proto#L33).

- **b. Client.** Join, Open, facts, harness versions, load, scan, state and restart have wire cases. The client can use `Welcome.last_event_number` and `EventAck.through` with its durable outbox. Retry timing and disk records are local and need no messages of their own. The shared pieces still missing are the removal disposition, a wire mapping for the interrupted receipt, and restart correlation if a completed restart must be proven. Pin persistence, retry timing after a missing challenge or welcome, and command expiry policy also need agreement. [Client link brief, plan.md:43](../../go-s3-client-link/plan.md#L43), [client storage plan, plan.md:572](../../go-s1-client-local/plan.md#L572), [link draft, link.proto:133](../draft/link.proto#L133).

- **c. Field numbers, zero values and revision.** No number is reused in the draft. Website field 4 is new, and link payload cases begin at 10 in their respective command and event messages. The draft declares no reserved ranges, and its first enum values are explicit zero sentinels. Reject them as operative approval or command results. Zero as the initial event cursor has a defined meaning. The generated website position is optional. Revision 1 is correct for the wire addition, while the live website behavior requires the rollout decision in finding 12. See the verification below. [Website diff, existing-files.diff:23](../draft/existing-files.diff#L23), [commands, commands.proto:46](../draft/commands.proto#L46), [stream expansion rule, plan.md:410](../plan.md#L410), [website revision check, api.ts:40](../../../../src/frontend/src/server/api.ts#L40).

## Post-build checks

- **T1 — Stack, Server and Client.** Use the pinned endpoint through the real proxy and keep the stream idle between heartbeats. Expect a new connection to verify the configured pin and the correct server key, both directions to stay open, and an invalid certificate pin to fail before sending a join secret. Expect a bad server challenge on reconnect to fail before the client signs. Record peer validation and proxy test results for each hop.
- **T2 — Server and Client.** Drop the first successful join reply, then retry with the saved key. Expect one machine record and the original result. Revoke or expire the token and expect further joins to fail. Inspect database receipts, browser caching, process arguments, state permissions and logs with synthetic marker secrets. Expect no cleartext in those surfaces.
- **T3 — Server and Stack.** Connect before approval and try owner operations from a machine and from an unlisted website origin. Expect only the explicitly allowed pending messages and no owner state change. Check active website streams after sign-out and password rotation. Record the observed authorization codes and durable state.
- **T4 — Server and Client.** Replace a live stream, then let the old stream close or send a late reply. Remove the machine while its network is unavailable. Expect the replacement stream to retain presence until its own timeout or close, the removed key to fail on reconnect, and old streams and tokens to have no authority. Capture the feed and registry state.
- **T5 — Server and Client.** Commit an event and cut the stream before its acknowledgement. Repeat with adjacent pending events, a gap and an unknown report. Expect one committed effect per number, a recoverable duplicate acknowledgement, and no deletion of a pending event beyond the committed prefix. Compare the database cursor, receipts and client outbox through a process restart.
- **T6 — Server and Client.** Interrupt a scan and a restart at receipt, report and result boundaries, then resend with a new attempt. Expect durable and truthful outcomes, no duplicate side effects, and no successful late result for another machine or attempt. Repeat with clock skew and absent command fields. Record the client receipt, process lifecycle and server command state.
- **T7 — Website, Server and Client.** Use the actual Machines page to create, use and revoke a token, then approve and restart an online machine. Expect the displayed instructions to enroll the Go client and the page to show the resulting presence changes with no reload. Run C5 to C11 with the test entry points described by issue 1634 and preserve the browser and service observations. [Issue 1634, issues.md:7531](../../../../docs/issues.md#L7531).
