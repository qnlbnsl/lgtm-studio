REVISE

A refused enrollment exits successfully under the new stop rule, so the installer can proceed without a joined machine and the required used-token check fails.

## Findings

The evidence is by reading the patches from `fca037e0` to `eb9f2710` and checking the cited sources in the current checkout at `f1dcbb7d`. The reviewed plan, decisions, scouting notes and drafts match `eb9f2710`. The scenarios are consequences of the written rules. The Go link is a draft.

### threat-r3 01 — BLOCKER — C5. Give failed enrollment a failing exit status.

The new definition of “stop” applies to `Join` and `Open` and promises exit status 0. The installer starts the service when `join` returns 0, even if the token was refused and the client wrote no enrollment. The user-flow check treats that same exit status as a successful enrollment and fails before checking the refusal diagnostic. Limit status 0 for a terminal refusal to `lgtm-client run`. Specify that `lgtm-client join` returns 0 only after successful durable enrollment and returns 1 on refusal or exhausted retries. Keep its safe diagnostic and preserve status 75 for a requested restart. [Contract plan](../plan.md#L536), [draft](../draft/link.proto#L35), [client command](../../go-s3-client-link/plan.md#L276), [installer](../../go-s3-stack-client/plan.md#L225), [user-flow exit check](../../../../deploy/test/checks.sh#L217), [refusal assertion](../../../../deploy/test/checks.sh#L335).

### threat-r3 02 — BLOCKER — C11. Define which outbox a committed event number describes.

A server mark proves that the server consumed a number for the machine identity. The patch uses that mark as proof that a locally sent report at that number was consumed. These are equivalent while the identity has one durable outbox. If two processes with the same enrolled identity resume from separate copies of an outbox at 40, each can assign 41 to a different report. The first stream attempts its send and records 41 as sent, but the connection closes before its report commits. The replacement commits its own 41. When the first process reconnects, the genuine server mark of 41 makes `Reconcile` delete its only copy of the different report. A stream fence cannot distinguish the two payloads, and the patch explicitly handles repeated replacement by a process using the same key. State the one-outbox invariant and its recovery boundary. If independently writable copies are supported, bind resume acknowledgements to the identity of the queued reports and preserve an ambiguous prefix for explicit recovery. If they are unsupported, require a fresh enrollment identity when a state copy is made runnable, spell out the consequences of an undetected copy, and keep the claim about loss within one durable outbox. Do not restore the client-supplied applied mark. [Contract event and replacement rules](../plan.md#L354), [replacement diagnostic](../plan.md#L539), [local durable send and reconcile](../../go-s1-client-local/plan.md#L666), [planned two-process test](../../go-s3-server-machines/plan.md#L1126).

### threat-r3 03 — BLOCKER — R9. Remove machine-result text at both ends before freezing their tests.

The draft reserves `CommandResult.message`, but Client Link still writes the generated field and Server Link still validates and stores it. Building either planned access against the new generated type fails. Treating an unknown field as the old message would instead put untrusted text back into the result path. Name Client Link as the writer of only the identifier, attempt and outcome. Name Server Link as the reader of those fields and the discard point for unknown data. Have Server Machines derive display text from the stored outcome. Update both consuming plans, their fixtures and tests before they freeze, and keep raw result data out of logs. [Public name and reservation](../plan.md#L192), [stored result rule](../plan.md#L348), [wire reservation](../draft/commands.proto#L63), [client result writer](../../go-s3-client-link/plan.md#L252), [server result reader](../../go-s3-server-machines/plan.md#L893).

### threat-r3 04 — MAJOR — C6. Give the default loopback stack a browser token issuer.

The patched contract gives the Machines page only a configured public address and reserves the loopback token for the server command. The default stack publishes only loopback, and checks 5 and 6 obtain their token through `CreateClientToken` on that stack. A clean default deployment therefore has no allowed browser token to issue. In public mode the installer needs the opposite exception, but the receiving Server Machines issuer still rejects an explicit address different from its public address. The same receiving plan omits `address` from the browser reply. Specify a browser token for the effective loopback origin in default mode, with `hosts_server` false, and a pinned public token in public mode. Keep the host mark exclusive to the privileged local command and allow that command to select the installer’s actual loopback origin in either mode. Require the Go issuer to populate response field 4 and the website adapter to carry it to the dialog. Give the sample reply a defined display fallback or have the sample server write the field. Check the default stack on a non-default port as well as the public-mode split. [Contract issuer and reply](../plan.md#L292), [two issuer rules](../plan.md#L471), [default design](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L345), [test origin and issuer](../../../../deploy/test/checks.sh#L32), [test token creation](../../../../deploy/test/checks.sh#L206), [Server Machines issuer](../../go-s3-server-machines/plan.md#L535), [Go response writer](../../go-s3-server-machines/plan.md#L1022), [website adapter](../../../../src/frontend/src/server/sync.ts#L117), [sample response writer](../../../../src/mock-server/src/engine.ts#L182).

### threat-r3 05 — MAJOR — C5. Verify the bearer before either use or replay and agree how reasons travel.

The old draft required a verified secret for replay. The new draft omits verification from both branches, and item 5 mentions the verifier only in the first-use branch after the refusal list. A builder following the draft can accept a known token identifier without the bearer secret. A builder who checks the listed states first can disclose expiry, revocation or use to an unauthenticated caller. The Server Machines plan already compares the secret first, but it puts reasons in a header, uses `machine_removed`, and reserves the error message for a sentence. The Client Link reads that header while the patched contract puts `token_removed` and its peers in the message. On this mismatch a used token can be correctly refused while check 5 misses `token_used`. Require canonical lengths and a constant-time check of the bearer for every known token inside the redemption transaction. Give a missing identifier and a wrong secret the same generic refusal. Only after verification apply expiry, revocation, binding and removal checks in the documented order. Freeze one machine-readable channel and one enum of safe reasons across the issuer, enrollment client and log assertion. Use fixed client text and map unrecognized metadata to a generic refusal. [Plan refusal order](../plan.md#L462), [draft replay](../draft/link.proto#L59), [prior verified replay decision](../decisions.md#L53), [server verifier](../../go-s3-server-machines/plan.md#L565), [server refusal channel](../../go-s3-server-machines/plan.md#L1114), [client refusal reader](../../go-s3-client-link/plan.md#L109), [required diagnostics](../../../../deploy/test/checks.sh#L425).

### threat-r3 06 — MAJOR — C10. Carry the removal outcome into the server handshake, hub and tests.

The new client retries `unauthenticated` and stops only on `failed_precondition` after a validated challenge. The receiving server plan still uses `unauthenticated` on a missing identity, on removal during handshake and when its feed ends an open stream. An offline machine that the owner removes will retry after every valid challenge if both teams implement their written plans. The server plan also checks revision before sending a challenge and can therefore trigger endless retries for a genuine revision mismatch. Update the Server Machines code table, ordering, hub, tests and incident diagnostic names before freeze. Specify one outcome for a missing or revoked identity, including a removal concurrent with admission. Keep the same commit boundary for revocation, account for removal between durable registration and publishing `Welcome`, and require token authorization to validate identity and generation at use. The database row locks and connection deletion in Server Machines are evidence of a proposed fence. The report has no evidence that those rules have run. [Contract handshake and retry](../plan.md#L526), [contract removal and ownership](../plan.md#L547), [server admission](../../go-s3-server-machines/plan.md#L700), [server handshake and tests](../../go-s3-server-machines/plan.md#L736), [hub close code](../../go-s3-server-machines/plan.md#L768), [removal transaction](../../go-s3-server-machines/plan.md#L1023).

### threat-r3 07 — MAJOR — R6. Keep a completed receipt through the full server recovery window.

The patch uses a deliberately fast clock for both expiry admission and pruning. If the proof takes eight seconds and a receipt’s latest timestamp is its command expiry, the client can prune the completed receipt seven seconds before the server’s 24-hour result deadline. A reconnect in that interval can turn an already completed command into `EXPIRED`, even though the command was still eligible to recover its recorded result. The client-local high-water mark prevents re-execution in this example, but it cannot reconstruct the result. Use an upper bound for admission and a conservative lower bound for retention, as Client Link already proposes, or offset pruning by the full documented error bound. State how a stale sample, client suspend or elapsed-clock drift invalidates the bound. Define whether “starts” means durable admission or first effect, and recheck at the latter if that is the promised boundary. Keep the original expiry immutable and keep pruning disabled before a valid `Welcome`. [Contract timing and retention](../plan.md#L333), [local receipt and pruning rules](../../go-s1-client-local/plan.md#L735), [proposed separate clock](../../go-s3-client-link/plan.md#L248).

### threat-r3 08 — MAJOR — C11. Make the next-event dispositions and replay arithmetic identical at both ends.

The contract says that an invalid report at the next number is consumed and logged. Server Machines still freezes a test that rejects it without moving the mark. An older client with an already persisted invalid report at 41 will then replay 41 at every reconnect and prevent a valid 42 from reaching the server. The patch also says to number every unsent event after the reported mark. With mark 40, sent events 41 and 42 and an unsent 43, that wording can assign 41 twice. The local store correctly keeps the pending numbers in this case and only renumbers unsent payloads when the server mark exceeds the durable sent mark. State those cases explicitly. Define duplicate as a number at or below the committed mark and acknowledge that committed mark, as the `EventAck` field comment already says. Specify which malformed envelopes are fatal and which well-framed invalid report bodies advance only the mark atomically. Update the Server Machines rules and its frozen tests, including the event-gap code, and retain per-stream acknowledgement bounds. Use a fixed diagnostic without the report body. [Patched event rules](../plan.md#L354), [draft duplicate and acknowledgement rules](../draft/events.proto#L14), [local reconcile](../../go-s1-client-local/plan.md#L668), [server gap test](../../go-s3-server-machines/plan.md#L809), [server invalid report policy and test](../../go-s3-server-machines/plan.md#L919).

### threat-r3 09 — MAJOR — D17. Make the transport choice a real boundary for destructive client decisions.

The owner point now names a forged terminal status, but the same unprotected hop also carries the two values that authorize durable deletion from the client’s outbox. Even the current-stream acknowledgement ceiling proves only that a number could have been sent. It cannot prove that the server committed it. Under option A, a successful signed challenge followed by a corrupted in-range acknowledgement can leave an unapplied report without its client copy. A corrupted server time can also influence durable command decisions. The proof covers the identifier and the two nonces. The patch both requires the transport choice before item 6 merges and permits that merge with the choice still open. The rollout also promises a freeze at sprint merge. Name the protected boundary for `Join`, `Welcome`, acknowledgements, commands and terminal statuses, including the stated trust assumption for loopback. If the chosen transport authenticates these messages, make that an explicit dependency of their destructive effects. If the owner chooses to trust the internal hop, record that scope and the full integrity and confidentiality consequences. Put one consistent hold on freeze and on dispatch of the dependent Stack Web and Server Sign-in work until the applicable choice is settled. [Choice and deadline](../plan.md#L111), [rollout freeze](../plan.md#L105), [proof bytes](../draft/link.proto#L228), [receipt and event inputs](../draft/link.proto#L239), [local acknowledgement rule](../../go-s1-client-local/plan.md#L667), [issue 1633](../../../../docs/issues.md#L7520).

### threat-r3 10 — MAJOR — D7. Agree on a waiting stream’s authority before its in-place approval.

The contract allows an existing waiting stream’s bearer to open calls once the machine is approved. The Server Machines plan issues no bearer while waiting, and approval on that same stream only queues `SetState`. A side-call reader following the contract can treat a previously issued waiting bearer as authority immediately after approval. A client following the server plan has no bearer until a new proved stream. State which lifecycle is intended and give it one writer and reader. The least change to the receiving plans is to issue no bearer while waiting, retain in-place approval for the wave 1 reports, and require a new approved `Welcome` before any later sibling call. Require the client to reject work commands while its own standing is waiting and the server to gate each message by current approval and generation. Specify the disposition of a forbidden numbered report after the owner chooses the report allowance. [Contract waiting and token rule](../plan.md#L542), [draft current token](../draft/link.proto#L239), [server token issuer](../../go-s3-server-machines/plan.md#L700), [in-place approval](../../go-s3-server-machines/plan.md#L1047), [client waiting behavior](../../go-s3-client-link/plan.md#L201).

### threat-r3 11 — MINOR — D16. Keep replacement backoff within the reconnect bound.

The second `aborted` within a minute now makes a client wait 60 seconds. If the replacement ends during that wait, the earlier process still remains disconnected beyond the approved 15-second retry bound. Client Link explicitly plans a 15-second cap and freezes a test for it. Keep 15 seconds as the maximum and retain the duplicate-key diagnostic, or record a separate approved exception in the design and both plans. [Contract backoff](../plan.md#L539), [design retry bound](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L310), [client retry test](../../go-s3-client-link/plan.md#L204).

## Answers to the attack questions

### Threat lens

1. **Trust boundaries.** The browser issues a token through the owner session and origin check. The CLI issuer uses local server authority. `Join` crosses from a previously unknown machine with a bearer and public key, while `Open` proves key possession with fresh challenges. Reports and results cross the current stream and the client reconciles durable disk state from the server’s mark. Findings 02, 05, 06, 08, 09 and 10 identify the remaining checks at those boundaries. [Owner origin guard](../../go-s2-server-signin/plan.md#L279), [machine route separation](../plan.md#L750).
2. **Credential inventory.** The issuer generates the 32-byte join secret and holds only a verifier in the database. It sends the secret to the issuing page or local command output and the machine presents it in the `Join` body. Request receipts exclude it. The clipboard and command argument remain possible exposures under owner point 4. The machine generates and retains its private signing key in user-only state. Enrollment sends only its public key and proofs and stores the machine identifier, address, server public key and public certificate pin for future connections. The server signing key stays in OpenBao, and the web certificate private key belongs to Stack Web. The server generates the connection bearer for `Welcome`, the client keeps it in session memory, and the Server Machines plan stores only a verifier. The owner password, session cookie and verifier, vault access credential and unseal file remain in their existing plans. No new log or durable plaintext copy is authorized. [Credential and transport rules](../draft/link.proto#L123), [client enrollment file](../../go-s3-client-link/plan.md#L110), [server token storage](../../go-s3-server-machines/plan.md#L700), [web session and vault design](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L197).
3. **Credential endings.** A join token expires 15 minutes after issue or is revoked earlier. A same-key replay must also prove the secret and stops on machine removal. Revoking a used token removes a waiting machine and leaves an approved machine enrolled. Registry removal ends machine authorization and invalidates its stream bearer. Stream close or replacement also ends that bearer. Client stop preserves its key file. Changing the certificate key requires re-enrollment under the plan. Owner session sign-out, password change, expiry and eviction remain with Sign-in. Findings 05, 06 and 10 cover the missing protocol agreements. [Enrollment lifecycle](../plan.md#L462), [stream lifecycle](../plan.md#L547), [rotation risk](../plan.md#L716).
4. **Encryption.** The design allows plain Hypertext Transfer Protocol version 2 on loopback, requires Hypertext Transfer Protocol Secure elsewhere, and specifies a machine certificate. The public pin protects the client-to-web hop and is checked before the join secret is sent. Option A leaves the inner hop readable and mutable, and option C as worded promises message integrity only. OpenBao encrypts its stored secrets. The machine key relies on user-only file permissions. The owner still owns the transport choice and finding 09 covers its effect on the new destructive client rules. [Approved link transport](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L316), [vault protection](../../../../docs/specs/2026-11-25-go-rewrite-foundation-design.md#L215), [options](../plan.md#L128).
5. **Dependencies and images.** Nothing found in the patches that adds a dependency or image. The two Go generators have pinned versions. The frozen workspace lock uses the pinned Buf and TypeScript generator versions for the new checkout check. The Go directive is a minimum version, and the install still trusts the toolchain and dependency publishers. [Generator versions](../plan.md#L228), [checkout commands](../plan.md#L254), [workspace pins](../../../../pnpm-workspace.yaml#L34).
6. **Integrity.** A browser outside the allowlist cannot reach owner dispatch under the Sign-in plan. A waiting machine can affect its self-reported row under the current draft and can send a command result that must be ignored. A stale stream may not change server state and a removal must end authority at commit. A separate process using duplicated state, or corruption of an unprotected hop, breaks the new assumptions about deletion and stop. [Sign-in origin guard](../../go-s2-server-signin/plan.md#L279), [waiting, replacement and removal rules](../plan.md#L542), findings 02, 06, 08, 09 and 10.
7. **Checks that need code.** The post-build checks below cover enrollment status, authorization ordering, durable event and command state, revocation, transport integrity and the displayed pairing command.

### Interacting rules

| Input or state | Result of applying the written rules | Required agreement |
|---|---|---|
| Default web stack and signed-in browser | Browser needs a public origin that the default stack does not have. | Issue for the effective loopback origin without the host mark. |
| Public stack and local installer | Contract allows the local token, while the downstream issuer rejects a different origin. | Permit this override only through the privileged issuer. |
| Present request key, with any value | Refuse before insertion or receipt. | Check presence, including empty or repeated fields. |
| Missing token identifier or wrong secret | Old and receiving rules require generic refusal. New draft omits the secret check and lists state-specific reasons. | Authenticate before disclosing token state or mutating it. |
| Verified secret and first valid use, or same-key retry | Claim and create one waiting entry on first use. Return the original reply on authorized replay. | Keep those actions atomic and verify the secret on both. |
| Verified secret and expired, revoked, bound to a different key, or removed | Refuse according to precedence. Draft and readers differ on metadata and exit status. | Freeze the same reason format and return a failing `join` exit. |

| Server mark above the durable sent mark, with a new empty outbox | The new outbox starts after the server prefix. | Retain and renumber unsent payloads. Treat ambiguity between independently writable copies separately. |
