## Findings

### architect-r1 01 — BLOCKER — R3 — The Link registration signatures disagree

**Evidence.** Projects specifies `RegisterPart(PartHooks)` without a return value, `OnFolderSeen` receiving `*linkv1.FolderSeen`, and `OnCommandSettled` receiving three strings. Link specifies `RegisterPart(PartHooks) error`, report and settlement maps, and callbacks that receive `*linkv1.Event` and `link.Settlement`. The `EnqueueCommand` and `RemoveMachine` signatures agree. `.foundry/go-rewrite/results/plan-go-s4-server-projects.md:41`, `.plans/plans/go-s4-server-projects/plan.md:112`, `.plans/plans/go-s4-server-link/plan.md:78`, `.plans/plans/go-s4-server-link/plan.md:117`.

**Failure.** Item 8 cannot compile a registration built against the Projects handoff and the Link definitions. Changing Link to match Projects would invalidate the duplicate-route and multiple-part acceptance criteria for Link item 1.

**Fix.** Adopt Link's registration as the shared signature. In startup, register `ReportFolderSeen` with an adapter that passes `event.GetFolderSeen()` and the authenticated machine identifier. Register `CommandLookAtFolder` with an adapter that passes the settlement machine identifier, stored command identifier and mapped outcome. Bind `MachineRemoved` directly and propagate registration errors before worker or listener start. Name `link.Seams.BeforeEventCommit func(context.Context, string, uint64) error` as the rollback hook, including its application and server fixture adapters. Compile the three Server parts and their fixtures against that handoff before their dependent tests freeze. `.plans/plans/go-s4-server-link/plan.md:126`, `.plans/plans/go-s4-server-link/plan.md:128`, `.plans/plans/go-s4-server-link/plan.md:241`, `.plans/plans/go-s4-server-link/plan.md:274`.

**Assessment.** Design. Confirmed by reading both plans. Build gate. The Projects and Link planners own the shared interface.

### architect-r1 03 — MAJOR — R4 — A machine with 256 repositories cannot be removed

**Evidence.** The plan records one feed reference per affected repository in the machine removal write. A machine has no planned bound on its distinct saved repositories. Registry deletion already records one machine reference. Store rejects the 257th reference and aborts the write, and an existing test pins that behavior. `.plans/plans/go-s4-server-projects/plan.md:157`, `.plans/plans/go-s4-server-projects/plan.md:166`, `src/server/internal/machines/records.go:59`, `src/server/internal/machines/store.go:178`, `src/server/internal/store/feed.go:13`, `src/server/internal/store/feed.go:70`, `src/server/internal/store/feed.go:110`, `src/server/internal/store/feed_test.go:426`.

**Failure.** Save 256 distinct repositories on an approved machine and then remove it. The machine reference and repository references exceed the Store limit even with an empty Link queue. The removal rolls back each time, leaving the machine, its folders and any open operations in place.

**Fix.** Specify a Store-owned bulk feed path for the removal transaction. It must publish every affected repository reference under the same final feed lock and preserve the existing limit for ordinary calls to `Tx.Record`. Keep the machine deletion, folder cleanup and operation failure atomic. Gate the handoff with 256 distinct affected repositories, including a shared one, and assert one successful removal with the complete set of durable changes.

**Assessment.** Design. Confirmed by reading the write paths. Risk score 60, within the current phase. Severity 6 because removal fails persistently. Fallout 5 because recovery requires help or a code change. Probability 2 because the checkout count is unusual. Store and Projects own the fix.

### architect-r1 04 — MAJOR — R5 — The watch lag test cannot fill the follower as written

**Evidence.** Item 7 asks the test writer to commit more than 2,048 references in one Store write. Store accepts 256 and rolls back on overflow. **Fix.** Hold a saved-frame send after the snapshot, commit at least `store.MaxWatchLag` additional references in transactions of at most `store.MaxWriteChanges` references each, and observe the follower reach the cutoff before releasing the fixture. Require the fixed `aborted` sentence and a complete replacement snapshot on reopening.

**Assessment.** Design. Confirmed by reading the Store and follower. Required test gate. The Projects watch test writer owns the fixture.

### architect-r1 07 — MINOR — R9 — The origin parser needs the contract's explicit home-relative example

**Evidence.** Projects asks its parser to reject account-relative Secure Shell (SSH) origins, but omits the special case the contract and Client plan expressly identify. The attachment and report tests list shorthand, normal forms and credential-bearing origins without pinning the SSH URL form with a home marker after the first slash. `.plans/plans/go-s4-server-projects/plan.md:113`, `.plans/plans/go-s4-server-projects/plan.md:123`, `.plans/plans/go-s4-server-projects/plan.md:158`, `.plans/plans/go-s4-server-projects/plan.md:161`, `.plans/plans/go-s4-contract/plan.md:234`, `.plans/plans/go-s4-client-folders/plan.md:143`.

**Failure.** Basic URL parsing treats a path shaped like `/~/repo` as absolute. If Projects implements only that check, a report containing such a present SSH origin can be stored and compared as an absolute origin, incorrectly allowing an attachment by origin identity.

**Fix.** State that an SSH URL path whose first component is a home marker is account-relative. Consume a report carrying that present value without applying it. Freeze a case for that form and a separate case that accepts the client's legitimate absent remote with `remote_omitted=true`. Keep the existing known-absence fallback test.

**Assessment.** Design. The missing case is confirmed by reading. Runtime behavior is unresolved. Risk score 36, record. Severity 6 because a repository can get the wrong attachment. Fallout 3 because the owner can remove the affected machine. Probability 2 because the planned client already withholds the value. The Projects report and identity builders own the parser case.
